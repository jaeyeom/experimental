#+TITLE: DevCheck
#+DATE: 2026-11-15

* Overview

~devcheck~ runs the right formatter, linter, and tests for whatever
repository you are in, so you (or a coding agent) can use one command
across Go, Python, and JavaScript/TypeScript projects. It uses ~bazel~
or ~make~ targets when the repo defines them and falls back to tools
like ~gofumpt~, ~ruff~, or ~eslint~ otherwise. The default report
(~--format=prompt~) is written for AI coding agents; use
~--format=summary~ for a short human-readable result.

* Installation

#+BEGIN_SRC bash
go install github.com/jaeyeom/experimental/devtools/devcheck/cmd/devcheck@latest
#+END_SRC

From this repository:

#+BEGIN_SRC bash
go install ./devtools/devcheck/cmd/devcheck
# or
bazel run //devtools/devcheck/cmd/devcheck -- [OPTIONS] [PATH]
#+END_SRC

~bazel run~ uses the directory you invoked from.

* Usage

#+BEGIN_SRC bash
devcheck [OPTIONS] [PATH]
#+END_SRC

~PATH~ is optional and defaults to the current directory.

| Flag              | Meaning |
|-------------------+---------|
| ~--dry-run~, ~-n~ | Print the selected commands without running them |
| ~--verbose~, ~-v~ | Include raw tool output when there are no parsed issues |
| ~--format~        | Report format: ~prompt~ (default), ~summary~, or ~json~ |
| ~--filter~        | Restrict to ~format~, ~lint~, and/or ~test~ (repeatable or comma-separated) |
| ~--changed-only~  | Limit file-aware tools to git changes (requires git) |
| ~--force-fallback~ | Skip Bazel/Make and use language-specific tools |

#+BEGIN_SRC bash
devcheck --format=summary        # short result for a person
devcheck                         # default prompt report, for an agent
devcheck --dry-run               # preview commands
devcheck --filter=format         # formatters only
devcheck --filter=lint,test      # lint and test
devcheck --format=json           # machine-readable JSON
devcheck --changed-only          # git-changed / untracked files
devcheck --force-fallback -n     # preview language tools
devcheck --dry-run ./path        # detect a specific directory
#+END_SRC

~--format=summary~ for a dry-run on this repository:

#+BEGIN_EXAMPLE
DevCheck: 3 passed, 0 failed
  dry-run make format
  dry-run make lint
  dry-run make test
#+END_EXAMPLE

* Detection

DevCheck scans the tree once (ignoring ~node_modules~, ~.git~, ~vendor~,
~.venv~, ~venv~, and cache/build directories such as ~.ruff_cache~,
~.pytest_cache~, ~.mypy_cache~, and ~bazel-*~), then chooses tools in
this order:

1. *Languages* (reported in canonical order ~go~, ~python~, ~typescript~,
   ~javascript~) from files and config: Go (~go.mod~, ~*.go~), Python
   (~pyproject.toml~, ~uv.lock~, ~requirements.txt~, ~setup.py~, ~setup.cfg~,
   ~Pipfile~, ~*.py~), TypeScript (~tsconfig.json~, ~*.ts~, ~*.tsx~,
   ~*.mts~, ~*.cts~), JavaScript (~*.js~, ~*.jsx~, ~*.mjs~, ~*.cjs~, or a
   ~package.json~ that is not a TypeScript-only tree).
2. *Build system* at the chosen directory depth: Bazel (~MODULE.bazel~,
   ~BUILD.bazel~, ~WORKSPACE~) or Make (~Makefile~, ~makefile~,
   ~GNUmakefile~). If both are present, Bazel wins only when format *and*
   lint targets exist (~//tools:format~ or ~//:format~, and ~//tools:lint~
   or ~//:lint~); otherwise Make is used. That is why this repository
   reports Make: it has a Makefile with those targets and no ~//tools:lint~
   or ~//:lint~. ~bazelisk~ is used when ~bazel~ is absent.
3. *Probe* before listing a command: the binary must be on ~PATH~, Make
   targets must appear in the Makefile, Bazel labels must exist in a
   ~BUILD~ file, and JS/TS package-manager scripts (~bun~, ~pnpm~, ~yarn~,
   or ~npm~ from lockfiles) are listed only when ~package.json~ defines
   that script (and run in that ~package.json~'s directory).

For each requested type (format, lint, test) DevCheck runs *one* available
command, preferring the build-system tool. ~--force-fallback~ skips
~bazel~/~bazelisk~ and ~make~ and takes the first language tool instead
(Go, then Python, then JavaScript/TypeScript).

Language fallbacks when the binary exists:

| Language | Format                                                       | Lint                                                                                                    | Test                                                             |
|----------+--------------------------------------------------------------+---------------------------------------------------------------------------------------------------------+------------------------------------------------------------------|
| Go       | ~gofumpt~, then ~gofmt~                                      | ~golangci-lint~ (v2 JSON), then [[file:../linters/README.org][unnecessary-interface-assertion-linter]], then ~go vet~ | ~go test~                                                        |
| Python   | ~ruff format~, then ~black~, then ~uv run --no-sync ruff~    | ~ruff check~, then ~flake8~, then ~uv run --no-sync ruff~                                               | ~pytest~, ~python3 -m unittest~, ~python -m unittest~, ~uv run~ |
| JS/TS    | ~<pm> run format~, ~biome format~ (with config), ~prettier~ | ~<pm> run lint~, ~biome lint~ (with config), ~eslint~                                                   | ~<pm> test~, ~bun test~ (with ~bun.lock~), ~jest~, ~mocha~       |

Structured issue parsing supports ~golangci-lint~ (v2 JSON),
~unnecessary-interface-assertion-linter~, ~ruff check~, ~eslint~, and
~biome lint~. Other tools report their exit code and raw output on
failure.

~--changed-only~ finds git changes (working tree and untracked files,
excluding deleted paths, relative to the target directory even inside a
subpath of a repository). Tools receive matching files or Go package
directories (~gofumpt~, ~ruff~, ~prettier~, ~eslint~, ~biome~ receive
matching files; ~golangci-lint~, ~unnecessary-interface-assertion-linter~,
~go vet~, ~go test~ receive deduplicated package directories or ~./...~ on
~go.mod~ changes; ~pytest~ receives test files when only test files
changed and runs the suite when non-test Python files changed). Bazel and
Make still run their full targets. A non-build-system tool is skipped
when no changed files match its language.

* Fit with factory, docsync, and genfiles

~devcheck~ is a standalone code-check runner with no dependency on
~factory~, ~docsync~, ~genfiles~, ~herdr~, or ~agentbus~:

- *Scope*: ~devcheck~ runs repository formatters, linters, and tests.
- *Non-overlaps*:
  - [[https://github.com/chorong-sh/chorong/blob/main/docsync/README.md][docsync]] checks whether documentation is likely stale relative to changed files (~docsync.yml~). ~devcheck~ does not inspect doc mappings.
  - [[https://github.com/chorong-sh/chorong/blob/main/genfiles/README.md][genfiles]] validates ~generated_files.yaml~ and ~.gitattributes~ (~linguist-generated~) so linters and review tools handle generated files cleanly. ~devcheck~ does not inspect generated-file manifests.
  - [[https://github.com/chorong-sh/chorong/blob/main/factory/README.md][factory]] (~factory verify~) checks git worktree cleanliness, stash count, base-branch freshness, and PR template compliance before settling an issue. It does not invoke formatters, linters, or tests directly, so ~devcheck~ complements it as a standalone check command.
- *Current limitations*:
  - Runs at most one tool per type (~format~, ~lint~, ~test~); in a polyglot repo without a unified ~Makefile~ or Bazel targets, fallback tools cover only the highest-priority detected language unless scoped to a subdirectory or filtered.

* Exit codes

| Code | Meaning |
|------+---------|
|    0 | Help, dry-run, or every executed tool succeeded |
|    1 | Detection/execution error, or at least one tool failed |
|    2 | Invalid flags or extra arguments |

Dry-run always exits 0 after a successful detect/plan, even if the commands
would fail when run.

* Standard CLI protocol

~devcheck~ implements ~version [--json]~, ~update [--check] [--ref <ref>] [--json]~, ~doctor [--json] [--offline]~, and ~skill [install|uninstall|status ...]~.
