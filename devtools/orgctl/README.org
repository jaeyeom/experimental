#+TITLE: orgctl
#+DATE: 2026-11-15

* What it is

~orgctl~ checks a team of long-running coding agents against a file you keep.
Each agent runs in a [[https://herdr.dev/][herdr]] tab under an [[file:../agentbus/README.org][agentbus]] name.
The file says which tab and name, and which scheduled jobs that agent owns.
~orgctl~ prints the differences and reminders only a person can do,
such as adding a secret. It never opens a tab, starts an agent, or
edits a schedule.

You want it when several agents stay up for days and you need one
place that says where each one should be.

* Prerequisites and install

You need the ~pkl~ CLI on ~PATH~ (~pkl eval -f json~ renders the spec)
and herdr on ~PATH~. agentbus is how a role gets its name. ~orgctl~
only reads both.

#+BEGIN_SRC bash
go install github.com/jaeyeom/experimental/devtools/orgctl/cmd/orgctl@latest
#+END_SRC

* Concepts

- *machine* — one computer. The key is a short name such as ~local~. ~host~, ~herdrHandle~, and ~timezone~ describe it.
- *role* — one agent. The key is ~area/name~, for example ~desk/clerk~, and that key is its agentbus name.
- *class* — a group of roles sharing rules under ~classes~. A role's class is its name prefix before ~/~ (for example ~review/desk~ → ~review~), or an explicit ~class~ field. A role whose prefix has no class gets org rules only.
- *pool* — similar workers that are not each a role. A pool has no schedules. Patterns choose which names and tabs belong to it.
- *workspace, tab, and pane* — a herdr workspace holds tabs, and a tab holds panes. The spec names the workspace and the tab label. The pane is the agent inside that tab.
- *agentbus name* — the name other agents use to reach this one. For a role, it is the role key.
- *handle* — the agentbus record that points at a herdr pane. Import copies that pane's workspace, tab, and directory.
- *liveness* — ~alive~ or ~unreachable~ means the name is still in use. ~gone~ or ~dead~ is a stale registration.
- *when* — the agentbus ~--when~ text, such as ~weekday mornings~. Plan reports a line when the live text differs.
- *brief* — the note the agent reads when it starts. ~text~ or ~file~ you set is managed. Empty ~text~ leaves an existing file unmanaged.
- *decides* — ordinary work words the role may decide, such as ~priority~. An approval verb is rejected.
- *needs* — names of permissions, secrets, and services a person still has to provide. Secret values are never read.
- *durable cron* — a scheduled job that should still exist on the next run. Import attaches it to the role whose session created it.
- *scope* — an optional list of workspaces. Tab drift then ignores other workspaces. Names and scheduled jobs stay global.

* Quick start

~import~ reads live state and prints a Pkl stub. It does not take a
spec file. The schema is [[file:pkl/Org.pkl][Org.pkl]]. A fictional
team is [[file:examples/acme.pkl][examples/acme.pkl]]. This walkthrough
uses a smaller desk. The names are made up.

#+BEGIN_SRC bash
orgctl import --out desk.pkl
#+END_SRC

~--out~ writes the stub with mode ~0600~. Without ~--force~, an
existing file is left unchanged and the command exits 1 with
~refusing to overwrite~. A shortened stub for one live agent:

#+BEGIN_EXAMPLE
amends "/path/to/devtools/orgctl/pkl/Org.pkl"

// TODO: org name
org = "TODO"

machines {
  ["local"] {
    // TODO: host
    host = "local"
    herdrHandle = "local"
    // TODO: timezone
    timezone = "UTC"
  }
}

rules {}

roles {
  ["desk/clerk"] {
    machine = "local"
    workspace = "front"
    tab = "clerk"
    cwd = "/work/desk/clerk"
    agent = "clerk"
    // TODO: reportsTo
    // TODO: decides
    // TODO: brief
    // TODO: needs
  }
}
#+END_EXAMPLE

Fill those TODOs before checking the spec. ~decides~ takes ordinary
work words. An approval verb is rejected. A secret is a name, never
a value. How the stub is built is in the
[[file:docs/reference.org][reference]].

#+BEGIN_EXAMPLE
org = "Acme Desk"

roles {
  ["desk/clerk"] {
    machine = "local"
    workspace = "front"
    tab = "clerk"
    cwd = "/work/desk/clerk"
    agent = "clerk"
    reportsTo = "desk/lead"
    decides { "priority" }
    brief {
      text = "Keep the front desk moving."
    }
    needs {
      secrets { "MAIL_TOKEN" }
    }
  }
}
#+END_EXAMPLE

Render the Pkl to JSON, then check it. ~check~ does not read live
state. Exit 0 means the spec passed, including the decides list.

#+BEGIN_SRC bash
pkl eval -f json desk.pkl > desk.json
orgctl check desk.json
#+END_SRC

~plan~ reads live state and prints diff lines, then ~USER STEP~
lines. For the spec above, a run can look like this.

#+BEGIN_SRC bash
orgctl plan desk.json
#+END_SRC

#+BEGIN_EXAMPLE
+ desk/clerk tab front/clerk
~ desk/clerk when
USER STEP: desk/clerk secret MAIL_TOKEN
#+END_EXAMPLE

A line that starts with ~+~, a tilde, ~!~, or ~?~ is a diff marker
and can change the exit code. ~i~ is informational and does not
count. ~USER STEP~ is a reminder for a person. It is not a change.
In scripts, treat exit 2 from ~plan~ or ~drift~ as changes found.
~check~ uses 2 for a bad invocation. Every code is in the reference.

~drift~ looks the other way: something running that the spec does
not declare. The tool prints the finding and a suggestion. It does
not delete the job or close the tab.

#+BEGIN_SRC bash
orgctl drift desk.json
#+END_SRC

#+BEGIN_EXAMPLE
+ tab front/night
add to spec, or USER: close tab night in front if it is no longer needed
#+END_EXAMPLE

A tab that runs no agent and has no agentbus name on its panes shows as
~~ shell tab WORKSPACE/LABEL~ with no suggestion. It does not change the
exit code. Pass ~--agents-only~ to leave such tabs out.

* Layered AGENTS.md rendering

~orgctl render agents-md~ turns the JSON spec into three layers of instructions:

1. Org rules for every agent: ~DIR/AGENTS.md~.
2. Class rules for every role in a class: ~DIR/roles/<class>/AGENTS.md~.
3. Each role's own ~brief~ (managed per role, not written by ~render~).

Beside each ~AGENTS.md~, ~render agents-md~ writes a ~CLAUDE.md~ whose whole
content is ~@AGENTS.md~. Each ~AGENTS.md~ starts with an HTML comment header
naming the spec as the source of truth and warning not to edit by hand.

#+BEGIN_SRC bash
orgctl render agents-md --root /path/to/root desk.json
orgctl render agents-md --root /path/to/root --check desk.json
#+END_SRC

*Several machines:* ~render agents-md~ reads only the rendered spec JSON, with
no ~pkl~ and no spec tree required. Run ~pkl eval -f json~ where the spec
lives, copy the JSON to each machine, and run ~orgctl render agents-md --root
DIR SPEC.json~ locally—no sync daemon needed. Use ~--check~ (exits 2 on drift
or missing files) to verify a machine's copy is current.

For [[file:examples/acme.pkl][examples/acme.pkl]] (which defines org rules
~plain-words~ and ~no-secrets~ and the ~review~ class), ~render agents-md~
produces ~DIR/AGENTS.md~ and ~DIR/roles/review/AGENTS.md~. Rules keep
the order the spec lists them in, so ~plain-words~ comes before
~no-secrets~:

#+BEGIN_EXAMPLE
<!-- Generated by orgctl from the organization spec. Do not edit by hand; the spec is the source of truth. -->

# Acme Desk — Organization Rules

## plain-words

Write so a new teammate can follow the note.

_Source: desk handbook_

## no-secrets

Never write down a secret value.

_Source: desk handbook_
#+END_EXAMPLE

#+BEGIN_EXAMPLE
<!-- Generated by orgctl from the organization spec. Do not edit by hand; the spec is the source of truth. -->

# Role Class: review

Desk reviewers who read proposed changes before sign-off.

## cite-line

Point to the exact line or section that is unclear.

_Source: reviewers guide_
#+END_EXAMPLE

When ~--agents-md-root DIR~ (or ~agentsMdRoot~ in the spec) is set, ~plan~ and
~drift~ report ~+ agents-md <path>~ when a file is missing and
~~ agents-md <path> edited in place~ when edited by hand.

~tree~ draws the chart from ~reportsTo~: you at the top, then the
roles with no ~reportsTo~, their reports, and the pools each one
starts. ~--live~ adds each role's state from the same snapshot as
~plan~.

#+BEGIN_SRC bash
orgctl tree --live desk.json
#+END_SRC

#+BEGIN_EXAMPLE
user
└── desk/lead (alive, opus)
    ├── desk/clerk (hibernated)
    └── [pool] typists (max 3)
#+END_EXAMPLE

~diff~ compares two rendered specs, for example the JSON of a proposed
branch against main, and prints one line per change, grouped by role.
Rules and schedules are matched by id and list items by value, so
something that only moved is not reported. A long text such as a
schedule prompt shows a word diff, at most three hunks unless ~--full~.

#+BEGIN_SRC bash
orgctl diff main.json proposed.json
#+END_SRC

#+BEGIN_EXAMPLE
+ role desk/night (new)
~ desk/clerk: reportsTo desk/lead -> (none)
~ desk/clerk: + decides "refund under $50"
~ desk/clerk: schedule morning cron "0 8 * * *" -> "0 9 * * *"
~ desk/clerk: schedule morning prompt changed (+2 -0 words)
    Check the {+refund+} queue and file
#+END_EXAMPLE

* Commands

#+BEGIN_EXAMPLE
orgctl check  [--approval-word WORD]... SPEC.json
orgctl plan   [--machine NAME] [--role NAME] [--expiring 2d] [--agents-md-root DIR] SPEC.json
orgctl drift  [--agents-only] [--agents-md-root DIR] SPEC.json
orgctl import [--out FILE] [--force] [--schema PATH]
orgctl render agents-md --root DIR [--check] SPEC.json
orgctl tree   [--root ROLE] [--root-label TEXT] [--depth N] [--live] [--json] [--ascii] SPEC.json
orgctl diff   [--full] [--json] OLD.json NEW.json
#+END_EXAMPLE

~check~, ~plan~, ~drift~, ~import~, ~tree~, and ~diff~ only read. ~tree~ reads
live state only with ~--live~. ~render agents-md~ writes
only ~AGENTS.md~ and ~CLAUDE.md~ files under ~--root~ (unless ~--check~ is set).

| Flag                 | Commands          | Meaning                                  |
|----------------------+-------------------+------------------------------------------|
| --approval-word WORD | check             | extra approval verb to reject; repeat it |
| --machine NAME       | plan              | only this machine; AND with --role       |
| --role NAME          | plan              | only this role; AND with --machine       |
| --expiring 2d        | plan              | cron window; Nd or a Go duration         |
| --agents-md-root DIR | plan, drift       | root where AGENTS.md files are rendered  |
| --agents-only        | drift             | skip tabs that run no agent              |
| --out FILE           | import            | write the stub here instead of stdout    |
| --force              | import            | overwrite an existing --out file         |
| --schema PATH        | import            | Org.pkl the stub amends                  |
| --root DIR           | render agents-md  | output root directory (required)         |
| --check              | render agents-md  | exit 2 if any file is missing or differs |
| --root ROLE          | tree              | only that role's subtree                 |
| --root-label TEXT    | tree              | label of the top line (default user)     |
| --depth N            | tree              | stop below depth N; the top is 0         |
| --live               | tree              | add alive, hibernated, dead, or missing  |
| --json               | tree              | nested label/kind/max/live/children      |
| --ascii              | tree              | draw with pipes and backquotes           |
| --full               | diff              | every word-diff hunk of a long text      |
| --json               | diff              | the changes as a list for other tools    |

~--machine~ and ~--role~ are both applied. Empty means no filter.
~--expiring~ defaults to ~2d~, which is 48 hours. ~Nd~ is a whole
number of days. Anything else is a Go duration, such as ~36h~. A cron
counts as expiring when its expiry is within that window, including
the exact end. ~--approval-word~ adds to the built-in approval verbs.
The spec can do the same with its own list. Dropping a built-in verb
is a warning on stderr, not a failure by itself.

* Safety and non-goals

From [[https://github.com/jaeyeom/experimental/issues/771][the tracking issue]], and enforced in the tool:

- It never writes Claude Code settings, hooks, permissions, or sandbox allowlists. A role may declare ~needs.permissions~, and the tool prints them as ~USER STEP~ lines.
- Secrets are referenced by name only. Their values are never read.
- No field grants approval authority. Validation rejects approval verbs in a role's ~decides~ list.
- It never closes tabs, kills agents, or deletes crons, and has no apply for tabs or briefs.
- ~render agents-md~ writes only under ~--root~ (never outside it) and never deletes files it did not render.
- There is no stored state file. Live state is read on every run.

* Standard CLI protocol

~orgctl~ implements ~version [--json]~, ~update [--check] [--ref <ref>] [--json]~, ~doctor [--json] [--offline]~, and ~skill [install|uninstall|status ...]~.
