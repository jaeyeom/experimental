* Exit codes

An unknown command, or no command, exits 2. ~check~ exits 2 on a bad
flag or the wrong number of files. ~plan~, ~drift~, and ~import~ exit
1 for those usage errors. Diff lines go to stdout. Errors go to
stderr.

In scripts, treat 2 from ~plan~ or ~drift~ as changes found. ~check~
uses 2 for usage, not for a difference.

| Command | Code | Meaning                                  |
|---------+------+------------------------------------------|
| check   | 0    | the spec passes                          |
| check   | 1    | the spec or an approval verb is rejected |
| check   | 2    | usage                                    |
| plan    | 0    | no diff marker                           |
| plan    | 1    | the spec, a flag, or a read failed       |
| plan    | 2    | a diff marker is present                 |
| drift   | 0    | nothing to report                        |
| drift   | 1    | the spec, a flag, or a read failed       |
| drift   | 2    | a diff marker is present                 |
| import  | 0    | the stub was written                     |
| import  | 1    | a flag, a read, or a refused overwrite   |
| (none)  | 2    | usage, or an unknown command             |

A diff marker is a line whose first character is ~+~, a tilde, ~!~,
or ~?~. ~i~ is informational and does not change the exit code.
Lines that start with ~USER STEP~ or ~USER:~ do not count, and
neither does a drift stub that starts with ~module~.

* Plan lines

Roles are printed in name order. For a role on another machine the
only diff line is ~? ROLE remote: not read~. Otherwise, within the
role: the tab, the agentbus name, cwd and model when herdr found an
agent, each cron in spec order, an edited or unmanaged brief, then an
unknown model. ~USER STEP~ lines for every selected role come after
the diff.

cwd and model lines are omitted when herdr was not read, or when no
agent is present. A configured brief file that is absent is
~+ ROLE brief missing~. An empty ~brief.text~ means the file is not
managed: plan prints ~i ROLE brief unmanaged~ when that file exists,
and that line does not change the exit code. ~+~ is a missing tab, an
agentbus name, a missing brief file, or a durable cron. A durable
cron matches a live job by the role's agentbus session and the cron
expression. The spec id is the label in the line, not the live id.
Two jobs with the same cron are split by the prompt prefix. A job
created by another session is not missing. A role with no live
handle is unverifiable. ~!~ on a brief means the file on disk was
edited in place.

A role cwd and a brief path expand a leading tilde to the home
directory. A relative brief path is joined to that cwd. ~check~
rejects a relative cwd. A missing cwd is ~? ROLE cwd not found~, and
its crons are not read as an empty job file.

The command leaves the known-model list empty, so a normal plan does
not print ~model unknown~. A snapshot that sets the list can.

| Marker | Line                         | When                                        |
|--------+------------------------------+---------------------------------------------|
| +      | + ROLE tab WORKSPACE/LABEL   | herdr was read and the tab is absent        |
| +      | + ROLE agentbus              | the agentbus name is absent                 |
| +      | + ROLE cron ID               | durable cron absent, file read, live handle |
| +      | + ROLE brief missing         | brief.file is set and the file is absent    |
| i      | i ROLE brief unmanaged       | brief.text is empty and the file exists     |
| ~      | ~ ROLE when                  | the agentbus when string differs            |
| ~      | ~ ROLE cwd                   | herdr was read and the cwd differs          |
| ~      | ~ ROLE model                 | both models are set and they differ         |
| !      | ! ROLE brief edited in place | the brief file differs from the spec        |
| !      | ! ROLE cron ID expiring      | owned job is inside the expiring window     |
| !      | ! ROLE model unknown         | model is set and not in the known list      |
| ?      | ? ROLE remote: not read      | the role's machine is not this host         |
| ?      | ? ROLE herdr: not read       | herdr could not be read                     |
| ?      | ? ROLE agentbus: not read    | agentbus names could not be read            |
| ?      | ? ROLE cwd not found         | the role directory does not exist           |
| ?      | ? ROLE cron ID unverifiable  | file not read, not durable, or no handle    |

| Line                            | When              |
|---------------------------------+-------------------|
| USER STEP: ROLE permission NAME | needs.permissions |
| USER STEP: ROLE secret NAME     | needs.secrets     |
| USER STEP: ROLE service NAME    | needs.services    |

* Drift lines

Nothing is written. Each finding is followed by a suggestion. Extras
are skipped when that source was not read, instead of failing the
command.

| Marker | Line                                     | Suggestion                                                                    |
|--------+------------------------------------------+-------------------------------------------------------------------------------|
| +      | + tab WORKSPACE/LABEL                    | add to spec, or USER: close tab LABEL in WORKSPACE if it is no longer needed |
| +      | + name NAME                              | a Pkl stub for that name                                                      |
|        | gone (stale registration): NAME          | USER: agentbus release NAME                                                   |
| +      | + cron ID                                | a Pkl stub for that cron                                                      |
| !      | ! cron ID misplaced: move to role TARGET | USER: recreate cron in role TARGET                                            |
| ~      | ~ ROLE when                              | a stub that sets the live when                                                |
| !      | ! ROLE brief edited in place             | USER: review brief for ROLE                                                   |

A cron is misplaced when the spec declares it on one role, the job
was created by a session, and that session belongs to a different
role. The session is the one in the agentbus handle. The job is the
one with the same cron expression, not the same id. The suggestion
names the role that owns the session. When that role has no live
agentbus name, it instead says to register the tab running that
session as the role, or to recreate the cron. A liveness other than
alive or unreachable, such as gone or dead, is a stale registration.

* Pools and scope

A pool hides workers so drift does not ask you to declare each one.
A role key stays a role, even when a pattern would also match it.
Each scheduled job is read once and reported once, including when
several roles share its directory.

- No ~namePattern~ and no ~tabPattern~: hide every tab in the pool's workspace. Also hide a name equal to the pool key, a name that starts with ~key-~ or ~key/~, and a name whose pane is in that workspace. The herdr agent name on that pane can differ.
- ~namePattern~ only: hide names the glob matches, and hide the tab whose pane holds such a name.
- ~tabPattern~ only: hide tabs in the workspace whose label matches.
- Both patterns: hide a tab only when the label matches and that tab hosts a matching name. A matching name on a tab that misses the glob is still reported.

When ~scope~ lists workspaces, tab drift reports only tabs in that
list. A pattern-less pool still hides its whole workspace. A
patterned pool hides only its member tabs, so an uncovered tab in a
scoped workspace is still reported. Names and scheduled jobs stay
global. An empty scope reports every workspace. ~check~ warns when a
role or pool workspace is outside that list.

#+BEGIN_EXAMPLE
pool hands, workspace workers, no patterns
  hidden: every tab in workers
  reported: tab hq/stray

pool team, workspace W, namePattern team/*
  hidden: name team/x and tab W/X, the tab its pane is on
  reported: tab W/notes

scope workspaces org-a and workers
  pool hands in workers, tabPattern hands-*
  hidden: tab misc/notes, outside the scope
  reported: tab org-a/stray
  reported: tab workers/other, in scope but not a member
  still reported: names and crons in any workspace
#+END_EXAMPLE

* Import

~import~ reads the same live state as plan and prints a stub that
amends [[file:../pkl/Org.pkl][Org.pkl]]. ~--schema PATH~ replaces that
path. ~--out~ also writes a long prompt beside the stub.

- The default amends path is the ~Org.pkl~ found by walking up from the working directory.
- Each agentbus name is joined to the herdr agent on the pane in its handle. The stub copies that pane's workspace, tab, and cwd.
- A name with no pane keeps workspace and tab as ~TODO~, and cwd as =~/TODO= so ~check~ accepts the stub.
- Colliding tab placeholders become ~TODO-1~, ~TODO-2~, and so on.
- A stale name, anything other than alive or unreachable, is a comment ~// gone: NAME~, not a role.
- A durable job is attached to the role whose handle session created it. A job with no matching role is a trailing comment.
- The schedule id is a slug of the prompt's first four words: lower case, letters and digits, joined by hyphens.
- A prompt of at most 80 characters is copied into the stub. A longer prompt is ~read("prompts/<id>.txt").text~, and ~--out~ writes that file.

Fields the snapshot cannot know, ~reportsTo~, ~decides~, ~brief~, and
~needs~, are TODO comments. Pool candidates are comments too.
