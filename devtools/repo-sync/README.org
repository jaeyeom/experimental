#+TITLE: repo-sync

repo-sync keeps files that live in a project directory but that you do
not commit there, such as local config, editor settings, and notes, the
same on every machine. It copies matching files into a local clone of a
separate private Git repository you own, then commits, pulls with
rebase, and pushes, and copies changes from other machines back. Use it
when the files are too project-specific for a dotfiles manager and you
do not want a full Syncthing share.

* How it works

~config add-project~ names the project and records five paths. ~sync~
rsyncs between the local directory and a clone on this machine, then
commits, pulls with rebase, and pushes that clone.

#+begin_example
~/projects/myproject
        <- rsync ->
~/.repo-sync/remotes/myproject
        <- git commit, pull --rebase, push ->
git@github.com:you/sync-repo.git
#+end_example

- A *project* is the name you pass on the command line, such as
  ~myproject~.
- The *sync repo* is the private Git repository you push to
  (~remote_repo~).
- The *local dir* (~local_work_dir~) is the project directory on this
  machine, such as =~/projects/myproject=.
- The *remote work dir* (~remote_work_dir~) is a local clone of the
  sync repo, not a directory on another machine. ~config add-project~
  sets it to =~/.repo-sync/remotes/<project-name>=.
- The *remote prefix* (~remote_path_prefix~) is a directory inside that
  clone. ~add~ and ~remove~ use
  ~remote_work_dir/remote_prefix/<file>~. ~sync~, ~sync download~, and
  ~sync upload~ rsync the local directory with the clone root.

~sync~ runs rsync with ~--delete~ and ~--delete-excluded~. When the
project has include patterns, rsync also gets ~--exclude=*~, so only
included names match. The copy back onto the local directory is not a
dry run. Files there that do not match an include can be deleted. Keep
the synced files in a directory that holds only those files, and run
~sync --dry-run~ before the first real sync.

~sync --dry-run~ still clones the sync repo when
=~/.repo-sync/remotes/<project-name>= is not a clone yet, and it still
runs ~git ls-remote~. It passes ~--dry-run~ to the first rsync and
skips the commit, the pull, the push, and the copy back.

* Requirements

- git
- rsync
- A private Git repository you can push to. The URL must start with
  ~git@~, ~ssh://~, or ~https://~.
- A C compiler. The database driver is ~github.com/mattn/go-sqlite3~,
  which needs cgo (~CGO_ENABLED=1~).
- Go 1.26.0 to build from this repository. The module is the repository
  root. This directory has no ~go.mod~.

* Install

Put the binary on ~PATH~ before the quick start. Building needs cgo.

#+begin_src sh
go install github.com/jaeyeom/experimental/devtools/repo-sync/cmd/repo-sync@latest
#+end_src

From a checkout of this repository:

#+begin_src sh
go install ./devtools/repo-sync/cmd/repo-sync
#+end_src

Bazel, from the repository root:

#+begin_src sh
bazel build //devtools/repo-sync/cmd/repo-sync:repo-sync
bazel run //devtools/repo-sync/cmd/repo-sync:repo-sync -- --help
#+end_src

* Quick start

Create the config directory and the database:

#+begin_src sh
repo-sync init
#+end_src

The first ~init~ prints a warning, then the paths. ~chmod~ runs before
SQLite creates ~metadata.db~. This is one captured run with ~HOME~
under a temporary directory. On your machine the same lines use
=~/.config/repo-sync=:

#+begin_example
time=2026-11-14T22:39:16.981-08:00 level=WARN msg="Failed to set database permissions" error="chmod /tmp/repo-sync-demo-FeBM/home/.config/repo-sync/metadata.db: no such file or directory"
Configuration directory: /tmp/repo-sync-demo-FeBM/home/.config/repo-sync
Database location: /tmp/repo-sync-demo-FeBM/home/.config/repo-sync/metadata.db

Next steps:
1. Add a project: repo-sync config add-project <name> --local-dir <path> --remote-repo <url>
2. Sync a project: repo-sync sync <name>
#+end_example

The next-step line omits ~--remote-prefix~. That flag is required.

Add a project. ~--local-dir~, ~--remote-repo~, and ~--remote-prefix~
are required. A ~--local-dir~ that starts with =~/= is expanded.

#+begin_src sh
repo-sync config add-project myproject \
  --local-dir ~/projects/myproject \
  --remote-repo git@github.com:you/sync-repo.git \
  --remote-prefix projects/myproject \
  --include '*.org' \
  --exclude '*.log'
#+end_src

The same captured run printed:

#+begin_example
Project 'myproject' added successfully:
  Local directory: /tmp/repo-sync-demo-FeBM/projects/myproject
  Remote repository: git@localhost:sync-repo.git
  Remote work directory: /tmp/repo-sync-demo-FeBM/home/.repo-sync/remotes/myproject
  Remote path prefix: projects/myproject
#+end_example

~status~ prints the stored paths and the counters. With no parsed
completion time, ~Last sync~ is Go's zero time:

#+begin_example
Project: myproject
Local Directory: /tmp/repo-sync-demo-FeBM/projects/myproject
Remote Repository: git@localhost:sync-repo.git
Remote Work Directory: /tmp/repo-sync-demo-FeBM/home/.repo-sync/remotes/myproject

Statistics:
  Total syncs: 0
  Successful syncs: 0
  Failed syncs: 0
  Last sync: 0001-01-01 00:00:00
  Tracked files: 0
  Conflicted files: 0
#+end_example

Preview, then sync:

#+begin_src sh
repo-sync sync myproject --dry-run
repo-sync sync myproject
#+end_src

~sync --dry-run~ prints the same four-line summary as a real sync. It
does not print an itemized "would sync" list. rsync's own output is
logged at debug. This is the stdout from the captured run. The counters
and the duration are that run's values:

#+begin_example
Sync completed successfully:
  Files synced: 0
  Bytes transferred: 0
  Conflicts resolved: 0
  Duration: 20.575083ms
#+end_example

A real ~sync~ prints those same four lines after the commit, the pull
with rebase, the push, and the copy back onto the local directory.
The default slog level is warn, so info lines stay off unless you pass
~-v~ or ~--debug~.

* Commands

~repo-sync --help~ lists these commands. ~download~ and ~upload~ are
subcommands of ~sync~, shown by ~repo-sync sync --help~. There is no
~repo-sync log~ command and no ~repo-sync test~ command.

| Command                                | Purpose                                      |
|----------------------------------------+----------------------------------------------|
| repo-sync init                         | Create the config directory and database     |
| repo-sync sync <project>               | Rsync both ways, then commit, pull, and push |
| repo-sync sync download <project>      | Pull, then copy the clone onto the local dir |
| repo-sync sync upload <project>        | Copy the local dir onto the clone, then push |
| repo-sync add <project> <file>         | Copy one file under the prefix and commit    |
| repo-sync remove <project> <file>      | Delete the local file and the prefix copy    |
| repo-sync status [project]             | Print paths and sync counts                  |
| repo-sync verify <project>             | Print checks; connectivity is not checked    |
| repo-sync config add-project <name>    | Save a project mapping                       |
| repo-sync config remove-project <name> | Delete the mapping file only                 |
| repo-sync config list-projects         | List project mappings                        |
| repo-sync config show-project <name>   | Print one project mapping                    |
| repo-sync completion                   | Print a shell completion script              |
| repo-sync help [command]               | Print help                                   |

*Warning.* ~repo-sync remove <project> <file>~ deletes that file from
the local directory and from ~remote_work_dir/remote_prefix/<file>~,
then commits and pushes the deletion. It does not merely drop the file
from the sync set. Unless you pass ~--confirm~, it asks:

#+begin_example
Are you sure you want to remove '<file>' from project '<project>'? [y/N]:
#+end_example

On success it prints ~File removed successfully:~, the file path, the
git commit, and ~Deletion timestamp:~ in ~2006-01-02 15:04:05~ form.
Other machines are not told about the deletion. See
[[*Not yet implemented]].

~config remove-project~ is different. It deletes the mapping file
=~/.config/repo-sync/mappings/<name>.yaml= and leaves your files and
the clone in place. Without ~-f~ / ~--force~ it asks:

#+begin_example
Are you sure you want to remove project '<name>'? [y/N]:
#+end_example

Flags that exist in help:

- ~--reset-db~ on ~init~ deletes an existing database, then creates the
  tables again.
- ~--dry-run~ on ~sync~, ~sync download~, and ~sync upload~ passes
  ~--dry-run~ to rsync. On ~sync~ it also skips the commit, the pull,
  the push, and the copy back.
- ~--force~ on ~sync~ is accepted. The sync engine does not read it.
- ~--confirm~ on ~remove~ skips the prompt. The local file is still
  deleted.
- ~-f~ / ~--force~ on ~config remove-project~ skips that prompt.
- ~config add-project~ requires ~--local-dir~, ~--remote-repo~, and
  ~--remote-prefix~. Repeat ~--include~ and ~--exclude~ for each
  pattern.
- ~--config~ selects the config file. The default is
  =~/.config/repo-sync/config.yaml=.
- ~-v~ / ~--verbose~ sets slog to info. ~--debug~ sets slog to debug.
  ~-h~ / ~--help~ prints help.

~sync download~ prints ~Download completed:~ and then
~Files downloaded:~ and ~Bytes transferred:~. ~sync upload~ prints
~Upload completed:~ and then ~Files uploaded:~ and
~Bytes transferred:~. ~add~ prints ~File added successfully:~, the
file path, the size in bytes, and the git commit.

~status~ with no project name prints one summary line per project,
~Project Status Summary:~ and then the name, ~OK~, ~CONFLICTS~, or
~ISSUES~, and ~Last sync:~ as ~2006-01-02 15:04~. No projects prints
~No projects configured~.

* Configuration

Global settings are =~/.config/repo-sync/config.yaml=. ~init~ writes
this file when it is missing:

#+begin_src yaml
# Repo-Sync Configuration
# Global settings for repo-sync utility

# Default sync patterns (can be overridden per project)
default_sync_patterns:
  include:
    - "*.yaml"
    - "*.yml"
    - "*.json"
    - "*.toml"
    - "*.ini"
    - "*.conf"
    - "*.config"
    - "*.md"
    - "*.txt"
    - "*.org"
  exclude:
    - "*.tmp"
    - "*.log"
    - "*.cache"
    - ".git/**/*"
    - "node_modules/**/*"
    - "__pycache__/**/*"

# Conflict resolution preferences
conflict_resolution:
  default_strategy: "timestamp_newest"
  backup_conflicts: true

# Performance settings
performance:
  rsync_compression_level: 6
  max_concurrent_operations: 3
  timeout_seconds: 300

# Logging settings
logging:
  level: "info"
  file_retention_days: 30
  max_file_size_mb: 10
#+end_src

The running code reads two of those groups:

- ~default_sync_patterns~, when a project has no include patterns and
  no exclude patterns.
- ~performance.rsync_compression_level~, passed to rsync as
  ~--compress-level~.

The other keys are parsed and otherwise unused. See
[[*Not yet implemented]]. The slog level comes from ~-v~ and ~--debug~,
not from ~logging.level~.

Each project is =~/.config/repo-sync/mappings/<name>.yaml=. The keys
are ~project_name~, ~local_work_dir~, ~remote_repo~,
~remote_work_dir~, ~remote_path_prefix~, and ~sync_patterns~ with
~include~ and ~exclude~. ~add-project~ stores absolute paths.
~sync_patterns~ on the project replace the global patterns when either
list is non-empty.

The database is =~/.config/repo-sync/metadata.db=. ~init~ also creates
~mappings~, ~logs~, ~backups~, ~rollbacks~, and ~locks~ under
=~/.config/repo-sync=. Nothing else in the program reads or writes
~logs~, ~backups~, ~rollbacks~, or ~locks~.

* Using it on a second machine

Run ~init~ there. Run ~config add-project~ with the same
~--remote-repo~ and ~--remote-prefix~, and with the local directory on
that machine. The project name selects
=~/.repo-sync/remotes/<project-name>= on that machine. ~add-project~
only writes the mapping. The clone is created when ~sync~,
~sync download~, ~sync upload~, or ~add~ builds the engine. Then run
~sync~.

~remove~ deletes the file on the machine where you run it and pushes
that deletion. It does not record the deletion for the other machine,
so a later ~sync~ there can copy the file back.

* Troubleshooting

- ~config add-project~ fails with ~local directory does not exist~ when
  ~--local-dir~ is missing on disk. Create the directory first.
- ~invalid remote repository URL~ means the URL does not start with
  ~git@~, ~https://~, or ~ssh://~.
- ~sync~ fails before copying files when ~git ls-remote~ cannot reach
  ~remote_repo~, or when ~git clone~ cannot create the remote work
  dir. ~--dry-run~ does not skip those checks.
- ~rsync command failed~ means the rsync invocation failed. Pass
  ~--debug~ to log rsync's own lines.
- The ~chmod~ warning on the first ~init~ is the database file not
  existing yet. The ~Configuration directory~ line after it is the
  result. Run ~init~ again only to recreate a database you removed, or
  pass ~--reset-db~ to delete the current database first.
- ~verify~ prints a checkmark before it has checked the local
  directory, SSH, or the remote work dir. A successful exit means the
  database opened. See [[*Not yet implemented]].
- There is no command that drops a file from the sync set and leaves
  the local file on disk. ~remove~ deletes it.

* Not yet implemented

These are not in the code. The design notes under [[*Development]]
describe some of them as later work.
[[file:IMPLEMENTATION_PLAN.md][IMPLEMENTATION_PLAN.md]] marks phases 3
and 4 as not implemented.

- Conflict strategies other than "keep one side of the hunk". On a
  rebase conflict, ~resolveFileConflict~ in ~internal/git/manager.go~
  keeps the incoming side when that side has any lines, and otherwise
  keeps the local side. It does not compare timestamps, and it does
  not offer a content or manual strategy.
  ~conflict_resolution.default_strategy~ and
  ~conflict_resolution.backup_conflicts~ are not read.
- ~performance.max_concurrent_operations~ and
  ~performance.timeout_seconds~ are not read.
- ~logging.level~, ~logging.file_retention_days~, and
  ~logging.max_file_size_mb~ are not read.
- ~sync --force~ is accepted and not read.
- Cross-machine deletion tracking. ~internal/reposync/engine.go~ has a
  TODO at the end of ~RemoveFile~. ~remove~ deletes the local file and
  the copy under the prefix, then commits and pushes. It does not
  store a deletion row for other machines.
- Connectivity checks in ~verify~. The local-directory, SSH, and
  remote-directory checks are TODOs in ~internal/cli/status.go~. Only
  opening the database is real.
- Git hooks and branch management. The git step in the clone is
  commit, ~pull --rebase~, and push.
- The ~logs~, ~backups~, ~rollbacks~, and ~locks~ directories created
  by ~init~.
