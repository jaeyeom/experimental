#+TITLE: docsync
#+DATE: 2026-11-15

docsync tells you which documentation might be out of date after a
code change. You list, in a docsync.yml file, which source files each
doc describes. Then docsync check --base main compares your branch
with main and prints the docs whose source files changed. It only
points at docs. Deciding whether they need edits is up to you. Run it
before you commit, in CI, or while reviewing a pull request.

* Quick start

** Install

#+BEGIN_SRC bash
go install github.com/jaeyeom/experimental/devtools/docsync/cmd/docsync@latest
#+END_SRC

Or with Bazel from this repo:

#+BEGIN_SRC bash
bazel run //devtools/docsync/cmd/docsync -- version
#+END_SRC

After ~go install~, put ~$GOPATH/bin~ or ~$GOBIN~ on ~PATH~.

** Write docsync.yml

The mapping root is the directory that contains ~docsync.yml~. Save
the file there, usually the repository root. Every path in it is
relative to that directory. ~docs[].path~ must exist on disk.

#+BEGIN_SRC yaml
version: 1
rules:
  - match: ["internal/auth/**/*.go"]
    docs:
      - path: docs/api-reference.md
        why: token TTL + claim shape
#+END_SRC

A commented three-rule map is [[file:docsync.yml.example][docsync.yml.example]].

** Check

#+BEGIN_SRC bash
docsync check --base main
#+END_SRC

There is no default base. When ~internal/auth/token.go~ changed, the
text report looks like this:

#+BEGIN_EXAMPLE
Affected docs (1):
  docs/api-reference.md
    ← internal/auth/token.go (why: token TTL + claim shape)
#+END_EXAMPLE

When nothing you listed changed:

#+BEGIN_EXAMPLE
All clear — no docs implicated.
#+END_EXAMPLE

* Config discovery

~check~ and ~validate~ walk *up* from the current directory looking for
~docsync.yml~, the way git finds ~.git~. The directory that contains
that file is the mapping root.

1. ~--config PATH~ — use this file. It must exist; a missing file
   exits 2. That file's directory becomes the mapping root.
2. Otherwise walk up from the current directory. Under ~bazel run~,
   the current directory is ~BUILD_WORKING_DIRECTORY~.
3. If none is found, that is a precondition error (exit 3).

All ~match~ globs and ~docs[].path~ values are relative to the mapping
root. Changed paths from ~git diff --name-only~ are repository-root
relative. Paths from ~--files~ or stdin may be relative to the current
directory or absolute. docsync normalizes them to the mapping root
before matching. A path outside the mapping root is dropped, not
reported as an error. That is normal when the mapping root is a
subdirectory of a larger repository.

* Typical uses

- Before a commit, list the staged paths:
  ~git diff --name-only --cached | docsync check -~
- In CI, compare the branch to the default branch:
  ~docsync check --base main~
- While reviewing a pull request, the same command with ~--json~ gives
  an agent a list of docs to read. ~--exit-zero~ keeps the exit code
  at 0 when docs are listed, which is what a warning step wants.

* Commands

#+BEGIN_EXAMPLE
docsync check    --base REF | --files PATH ... | -
                 [--config PATH] [--json] [--exit-zero]
docsync validate [--config PATH]
docsync version
#+END_EXAMPLE

| Command    | Effect                                 |
|------------+----------------------------------------|
| ~check~    | Match changed files to implicated docs |
| ~validate~ | Lint ~docsync.yml~ (no git)            |
| ~version~  | Print version and build metadata (~--json~) |

** check

Requires exactly one of ~--base~ or ~--files~ / ~-~. Both or neither is a
usage error (exit 2). There is no implicit default base.

| Flag               | Effect                                        |
|--------------------+-----------------------------------------------|
| ~--base REF~       | Changes via ~git diff --name-only REF...HEAD~ |
| ~--files PATH~     | Explicit changed file (repeatable)            |
| ~-~ or ~--files -~ | NUL- or newline-separated paths from stdin    |
| ~--config PATH~    | Mapping file (default: upward discovery)      |
| ~--json~           | Emit JSON instead of the text report          |
| ~--exit-zero~      | Exit 0 even when docs are implicated          |

#+BEGIN_SRC bash
docsync check --base main
docsync check --files internal/auth/token.go --files config/schema.go
docsync check --files - --json < changed.txt
git diff --name-only main...HEAD | docsync check -
#+END_SRC

Text report, one block per implicated doc (deduped by path + section):

#+BEGIN_EXAMPLE
Affected docs (2):
  docs/api-reference.md  §Authentication
    ← internal/auth/token.go (why: token TTL + claim shape)
  docs/configuration.md
    ← config/schema.go (why: documented option list)
#+END_EXAMPLE

JSON (~--json~). Keys are snake_case (~triggered_by~,
~changed_files~, ~unmatched_files~). ~unmatched_files~ are changed
paths that hit no rule:

#+BEGIN_SRC json
{
  "affected": [
    {
      "path": "docs/api-reference.md",
      "section": "## Authentication",
      "why": "token TTL + claim shape",
      "triggered_by": ["internal/auth/token.go"]
    }
  ],
  "changed_files": ["internal/auth/token.go", "config/schema.go"],
  "unmatched_files": ["README.md"]
}
#+END_SRC

** validate

Loads and lints the mapping without touching git.

#+BEGIN_SRC bash
docsync validate
docsync validate --config ./docsync.yml
#+END_SRC

Checks: schema (~version~ must be ~1~, required fields, unknown keys),
each ~match~ glob compiles, each ~docs[].path~ exists on disk (error),
and — warning only — a rule whose globs currently match zero files in
the tree.

#+BEGIN_EXAMPLE
docsync.yml: 2 problems
  error  rule[3].match "src/**.go" is not a valid glob (bare ** must be a path segment)
  warn   rule[5].match ["legacy/*.go"] matches no files currently tracked
  error  rule[1].docs[0].path "docs/old-name.md" does not exist
#+END_EXAMPLE

Clean mapping prints ~docsync.yml: ok~.

~docsync~ also implements ~update [--check] [--ref <ref>] [--json]~,
~doctor [--json] [--offline]~, and ~skill [install|uninstall|status ...]~.

* Mapping file

~docsync.yml~, schema version ~1~, one ~rules~ list. Each rule is a set
of ~match~ globs and the docs that describe those files. ~section~ and
~why~ are optional. ~path~ is required. Unknown YAML keys are a hard
error. An exact path is just a glob with no wildcards.

** Glob semantics

Matching uses ~github.com/bmatcuk/doublestar/v4~ (~*~, ~**~, ~?~,
~[...]~, ~{a,b}~). Patterns are slash-separated.

1. *Root-anchored, not floating.* A pattern matches the entire
   mapping-root-relative path. There is no implicit ~**/~ prefix.
   ~config/schema.go~ matches only that file, not
   ~src/config/schema.go~. This differs from ~.gitignore~. To match a
   name at any depth, write the ~**/~ yourself.

   | Pattern               | Matches                                    | Doesn't match           |
   |-----------------------+--------------------------------------------+-------------------------|
   | ~config/schema.go~    | ~config/schema.go~                         | ~src/config/schema.go~  |
   | ~**/config/schema.go~ | ~config/schema.go~, ~src/config/schema.go~ | ~config/schema_test.go~ |
   | ~**/schema.go~        | any ~schema.go~ at any depth               | —                       |

2. *A leading ~/~ is stripped.* ~/config/schema.go~ and
   ~config/schema.go~ mean the same thing.

3. *Bare ~**~ must be a complete path segment.* ~src/**.go~ is invalid;
   write ~src/**/*.go~.

* Exit codes

| Code | ~check~                                                       | ~validate~                      |
|------+---------------------------------------------------------------+---------------------------------|
| 0    | No docs implicated                                            | Clean                           |
| 1    | One or more docs implicated                                   | Warnings only                   |
| 2    | Usage, config, or flag error                                  | Any hard error                  |
| 3    | Git not found, not a repo, or mapping not found via discovery | Mapping not found via discovery |

~check --exit-zero~ forces 0 unless the run itself errored (2 and 3
still apply).

* Non-goals

docsync does not draft doc edits, does not talk to the network, and
does not read ~last_reviewed~ front-matter.
