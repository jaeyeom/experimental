* Overview

Small command-line tools I use day to day, mostly in Go. They fall
into three groups: code-quality helpers you can use in any repo
(devcheck, linters), GitHub and Jira helpers (gh-pr-review, gh-outbox,
rename-jira-keys, reviewpush), and experimental companions to the
[[https://github.com/chorong-sh/chorong][chorong]] stack for running coding agents side by side in
[[https://herdr.dev/][herdr]] terminal panes (agent-pool, install-check, quotapace, slackwatch).
Each tool has its own README. Start with the one-line summaries below.

* Agent workflow
:PROPERTIES:
:CUSTOM_ID: agent-workflow
:END:

[[https://herdr.dev/][herdr]] is the terminal multiplexer. One pane holds one coding
agent. Core workflow tools (=agentbus=, =decide=, =prsync=, =orgctl=) now live in
[[https://github.com/chorong-sh/chorong][chorong]], and the remaining Wave 2 companions stay here while incubating:

#+BEGIN_EXAMPLE
herdr panes
    |
    +-- agentbus    agents message each other (chorong)
    +-- decide      you answer and approve (chorong)
    +-- slackwatch  Slack replies in, approved drafts out
    +-- prsync      one agent tab per open pull request (chorong)
    +-- orgctl      the written description of the team (chorong)
#+END_EXAMPLE

agentbus is the bus. It is not the user's approval. decide is the
inbox for questions and approvals. slackwatch delivers Slack replies
to the agent that owns the post, and posts a draft only after decide
has approved it. prsync keeps a herdr tab lined up with each open
pull request. orgctl checks a declarative team spec against the live
tabs, names, and scheduled jobs. After a reboot, follow
[[https://github.com/chorong-sh/chorong/blob/main/agentbus/reboot.md][the agentbus runbook]].

- *Ansible*, for setup-dev.

** Versioning and releases

All tools share a single monorepo Semantic Versioning tag
(=vMAJOR.MINOR.PATCH=) at the repository root. You can install a
specific release of any Go tool with:

#+BEGIN_SRC bash
go install github.com/jaeyeom/experimental/devtools/<tool>/cmd/<tool>@vX.Y.Z
#+END_SRC

=make install= builds every binary in =INSTALL_CMDS= with =-ldflags=
embedding the latest git tag (or =dev= when untagged), and Go binaries
fall back to =runtime/debug.ReadBuildInfo()= when installed via
=go install ...@vX.Y.Z=.

Releases are automated via =release-please=
(=.github/workflows/release.yml=, =release-please-config.json=, and
=.release-please-manifest.json=). Pushing conventional commits to =main=
updates an open Release PR (for example, =chore(main): release 0.2.0=)
with a proposed version bump and root =CHANGELOG.md= entries grouped by
change type while preserving tool scopes and hiding internal chores and
dependency bumps. During =0.x=, =bump-minor-pre-major= is enabled so
breaking changes (=feat!:= / =BREAKING CHANGE=) bump minor rather than
graduating to =1.0.0=. No tag or release is created until a maintainer
reviews and squash-merges the Release PR.

*** Release checklist

1. *Inspect the open Release PR*: verify the proposed SemVer bump
   against [[file:../AGENTS.md][AGENTS.md]]. To override the version,
   add a commit with a =Release-As: X.Y.Z= footer (for example,
   =git commit --allow-empty -m "chore: release X.Y.Z" -m "Release-As: X.Y.Z"=)
   so =release-please= updates the Release PR.
2. *Review and polish =CHANGELOG.md=*: add migration notes for breaking
   changes or clarify terse commit titles on the Release PR branch if
   needed.
3. *Confirm CI (=Bazel Tests=) is green*: make sure no multi-PR feature
   is half-landed and =Bazel Tests= passed on the Release PR. Because
   PRs created by the default =GITHUB_TOKEN= do not automatically
   trigger =pull_request= workflows, close and reopen the Release PR (or
   push a polish commit to its branch, or configure a
   =RELEASE_PLEASE_TOKEN= secret) to trigger CI before merging.
4. *Squash-merge the Release PR*: keep =main= history flat. On merge,
   =.github/workflows/release.yml= creates the =vX.Y.Z= tag, publishes
   the GitHub Release from =CHANGELOG.md=, and verifies
   =make install VERSION=vX.Y.Z=.
5. *Verify the published release*: inspect the GitHub Release notes and
   test =go install github.com/jaeyeom/experimental/devtools/<tool>/cmd/<tool>@vX.Y.Z=.

*** Manual tag fallback

=make tag TAG=vX.Y.Z= remains as a manual fallback and guards against
diverging from =.release-please-manifest.json= (pass =FORCE=1= to
override). Prefer the Release PR workflow so =CHANGELOG.md= and the
manifest stay in sync.

** gh-nudge commands

=devtools/gh-nudge/cmd/= currently keeps =gh-pr-review=, which =make install=
installs. The other =gh-nudge= commands (=gh-approve=, =gh-codeowners=,
=gh-merge=, =gh-nudge=, =gh-slack=, =gh-storage=, and =gh-throttle=)
moved to [[https://github.com/chorong-sh/chorong][chorong-sh/chorong]].

** ascii-art

The implemented command is =box-renderer=:

#+BEGIN_SRC bash
bazel build //devtools/ascii-art/cmd/box-renderer
#+END_SRC

=gantt-chart= and =graph-viz= are planned. They have no build target.
