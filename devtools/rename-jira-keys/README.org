#+TITLE: rename-jira-keys
#+DATE: 2026-11-15

* Overview

~rename-jira-keys~ updates a Markdown planning folder when a Jira
ticket's key changes, for example after a move from ~PROJ~ to ~ACME~.
It replaces every whole-word ~OLD-KEY~ with ~NEW-KEY~ in the plan file
and in every ~*.md~ file directly under the docs directory, then
renames ~OLD-KEY.md~ and ~OLD-KEY-*.md~ to match.

It writes those edits in place. There is no dry run and no backup.
Run it on a clean Git tree.

* Expected layout

The plan file is the index that mentions ticket keys. It defaults to
~plan.md~ in the working directory. The docs directory is the folder
of one Markdown file per ticket. It defaults to ~docs/project~. A
ticket can also have a note whose name starts with the key and a
hyphen.

#+BEGIN_EXAMPLE
plan.md
docs/project/PROJ-123.md
docs/project/PROJ-123-login-flow.md
#+END_EXAMPLE

* Quick start

With that layout, and ~PROJ-123~ written in each file:

#+BEGIN_SRC bash
rename-jira-keys --old PROJ-123 --new ACME-10
#+END_SRC

#+BEGIN_EXAMPLE
Renaming Jira key from 'PROJ-123' to 'ACME-10'
Plan file: plan.md
Docs directory: docs/project
==================================================
Updated plan.md
Updated docs/project/PROJ-123-login-flow.md
Updated docs/project/PROJ-123.md
Renamed docs/project/PROJ-123-login-flow.md to docs/project/ACME-10-login-flow.md
Renamed docs/project/PROJ-123.md to docs/project/ACME-10.md

Summary: Updated 3 files
Operation completed successfully!
#+END_EXAMPLE

The tree is then:

#+BEGIN_EXAMPLE
plan.md
docs/project/ACME-10.md
docs/project/ACME-10-login-flow.md
#+END_EXAMPLE

* What gets changed

Content replacement uses a word boundary. ~MYPROJ-123~ is left alone
when the old key is ~PROJ-123~. The same key inside ~PROJ-123-extra~
is replaced, because the key ends at the hyphen.

File renaming keeps the suffix:

- ~OLD-KEY.md~ becomes ~NEW-KEY.md~.
- ~OLD-KEY-*.md~, such as ~OLD-KEY-login-flow.md~, becomes ~NEW-KEY-login-flow.md~.

Only ~*.md~ files directly in the docs directory are read. A file in
a subdirectory is left alone. If the new name already exists, that
file is not renamed.

* Options

| Flag        | Alias     | Default      |
|-------------+-----------+--------------|
| --old       | --old-key | required     |
| --new       | --new-key | required     |
| --plan-file | -p        | plan.md      |
| --docs-dir  | -d        | docs/project |

~-old~ and ~--old~ are the same flag. The alias is ~--old-key~.
The same is true for ~--new~ and ~--new-key~.

#+BEGIN_SRC bash
rename-jira-keys --old DEV-400 --new DEV-900 -p roadmap.md -d documentation/tickets
#+END_SRC

* Install

Go 1.26 or later.

#+BEGIN_SRC bash
go install github.com/jaeyeom/experimental/devtools/rename-jira-keys/cmd/rename-jira-keys@latest
#+END_SRC

From a clone of this repo:

#+BEGIN_SRC bash
go install ./devtools/rename-jira-keys/cmd/rename-jira-keys
#+END_SRC
