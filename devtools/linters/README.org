#+TITLE: Linters
#+DATE: 2026-11-15

* Overview

This directory holds three small linters. ~org-lint~ runs Emacs's built-in
Org-mode linter from the command line, so ~.org~ files can be checked in
CI. The two Go linters catch patterns ~golangci-lint~ doesn't: interface
assertions that guard nothing, and package-level variables that should be
constants or that run code at init time.

~make lint~ runs ~pkgvar~.
[[file:../devcheck/README.org][devcheck]] runs
~unnecessary-interface-assertion-linter~ when it falls back to Go tools.
Emacs packages for ~org-lint~ come from
[[file:../setup-dev/README.org][setup-dev]].

Go 1.26 or later.

* Index

| Tool                                   | Checks                                                       | Language | Typical use                    |
|----------------------------------------+--------------------------------------------------------------+----------+--------------------------------|
| org-lint                               | Org-mode syntax and source blocks, via Emacs org-lint        | Org      | CLI, on .org files             |
| unnecessary-interface-assertion-linter | var _ I = (*T)(nil) when that assertion adds nothing         | Go       | devcheck's Go fallback         |
| pkgvar                                 | package-level var that should be const, or that runs at init | Go       | make lint, via go vet -vettool |

* Tools

** org-lint

Runs Emacs's built-in ~org-lint~ on one or more ~.org~ files. Pass every
file in one command. One Emacs process checks all of them.

Emacs starts in batch mode, adds the current Emacs version's ELPA
directory to ~load-path~ (both =~/.emacs.d= and =~/.config/emacs=), and
loads the ~ob-*~ and ~*-mode~ packages it can. A package that fails to
load is skipped. That is what lets source blocks be checked.

*** Install

Emacs with Org mode. [[file:../setup-dev/README.org][setup-dev]] installs
those packages with ~./ensure.sh org-lint~ from
~devtools/setup-dev/ansible/~.

#+BEGIN_SRC bash
go install github.com/jaeyeom/experimental/devtools/linters/cmd/org-lint@latest
#+END_SRC

*** Usage

#+BEGIN_SRC bash
org-lint README.org
org-lint file1.org file2.org
DEBUG=1 org-lint README.org
org-lint --skip-if-no-emacs *.org
#+END_SRC

*** Output

~org-lint sample.org~ prints one line per finding. ~sample.org~ had a
link to a missing file, two headings with the same custom id, and
~#+ATTR_ORG: :align nowhere~ on a paragraph:

#+BEGIN_EXAMPLE
sample.org:3: (low) Link to non-existent local file "missing.org"
sample.org:7: (nil) Duplicate CUSTOM_ID property "same"
sample.org:12: (nil) Duplicate CUSTOM_ID property "same"
sample.org:15: (high) "nowhere" not a supported value for #+ATTR_ORG keyword attribute ":align".
#+END_EXAMPLE

~(low)~ is a weaker check, ~(high)~ is a stronger one, and ~(nil)~ means
the check set no trust level. The level is only a hint from Emacs.

*** Exit codes

- ~org-lint~ exits 0 when every file is clean. It also exits 0 when
  ~--skip-if-no-emacs~ is set and ~emacs~ is not on ~PATH~.
- It exits 1 when a file has a finding, a file is missing, ~emacs~ is
  not on ~PATH~, or no file was given.

** unnecessary-interface-assertion-linter

Flags ~var _ Iface = (*T)(nil)~ when two things are both true: only one
type implements ~Iface~, and the name ~Iface~ appears only on that line.
A use of the name, such as a function parameter, keeps the line. A second
implementation keeps it too.

#+BEGIN_SRC go
package iface

type Runner interface{ Run() }

type runner struct{}

func (*runner) Run() {}

var _ Runner = (*runner)(nil)
#+END_SRC

The path is absolute. A run of this file ends with:

#+BEGIN_EXAMPLE
bad.go:9:1: Unnecessary interface assertion
#+END_EXAMPLE

Adding ~func start(r Runner) { r.Run() }~ uses the name, and the finding
goes away.

*** Install

#+BEGIN_SRC bash
go install github.com/jaeyeom/experimental/devtools/linters/cmd/unnecessary-interface-assertion-linter@latest
#+END_SRC

*** Usage

#+BEGIN_SRC bash
unnecessary-interface-assertion-linter ./...
unnecessary-interface-assertion-linter --json ./...
unnecessary-interface-assertion-linter --dir path/to/module ./...
#+END_SRC

~--json~ is what [[file:../devcheck/README.org][devcheck]] reads.

*** Exit codes

- The command exits 0 when there is no finding.
- It exits 1 when there is a finding or a package fails to load.
- It exits 2 when the flags are invalid.

** pkgvar

A package-level ~var~ that never changes should be a ~const~. ~pkgvar~
also flags an initializer that calls a function or receives from a
channel when the package is loaded.

#+BEGIN_SRC go
package sample

import (
	"os"
	"regexp"
)

func loadConfig() string { return os.Getenv("CFG") }

var maxRetries = 3
var re = regexp.MustCompile(`x`)
var cfg = loadConfig()
var version = "dev" //nolint:pkgvar // set with -ldflags -X
var _ = regexp.MustCompile(`x`)
#+END_SRC

~maxRetries~ is never assigned and the package never takes its address,
so it should be a constant. ~re~ is quiet: ~regexp.MustCompile~ is on the
allowlist and the result is stored in ~re~. ~cfg~ is flagged because
~loadConfig~ calls ~os.Getenv~, which runs when the package is
initialized. ~version~ stays a variable. The ~nolint~ comment names
~pkgvar~ and gives a reason, which is how a string set with ~-ldflags -X~
is kept. A comment with no reason does not suppress the finding. The
blank ~var _~ is flagged even though ~regexp.MustCompile~ is on the
allowlist, because the result is discarded.

The message says "impure" when the call is not on the allowlist and is
not one of the builtins ~len~, ~cap~, ~complex~, ~real~, ~imag~, ~min~,
~max~, ~new~, and ~make~. A function in the same package is allowed only
when its body stays within those calls and does not change other
package-level variables, take their addresses, start a goroutine, defer,
send, or receive.

A compile-time interface assertion is not a ~pkgvar~ finding. The other
Go linter in this directory reports those.

The default allowlist is every name in the command below except
~example.com/config.Load~. The ~-allowlist~ flag replaces the whole list.
It does not append.

*** Install

#+BEGIN_SRC bash
go install github.com/jaeyeom/experimental/devtools/linters/cmd/pkgvar@latest
#+END_SRC

*** Usage

#+BEGIN_SRC bash
go vet -vettool=$(which pkgvar) ./...
#+END_SRC

#+BEGIN_SRC bash
go vet -vettool=$(which pkgvar) -allowlist errors.New,fmt.Errorf,regexp.MustCompile,strings.Join,strings.Repeat,strings.ReplaceAll,strings.Split,example.com/config.Load ./...
#+END_SRC

*** Output

~go vet~ prints paths relative to the package directory:

#+BEGIN_EXAMPLE
sample.go:10:5: package-level variable can be a constant
sample.go:12:5: package-level initializer calls an impure function or receives from a channel
sample.go:14:5: package-level initializer discards its result
#+END_EXAMPLE

~re~ and ~version~ produce no line. The ~pkgvar~ binary prints an
absolute path for the same three lines.

*** Exit codes

- ~go vet -vettool~ exits 0 when there is no finding and exits 1 when
  there is a finding or the package did not load.
- The ~pkgvar~ binary exits 3 when it prints a finding. It exits 1 when
  no package is given.
