#+TITLE: prsync team cover

The short guide is [[file:../README.org][the prsync README]].

* Ranking and calls

~team_cover~ is off by default, so the JSON above has no suggestion
field. With it on, stdout stays JSON. Human-readable lines and one
ready-to-run hint per pull request go to stderr, and prsync does not
run the hint:

#+BEGIN_EXAMPLE
acme/widgets#123 org/some-team: suggest alice (codeowner: src/foo/**, 3 open direct requests)
acme/widgets#123 org/other-team: covered by bob
acme/widgets#123 org/third-team: uncovered: all 2 members excluded (1 author, 1 inactive)
gh pr edit 123 --repo acme/widgets --add-reviewer alice
#+END_EXAMPLE

A team is covered when one of its members is already requested
individually or has submitted a review whose state is not ~PENDING~.
~covered_by~ prefers a requested member over a reviewer, then login
order. Suggestions skip the author, bots (~[bot]~ or user type ~Bot~),
excluded logins, people who already approved, and (when
~team_cover_active_days~ is set) members with no recent org event.
Coverage still counts those people. A person who belongs to two
uncovered teams is suggested once in the hint and listed on each team
they cover. The smallest teams are filled first. Already-picked people
are reused before the next team is ranked.

Ranking uses the configured signals, then login order: more owned
touched paths (CODEOWNERS on the base branch, last match wins, user or
a team they belong to), then more recent commits authored or reviewed
on those paths, then fewer open direct review requests
(~user-review-requested:<login>~ in the repo owner org, not
~review-requested:~). Reasons name the winning CODEOWNERS pattern, the
history counts, and the open-request count.

Missing ~read:org~, or a failed member list, sets that team's ~error~
and a stderr warning. The scan continues. A review-request search
failure skips that signal for the rest of the run, warns, and still
suggests from the remaining signals. An events-API error skips the
activity filter instead of dropping candidates. A rate limit (primary
or secondary) on any team-cover call stops team-cover for the round at
once: the call is not retried, no later team-cover call is made, no
signal is dropped to fall back on, and PRs not ranked yet get no
~team_review_suggestions~ until a later round. The round output and the
warnings say ~team-cover: stopped (rate limited)~. With the feature off,
scan does not call team members, CODEOWNERS, path history, or the
review-request search. With it on, a round where no PR has a requested
team makes none of those calls either, and changed files, CODEOWNERS,
and path history are fetched only for PRs with a team no member covers.


* Detail from the key table

Each entry is the note that used to sit in the key table.

** team_cover

When true, ~scan~ suggests individual reviewers for each requested team that
no member already covers. Report only: prsync never runs ~--add-reviewer~.
Off leaves scan JSON and the GitHub call budget unchanged.

** team_cover_signals

Ranking signals, in that priority order. Empty disables every signal and
leaves login order. Duplicate names are dropped. An unknown name is a config
error.

** team_cover_history_days

Authored commits and reviews on touched paths in this window. Each path asks
for at most 30 commits and 2 pull requests per commit,
~team_cover_batch_paths~ paths to a request; each distinct pull request's
reviews (at most 10) are then fetched once, 50 pull requests to a request. A
cut-off list is logged as a warning. Only paths of PRs with an uncovered
team that still has a member to rank are queried; M being the paths of PRs
whose files were listed, the round output (stderr) and the run log end with
~team-cover: paths N/M need history (X hits); team members A hits/B calls; files C/D; reviews E/F; refresh R; calls Y (cap Z)~,
where each pair is round-cache hits and real calls. A path's result is
reused for ~team_cover_history_ttl~ (see Round cache). Must be >= 0.

** team_cover_active_days

Drop members with no org event in this many days. ~0~ disables the filter.
The events API covers about 90 days. Must be >= 0.

** team_cover_every

Run the team-cover job on every Nth round: the 1st, N+1th, and so on. The
count is kept in the round cache and counts rounds with ~team_cover~ on and
the job not skipped. A skipped round omits ~team_review_suggestions~. Must
be >= 1.

** team_cover_batch_paths

Paths per path-history request. A request that times out (GitHub stops a
GraphQL query after about 10 seconds) or reports ~RESOURCE_LIMITS_EXCEEDED~
or HTTP 502/504 is split in half and each half retried, down to single
paths; a single path that still fails is skipped with a warning in the run
log, e.g. ~team-cover: batch of 20 timed out; retrying as 2×10~, with the
first line of stdout and stderr. After two requests in a row work whole, the
size doubles, up to this value. The size that worked is kept in the round
cache (never below 2 unless two paths fail together that each work alone)
and the next round starts there instead. Must be >= 1.

** team_cover_history_ttl

Go duration. How long a path's history is reused, keyed by repository, base
branch, path, and the history window's start day, whatever the base branch
head. Each entry lasts a deterministic hash of its key, between half this
TTL and the TTL, so a batch stored together expires gradually; a hit does
not extend it, and nothing is reused past the TTL. An unscoped ~scan~ that
finishes with calls left under ~team_cover_max_calls~ refetches the entries
closest to expiry, oldest first, in the same batched history requests, up to
~team_cover_refresh_max_calls~. Those calls count toward
~team_cover_max_calls~ and the summary names them as ~refresh R~.
~dispatch~, ~gate~, ~scan --repo~, ~scan --in-scope~, and a single-PR scan
do not refetch. A window of weeks barely changes in a few hours, so a
slightly stale list is accepted. Each entry is dropped on its own lifetime
when the round cache is written. ~0~ keys it by the base branch head instead
(reused while the head is unchanged, for at most a day, with no jitter and
no early refresh). Must be >= 0.

** team_cover_history_slack_days

How many days earlier than the current UTC window start a stored
path-history entry may be and still count as a hit. Lookup tries the exact
start day, then each earlier day through this many; the newest hit wins.
Writes always use the current start day, and the older entry keeps its own
TTL. ~0~ requires the exact day. The round summary counts these inside ~X hits~
and, when any were used, adds ~(Y across days)~. Must be >= 0.

** team_cover_refresh_max_calls

How many calls an unscoped ~scan~ may spend refetching stored path history
closest to expiry. The calls count toward ~team_cover_max_calls~. A scoped
run (~dispatch~, ~gate~, ~scan --repo~, ~scan --in-scope~, or one pull
request) refetches nothing. Must be >= 1.

** team_cover_max_calls

Caps team-cover's GitHub calls in one round: history, search and REST calls,
retries included. Round-cache hits make no call and do not count. A history
request is not sent unless a call is left for its pull requests' reviews. At
the cap the remaining paths and teams wait for the next round, and the cache
fills over several rounds; a PR whose history is incomplete gets no
~team_review_suggestions~ that round. The round output and the warnings name
the step that was cut short and what it left: ~team-cover: call cap 40 reached during history; 120 paths deferred~,
or ~during team members; 12 teams deferred~; other steps (~reviews~,
~files~, ~codeowners~, ~activity~, ~load~) count deferred PRs. Must be >= 1.

The cap goes to the PRs that need it most. Before any call, the round
cache's review snapshots and team members sort the PRs into three tiers.
First come PRs with a requested team that nobody covers, not counting
~team_cover_skip_teams~: the most uncovered teams first, then the newest
PR, then listed order. Next come PRs the cache cannot classify, and last
the covered ones, each in listed order. Path history follows the same
order, so a path an earlier tier needs is fetched first and a shared path
once. The early history refresh still comes last. ~team_review_suggestions~
stay in the listed PR order.

** team_cover_load_ttl

Go duration. How long a login's open-direct-request count (the ~load~
signal) is reused across rounds, from the round cache. ~0~ searches every
round. Must be >= 0.

** team_cover_members_ttl

Go duration. How long a team's member list is reused across rounds, from the
round cache. A failed lookup is not stored. ~0~ fetches it every round. Must
be >= 0.

** team_cover_codeowners_ttl

Go duration. How long a repository's CODEOWNERS (per base branch) is reused
across rounds, from the round cache. ~0~ fetches it every round. Must be >= 0.
