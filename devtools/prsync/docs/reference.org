#+TITLE: prsync reference

The short guide is [[file:../README.org][the prsync README]].

* Commands

#+BEGIN_EXAMPLE
prsync scan     [--config PATH] [--repo owner/repo ...] [--json] [--in-scope] [--emit-jobs] [--tab-machine M] [--untabbed include|exclude] [--skip JOB ...]
prsync tabs     --orphans [--config PATH] [--json] [--stdin] [--close-merged] [--go] [--force] [--tab-machine M]
prsync dispatch [--config PATH] [--pr owner/repo#N ...] [--all] [--go] [--rebase] [--merge] [--ci-fix] [--hint TEXT] [--prompt-suffix TEXT] [--force] [--stdin] [--open-tabs] [--parallel N] [--job ID] [--runner NAME] [--tab-machine M] [--untabbed include|exclude] [--skip JOB ...]
prsync loop     [--config PATH] [--max-rounds N] [--pause D] [--parallel N] [--dry-run] [--ensure]
prsync maintain [--config PATH] [--pr owner/repo#N ...] [--json] [--force] [--stdin]
prsync ledger   [--config PATH] [--pr owner/repo#N] [--kind KIND] [--head SHA] [--limit N] [--json]
prsync comment  [--config PATH] [--pr owner/repo#N ...] [--all] [--go] [--stdin] [--allow-duplicate] [--repost-waives] [--body TEXT]
prsync gate     [--config PATH] [--tab-machine M]
prsync logs     [--path]
prsync version  [--json]
prsync update   [--check] [--ref REF] [--json]
prsync doctor   [--config PATH] [--json] [--offline]
prsync skill    [install|uninstall|status] [--agent A] [--scope S] [--dir D] [--dry-run] [--force] [--json]
#+END_EXAMPLE

| Flag | Commands | Effect |
|------+----------+--------|
| ~--log-level LEVEL~ | all except ~logs~ | ~debug~ / ~info~ / ~warn~ / ~error~. Default ~info~. Also ~PRSYNC_LOG~. JSONL under =$XDG_STATE_HOME/prsync/=; stdout is unchanged |
| ~--config PATH~ | scan, tabs, dispatch, loop, maintain, ledger, comment, gate, doctor | Use this file (must exist) |
| ~--repo owner/repo~ | scan | Repeatable; replaces ~repos~ entirely |
| ~--json~ | scan, tabs | Accepted no-op (stdout is always JSON) |
| ~--in-scope~ | scan | Leave PRs marked ~out_of_scope~ out of the output. Overrides ~scan_in_scope_only~. See [[file:multi-machine.org::*One watcher per machine][One watcher per machine]] |
| ~--orphans~ | tabs | Required; report live-agent tabs with no open/draft PR |
| ~--close-merged~ | tabs | Close ~merged~-bucket orphan tabs (default is dry-run) |
| ~--pr owner/repo#N~ | dispatch, comment | Repeatable. ~dispatch~ fetches only these PRs; ~comment~ limits candidates in the scan |
| ~--all~ | dispatch, comment | Every PR in the scan document (default when no ~--pr~) |
| ~--go~ | dispatch, comment, tabs | Live send / close (default is dry-run) |
| ~--rebase~ | dispatch | Rebase-in-place prompt (push with ~--force-with-lease~); skips the unaddressed-comment gate. Refused when the prompt suffix asks for a merge or no force-push (see [[*dispatch][dispatch]]) |
| ~--merge~ | dispatch | Merge catch-up prompt: merge ~origin/{base}~ and push normally; skips the unaddressed-comment gate. Mutually exclusive with ~--rebase~ |
| ~--ci-fix~ | dispatch | CI-fix prompt; skips the unaddressed-comment gate. Mutually exclusive with ~--rebase~ and ~--merge~ |
| ~--hint TEXT~ | dispatch | Non-authoritative CI failure hint (requires ~--ci-fix~). The agent must verify it |
| ~--prompt-suffix TEXT~ | dispatch | Append TEXT after a blank line to every prompt. Overrides ~dispatch_prompt_suffix~ for this run |
| ~--force~ | dispatch, tabs | dispatch: re-dispatch even if dedupe would skip. tabs: allow ~--close-merged~ when every orphan is ~no_pr~ or ~unknown~ |
| ~--stdin~ | tabs, dispatch, comment | Read a scan document from a pipe or redirected file. Absent a document: tabs self-resolve; comment and bare dispatch self-scan; ~dispatch --pr~ fetches those PRs |
| ~--body TEXT~ | comment | Comment body to post (required unless ~--repost-waives~ is set) |
| ~--allow-duplicate~ | comment | Post even if the same ~(repo, number, head_sha, body)~ was already recorded |
| ~--repost-waives~ | comment | Re-post byte-identical waive comments for ~base-only~ stale waives when waived checks fail (requires ~waive_repost=true~ and non-empty ~waive_checks~) |
| ~--path~ | logs | Print the run-log file path as JSON instead of dumping the file |
| ~--tab-machine M~ | scan, dispatch, tabs, gate | Scope the run to PRs whose tab is on ~M~: ~local~ or one of ~machines~. ~gate~ (and dispatch's gate) then checks ~M~'s checkout and agents. Overrides ~tab_machine~. See [[file:multi-machine.org::*One watcher per machine][One watcher per machine]] |
| ~--untabbed include~ / ~exclude~ | scan, dispatch | Whether PRs with no tab belong to this run. Overrides ~untabbed~ |
| ~--skip JOB~ | scan, dispatch | Repeatable. Skip a machine-wide job this run (~team-cover~). Overrides ~skip_jobs~ |
| ~--emit-jobs~ | scan | Write agentbus job specs instead of the scan document. See [[file:jobs.org::*scan --emit-jobs][scan --emit-jobs]] |
| ~--job ID~ | dispatch | Run one agentbus job, live, and report it with ~agentbus jobs done~ or ~fail~. See [[file:jobs.org::*dispatch --job][dispatch --job]] |
| ~--runner NAME~ | dispatch | The job's runner for the report (requires ~--job~). Default =$JOB_RUNNER= |
| ~--open-tabs~ | dispatch | Open a herdr tab and start an agent for an in-scope PR with no tab. Overrides ~open_missing_tabs~. See [[file:multi-machine.org::*Opening tabs for untabbed PRs][Opening tabs for untabbed PRs]] |
| ~--parallel N~ | dispatch, loop | Run up to ~N~ PR dispatches concurrently (~>= 1~). Values ~> 1~ require ~gate_lease=required~. Overrides ~dispatch_max_parallel~ |
| ~--max-rounds N~ | loop | Stop cleanly after ~N~ scan+dispatch rounds (~0~ runs until ~SIGTERM~/~SIGINT~) |
| ~--pause D~ | loop | Go duration to wait between rounds (default ~0~ starts the next scan immediately) |
| ~--dry-run~ | loop | Run rounds in dry-run mode without sending prompts (by default ~loop~ runs live) |
| ~--ensure~ | loop | Idempotent watchdog check: exit 0 if heartbeat is fresh (~<= 10m~) and PID alive, else start ~loop~ detached |

Usage errors (exit 2): ~--pr~ with ~--all~; any two of ~--rebase~,
~--merge~, and ~--ci-fix~; ~--rebase~ with a prompt suffix that asks for
a merge or no force-push (~--force~ does not bypass it);
~--hint~ without ~--ci-fix~; ~--go~ on ~tabs~ without ~--close-merged~;
a ~--tab-machine~ that is neither ~local~ nor in ~machines~; an
~--untabbed~ other than ~include~ or ~exclude~; an unknown ~--skip~ job;
~--job~ with ~--pr~, ~--all~, a prompt-mode flag, ~--hint~, ~--force~,
~--stdin~, or ~--parallel~; ~--runner~ without ~--job~; ~--parallel < 1~;
~--parallel > 1~ without ~gate_lease=required~; negative ~--max-rounds~ or
~--pause~; neither ~--body~ nor
~--repost-waives~ on ~comment~; ~--repost-waives~ with ~--body~ or
~--allow-duplicate~.

~--go~ always sends (or, with ~--close-merged~, closes). ~dry_run=false~
in the config also sends / closes without ~--go~ (for cron); ~tabs~
still needs ~--close-merged~ to close anything.

~--stdin~ reads a scan document only from a FIFO or regular file (a
pipe or redirected file). Sockets, TTYs, and other non-file stdin are
ignored so they cannot hang. Decode errors are fatal. Without a
stdin document, ~comment~ always self-scans. ~dispatch~ self-scans for
~--all~ and when no ~--pr~ is given. A scan lists open PRs without
~statusCheckRollup~ or ~latestReviews~, then loads each rollup with its
own ~gh pr view~. The list request also asks for ~state~, a scalar on
each pull request already loaded, so that adds no GraphQL node.
~dispatch --pr~ fetches each named PR with one ~gh pr view~ that
includes ~state~ and the rollup fields, loads review threads for
those PRs only, and matches herdr tabs as a full scan does.

#+BEGIN_SRC bash
prsync scan --config ./prsync.config | prsync dispatch --stdin --config ./prsync.config
prsync scan --config ./prsync.config | prsync comment --stdin --body "please retry" --config ./prsync.config
#+END_SRC

* Configuration

Search order (first existing file wins):

1. ~--config PATH~ (missing file → exit 2)
2. ~./prsync.config~ (cwd; honors ~BUILD_WORKING_DIRECTORY~ under ~bazel run~)
3. =$HOME/.config/prsync/prsync.config=

If none exist, built-in defaults are used. That is not an error.

The file is ~KEY=VALUE~, one assignment per line. Blank lines and ~#~
comment lines are ignored. Inline comments (~key=value # comment~) are
not supported. Unknown keys are ignored. The parser does not ~source~
the file.

~*_ms~ keys are integers in milliseconds (~2000~ is 2s, not 2µs).
~true~ / ~false~ / ~1~ / ~0~ are accepted for booleans. ~state_file~,
~gh_bin~, ~herdr_bin~, ~jira_bin~, and ~@/path~ values (prompt templates,
~comment_strip_patterns~, and ~team_cover_exclude_logins~) expand a leading tilde.
Environment variables are not expanded.

| ~waive_authors~                 | empty                                                                                                                                                                                                                                        | Space-separated GitHub logins (matched case-insensitively) whose waive comments count. Empty means any author.                                                   |
| ~waive_checks~                  | empty                                                                                                                                                                                                                                        | Comma-separated CheckRun names or StatusContext contexts a waive may cover. Re-posting requires a non-empty list.                                                |
| ~waive_repost~                  | ~false~                                                                                                                                                                                                                                      | Allow ~prsync comment --repost-waives~ to re-post for ~base-only~ heads. ~author changes~ is never re-posted.                                                    |
| ~waive_max_per_pr~              | ~3~                                                                                                                                                                                                                                          | Maximum automated waive re-posts per PR (counted from ~waive-repost~ ledger entries; ~0~ disables re-posting).                                                   |

Default prompt text (checkout ~{head}~, mechanical vs judgment-call
triage, reply on every thread and resolve unless that reply asks the
reviewer a follow-up, re-request reviewers unless ~dispatch_rerequest=off~, catch-up / rebase / CI-fix wording) is
commented in [[file:../prsync.config.example][prsync.config.example]].

** Running gh through a rate limiter

prsync runs every GitHub call through the ~gh_bin~ executable. To send
them through the client-side limiter ~gh-throttle~ (or any wrapper that
accepts ~gh~'s arguments), set either:

- ~gh_bin=gh-throttle~ in the config file, or
- ~GH_BIN=gh-throttle~ in the environment. The ~gh-nudge~ tools read the
  same variable, so one export covers both.

~gh_bin~ wins over ~GH_BIN~, which wins over the default ~gh~.

prsync makes no GitHub writes in parallel. ~team_cover~ only reports
suggested reviewers (and the ~gh pr edit --add-reviewer~ line to run);
it never adds them. The only parallel calls are reads: up to 4
per-PR status-check views at a time during a scan.

When ~waive_comment_prefix~ is set, ~scan~ also checks each in-scope
open PR for stale CI waives. A PR head transition from ~old_head~ to
~new_head~ classifies as ~base-only~ only when ~old_head~ is an
ancestor of ~new_head~, no force-push happened after the waive comment,
every commit on the first-parent chain ~old_head..new_head~ is a
two-parent merge whose second parent is an ancestor of the base branch,
and ~git diff <old merge-base>..<old_head>~ equals
~git diff <new merge-base>..<new_head>~ byte-for-byte. Conflict edits,
author commits after a base merge, non-base merges, and rebases /
force-pushes classify as ~author changes~. Classification runs in a
local checkout when available (matched local agent cwd, current
working directory, or ~open_tabs_cwd~) and falls back to GitHub's
compare API. ~scan~ prints one line per stale waive on stderr
(~<repo>#<number> stale waive: old=<old_head> new=<new_head> class=<class> failing=<checks>~)
in addition to ~stale_waive~ in JSON. Nothing is posted or written to
state or ledger.

** tabs --orphans

Inverse of ~scan~: walk *this machine's* herdr tabs and flag those with
a live agent (~working~ / ~idle~ / ~blocked~) but no open or draft PR.
Usually the PR already merged — the tab, worktree, and gate slot can
be reclaimed.

Tabs whose labels yield tickets via ~title_id_pattern~ are resolved to
the author's PRs (any state) and bucketed. A label that is exactly
~#~ plus a pull request number (~#42~, not ~#1#2~ or ~#42 extra~)
is resolved instead to that number in the github.com repository of the
live agent's cwd (~git remote get-url origin~, then ~foreground_cwd~ if
the shell cwd is not a GitHub checkout). That lookup is not limited to
~author~, so a review tab for someone else's PR is included. ~--close-merged~
closes it when the pull request is merged or closed, and re-checks with
~gh pr view~ immediately before the close.

| Bucket | Meaning |
|--------+---------|
| ~merged~ | Matching PR (ticket, or ~#N~) is merged or closed → *safe to close*. ~pr~ has number, repo, ~state~, ~merged_at~ (null if closed but unmerged) |
| ~no_pr~ | No matching PR, agent is ~idle~ or ~blocked~ → *verify* (may be unpushed WIP, or ~#N~ is not a pull request in that repo). A ~working~ agent with no PR is omitted, not an orphan |
| ~unknown~ | No chunk in the sweep matched a ticket, and more than one ticket was searched (broken or throttled sweep, not N genuine ~no_pr~). An empty chunk is ~no_pr~ when another chunk mapped a PR. A ~warnings~ entry is emitted; ~working~ agents are still surfaced |

Skipped: tabs with an open/draft PR, agent-less scratch tabs, unparseable / non-ticket labels. A ~#N~ tab whose cwd is not a github.com checkout is skipped with a warning, not closed. A ~gh pr view~ error for one ~#N~ tab warns and skips that tab; it does not mark the sweep ~unknown~.

prsync tabs --orphans --config ./prsync.config
#+END_SRC

Live ~action~ values: ~closed~, ~skipped_not_merged~,
~skipped_not_found~. Dry-run emits ~would_close~. A row counts as
delivered only when ~action~ is ~closed~, ~ticket~ is set, and
~pr.merged_at~ is set.

Every close document includes ~unblock~, including a refused close.
Dry-run, a refused close, and a ~--go~ round with no ~closed~ row set
~status~ to ~not_run~ (~text~ and ~lines~ empty) and do not call Jira.
After ~--go~ closes at least one tab, ~status~ is ~ok~ or ~failed~.
~ok~ with no lines has text ~nothing newly unblocked~. With lines, ~text~
starts with ~Newly unblocked by this round~ and then one line per
ticket: a ticket clear to start, or a ticket still blocked by an open
issue. ~failed~ text is ~unblock check could not run: …~, ~lines~ stays
empty, and the close exit code is unchanged.

(exit 3), since tabs are the whole input — unlike ~scan~, which
degrades.

** dispatch

Dry-run (default). ~--pr~ fetches only those PRs instead of scanning
every open PR. ~--all~ and a bare ~dispatch~ still self-scan. When a
stdin document is present, it is used as given. Review ~rendered_prompt~
and confirm ~pane_id~ is a pane (~w2:pC~), not a tab id (~w2:tC~):

#+BEGIN_SRC bash
prsync dispatch --config ./prsync.config
prsync dispatch --config ./prsync.config --pr acme/widgets#123
#+END_SRC

#+BEGIN_SRC json
{
  "generated_at": "2026-01-01T09:00:00Z",
  "dry_run": true,
  "results": [
    {
      "repo": "acme/widgets",
      "number": 123,
      "action": "would_dispatch",
      "kind": "comment",
      "pane_id": "w2:pC",
      "rendered_prompt": "Get onto this PR's branch before editing: ... Address the unresolved review comments on PR #123 ... State: open."
    }
  ]
}
#+END_SRC

Live send (~--go~) writes ~state_file~ on ~dispatched~ /
~dispatched_timeout~, and when a later evaluation of the same
unaddressed comment ids is still inside the dedupe window. That later
run does not send. Its action is ~dispatched_unresolved~ and ~detail~
includes the recorded time. ~prsync scan~ sets ~dispatch~ to that same
marker. The window is ~dedupe_ttl~ (default 24h) or ~dedupe_scans~
later evaluations, whichever comes first. ~dedupe_scans~ of 0 does not
expire by count. A new unaddressed comment id is a fresh dispatch.
~--force~ re-dispatches immediately. When the window expires, dispatch
sends again and refreshes ~dispatched_at~ and the scan count. Gate /
serial / parallel / wait: [[file:gate.org::*Live dispatch][Live dispatch]] and [[file:gate.org::*Parallel dispatch][Parallel dispatch]]. When ~dispatch_max_parallel > 1~,
the JSON document also includes ~summary~ (~max_in_flight~, ~in_flight~,
~finished~, ~timed_out~, ~blocked~, plus non-zero ~failed~, ~queued~,
~skipped~); with ~--parallel 1~ (the default), output and behavior are
unchanged and ~summary~ is omitted. The prompt always goes to the PR's existing herdr
tab (no new worktree). A scan ~merge-queue-fix~ action, with none of
~--rebase~, ~--merge~, or ~--ci-fix~, sends that prompt instead and skips the
unaddressed-comment gate. The prompt points at the RCA comment URL and
asks the tab to fix the cause. When the ejection is a merge conflict,
it asks for a rebase, regenerated lockfiles, and a push; with
~dispatch_catchup = "merge"~ it asks to merge ~origin/{base}~ and push
normally instead. The same head is not prompted again until the head
changes.

Each result has a ~kind~: ~comment~, ~rebase~, ~merge~, ~ci-fix~, or
~merge-queue-fix~, the prompt the pull request gets.

| Mode | Flag | Done when | Notes |
|------+------+-----------+-------|
| comments (default) | (none) | listed threads addressed | Dedupe on unaddressed comment ids until ~dedupe_ttl~ or ~dedupe_scans~, whichever comes first. While the window holds the action is ~dispatched_unresolved~ (not ~skipped_deduped~) and ~detail~ includes the recorded time. ~scan~ shows that marker on the pull request. |
| rebase | ~--rebase~ | recorded ~dispatched_head_sha~ equals the current head, and merge state is not ~BEHIND~, ~DIRTY~, or ~UNKNOWN~, and ~mergeable~ is not ~CONFLICTING~ | A new head is a fresh decision. ~BEHIND~, ~DIRTY~, ~UNKNOWN~, and ~mergeable~ ~CONFLICTING~ retry even when the recorded sha matches. ~--all~ sends to every PR with a ready tab (auto-picking behind PRs is a follow-up). Missing ~merge_state_status~ keeps head-SHA dedupe. ~skipped_deduped~ sets ~detail~ to ~recorded at <sha>, merge_state=<status>~ |
| merge | ~--merge~ | recorded ~dispatched_merge_sha~ equals the current head, and merge state is not ~BEHIND~, ~DIRTY~, or ~UNKNOWN~, and ~mergeable~ is not ~CONFLICTING~ | Same rule as rebase, with its own recorded field, so a rebase on the same head does not dedupe a merge. Also the conflict-only use: catch up or fix conflicts without the comment gate. ~skipped_deduped~ sets ~detail~ to ~recorded at <sha>, merge_state=<status>~ |
| CI-fix | ~--ci-fix~ | recorded ~dispatched_ci_fix_sha~ equals the current head, and ~ci_state~ is not ~failing~ | A new head is a fresh decision, including ~pending~, ~none~, and ~green~. A still-red check retries on the same head. ~--hint~ is a starting point the agent must verify; omit it to investigate from scratch. Caller chooses ~--ci-fix~ — ~prsync~ does not triage. Missing ~ci_state~ keeps head-SHA dedupe. ~skipped_deduped~ sets ~detail~ to ~recorded at <sha>, ci_state=<status>~ |
| merge-queue-fix | (none; scan action ~merge-queue-fix~) | recorded ~dispatched_merge_queue_fix_sha~ equals the current head | Same draft, tab, agent, and busy gate as the other modes. Skips the unaddressed-comment gate. Not prompted again until the head changes, including when the pull request is still conflicting. ~--rebase~, ~--merge~, and ~--ci-fix~ keep their own prompts. ~--force~ re-dispatches. ~skipped_deduped~ sets ~detail~ to ~recorded at <sha>~ |

Cannot combine ~--rebase~, ~--merge~, and ~--ci-fix~; catch up first,
then CI-fix. If
you also re-trigger CI, do that last (a new commit invalidates it).
~--force~ re-dispatches even when dedupe would skip. A rebase or CI-fix
recorded for this head, once the PR is no longer in a needs-work state,
is ~skipped_deduped~ and ~detail~ says which sha and status were recorded.

With ~--rebase~, ~dispatch~ refuses (exit 2) a prompt suffix
(~--prompt-suffix~ or ~dispatch_prompt_suffix~) that contradicts the
rebase prompt, rather than send two conflicting instructions. The
phrases, matched case-insensitively as whole words, are ~merge~, ~push
normally~, ~no force~, ~do not force-push~, ~do not force push~, ~don't
force-push~, and ~don't force push~. Use ~--merge~ (or
~dispatch_catchup = "merge"~ for built-in catch-up preambles and merge-queue-fix conflicts) instead.
~--force~ does not bypass this check. The list is ~rebaseSuffixPhrases~
in ~internal/dispatch/prompt.go~.

#+BEGIN_SRC bash
prsync dispatch --config ./prsync.config --rebase --pr acme/widgets#123 --go
prsync dispatch --config ./prsync.config --ci-fix --pr acme/widgets#123 \
  --hint 'job X failed at step/target Y; key error: boom; looks real (not flake)'
prsync dispatch --config ./prsync.config --ci-fix --pr acme/widgets#123 --go --force
#+END_SRC

** comment

Posts a PR comment through ~gh pr comment~. No herdr tab, no agent, no
gate — a ~tab~ of ~null~ is not a skip, so this works for off-machine
PRs. Dry-run by default. ~--body~ is posted as-is. JSON matches the
~dispatch~ result shape (~would_dispatch~ / ~dispatched~ /
~skipped_not_found~ / ~skipped_deduped~), with the body in
~rendered_prompt~.

Live send (~--go~) records ~state_file~ on ~dispatched~, keyed on
~(repo, number, head_sha, body)~. The same tuple is ~skipped_deduped~
(including dry-run). A new ~head_sha~ allows the same body again.
~--allow-duplicate~ posts anyway. Comment state does not clobber
dispatch comment-id / rebase / CI-fix fields.

#+BEGIN_SRC bash
prsync comment --config ./prsync.config --pr acme/widgets#123 --body "please retry"
prsync comment --config ./prsync.config --pr acme/widgets#123 --body "please retry" --go
# same head SHA + body: skipped_deduped
prsync comment --config ./prsync.config --pr acme/widgets#123 --body "please retry" --go
prsync comment --config ./prsync.config --pr acme/widgets#123 --body "please retry" --go --allow-duplicate
prsync comment --config ./prsync.config --all --body "please retry"
#+END_SRC

#+BEGIN_SRC json
{
  "generated_at": "2026-01-01T09:00:00Z",
  "dry_run": true,
  "results": [
    {
      "repo": "acme/widgets",
      "number": 123,
      "action": "would_dispatch",
      "rendered_prompt": "please retry"
    }
  ]
}
#+END_SRC

With ~--repost-waives~, ~comment~ inspects ~stale_waive~ on each
in-scope candidate PR (self-scanning unless ~--stdin~ supplies a scan
document):

- Re-posting is off by default (~waive_repost=false~) and also requires
  non-empty ~waive_comment_prefix~ and ~waive_checks~. Otherwise each
  candidate becomes ~skipped_waive_disabled~.
- ~author changes~ is never re-posted (~skipped_author_changes~), so a
  human decides.
- Only ~base-only~ stale waives where at least one check in
  ~waive_checks~ is currently failing are eligible
  (~skipped_no_failing_waived_checks~ otherwise).
- Dry-run (default) writes what would be posted and where to stderr
  (~would post to <repo>#<number> (...):~ followed by the body) and
  keeps the byte-for-byte ~comment_body~ in ~rendered_prompt~ without
  calling ~gh~ or writing state or ledger files.
- Live send (~--go~, or ~dry_run=false~) posts a byte-for-byte copy of
  ~comment_body~ through ~gh pr comment~, deduplicates per head via both
  ~dispatch_ledger_file~ and ~state_file~ so restarts never repost on
  the same head (~skipped_deduped~), caps re-posts per PR at
  ~waive_max_per_pr~ (~skipped_waive_cap~), and appends a
  ~waive-repost~ entry to ~dispatch_ledger_file~ with the PR,
  ~old_head_sha~, ~new_head_sha~, and ~comment_id~. Query recorded
  re-posts with ~prsync ledger --kind waive-repost~.

** logs

Each run (except ~logs~ itself) appends JSON lines to
=$XDG_STATE_HOME/prsync/prsync.jsonl= (or
=~/.local/state/prsync/prsync.jsonl=). Rotates by size (~10 MiB~) and
age (~14 days~). Default level ~info~; stdout JSON is unchanged.
~--log-level~ overrides ~PRSYNC_LOG~.

A dispatch line of investigation includes the target pane, send, each
~agent_status~ transition, gate wait, settle decision, skip/dedupe
outcome, and process exit. Startup records the resolved config path
and ~concurrency_wait_on~.

#+BEGIN_SRC bash
prsync logs --path
prsync logs
#+END_SRC

~--path~ prints ~{"path":"…"}~. Without it, ~logs~ dumps the JSONL file
(empty stdout if no log exists yet).

** loop

Runs ~scan~ followed by ~dispatch~ round after round (~--pause~,
default ~0~, starts the next round right after the previous finishes).
Unless ~--dry-run~ is passed, rounds dispatch live.

#+BEGIN_SRC bash
prsync loop --config ./prsync.config --parallel 3
prsync loop --config ./prsync.config --max-rounds 5 --pause 10s
prsync loop --ensure --config ./prsync.config
#+END_SRC

Each completed round writes one JSON line (~RoundResult~) to stdout:

#+BEGIN_SRC json
{"round":1,"started_at":"2026-01-01T09:00:00Z","ended_at":"2026-01-01T09:00:02Z","scanned":2,"dispatch":{"generated_at":"2026-01-01T09:00:02Z","dry_run":false,"results":[...]}}
#+END_SRC

- *Locking* — holds an exclusive advisory ~flock~ on ~loop.lock~ (or
  ~loop-<hash>.lock~ when scoped to a config file) in the state
  directory (~filepath.Dir(state_file)~). A second loop for the same
  config refuses to start (~exit 3~).
- *Shutdown* — on ~SIGTERM~ or ~SIGINT~, the active round runs to
  completion, the heartbeat file is removed, the lock is released, and
  ~prsync loop~ exits ~0~.
- *Heartbeat* — writes ~loop.heartbeat.json~ (or
  ~loop-<hash>.heartbeat.json~) atomically every ~30s~ and on round
  boundaries with ~pid~, ~config_path~, ~round~, ~state~ (~starting~,
  ~running~, ~idle~, ~sleeping~), ~started_at~, ~updated_at~,
  ~last_round_start~, and ~last_round_end~.
- *Watchdog (~--ensure~)* — cheap, idempotent check intended for an
  hourly timer or cron. When the heartbeat is at most ~10m~ old and its
  ~pid~ is alive, ~--ensure~ exits ~0~ immediately. Otherwise it launches
  ~prsync loop~ detached in a new session, forwarding ~--config~,
  ~--max-rounds~, ~--pause~, ~--parallel~, ~--dry-run~, and ~--log-level~.

Example systemd, launchd, and crontab definitions live in
[[file:../contrib/README.org][contrib/]].

** doctor

Runs built-in environment diagnostics (~gh~, ~git~, ~herdr~, plus
~loop~):

#+BEGIN_SRC bash
prsync doctor --config ./prsync.config
prsync doctor --config ./prsync.config --json --offline
#+END_SRC

The ~loop~ check inspects the heartbeat for ~--config~ (or any
~loop*.heartbeat.json~ in the state directory when ~--config~ is omitted)
and reports one of three states: ~running~ (~ok~), ~stale heartbeat~
(~warn~ with hint to run ~prsync loop --ensure~), or ~not running~ (~ok~).
