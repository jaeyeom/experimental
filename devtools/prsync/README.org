#+TITLE: prsync
#+DATE: 2026-09-10

* Overview

~prsync~ lists your open pull requests and matches each one to a
[[https://herdr.dev/][herdr]] tab. Herdr is a terminal multiplexer that runs coding agents.
Each PR title must carry a ticket ID (for example ~PROJ-123~) that
equals that tab's label. A dry run prints JSON until you pass ~--go~.

You need ~gh~ logged in (~gh auth login~), herdr 0.8 or later on
~PATH~, and those ticket IDs in the titles. ~prsync~ never reads a
GitHub token. Posting a comment does not need herdr.

* Quick start

#+begin_src bash
go install github.com/jaeyeom/experimental/devtools/prsync/cmd/prsync@latest
cp prsync.config.example ./prsync.config
prsync scan --config ./prsync.config
#+end_src

A matched pull request looks like this. Other fields are in the
[[file:docs/reference.org][reference]].

#+begin_src json
{
  "prs": [
    {
      "repo": "acme/widgets",
      "number": 123,
      "title": "[PROJ-123] Fix the widget",
      "identifier": "PROJ-123",
      "bucket": "needs_you",
      "tab": {"tab_id": "w2:tC", "pane_id": "w2:pC", "label": "PROJ-123"}
    }
  ]
}
#+end_src

~bucket~ ~needs_you~ means reviewers still need a reply from you.
~pane_id~ (~w2:pC~) is the agent pane and ~tab_id~ (~w2:tC~) is the
tab. A prompt is pasted into the pane. ~rendered_prompt~ is the text
a dry run would send.

#+begin_src bash
prsync dispatch --config ./prsync.config --pr acme/widgets#123
prsync dispatch --config ./prsync.config --pr acme/widgets#123 --go
#+end_src

The first command changes nothing. ~--go~ sends that prompt.

* How matching works

The default ~title_id_pattern~ is ~[A-Z]+-[0-9]+~. In
~[PROJ-123] Fix the widget~ the identifier is ~PROJ-123~. The default
~tab_label_template~ is ~{id}~, so the herdr tab label must be exactly
~PROJ-123~.

A label that is only ~#42~ matches pull request 42 in the GitHub
repository of that agent's checkout. ~tab~ is JSON ~null~ when nothing
matches. The usual cause is a title with no ticket ID, or a tab whose
label is not that ID.

* Concepts

- *bucket* — ~needs_you~ (your reply), ~ready~ (can merge), ~waiting~ (reviewers or CI), or ~draft~.
- *gate* — whether another agent is busy in this checkout. A *busy signal* is why: working, a background job, a build tool, a decide question, or a workdir lease.
- *dedupe* — the same review comments are not sent again until ~dedupe_ttl~ (24h) or a new comment appears. ~--force~ sends anyway.
- *dry run and --go* — the default prints the plan. ~--go~ sends, posts, or closes.
- *pane id and tab id* — ~w2:pC~ is the pane. ~w2:tC~ is the tab. Prompts go to the pane.
- *orphan tab* — a live agent whose pull request is gone, usually merged. ~tabs --orphans~ lists them.
- *round cache* — GitHub answers kept so the next scan can skip calls that cannot have changed. Deleting the file is safe.

[[file:../agentbus/README.org][agentbus]] holds the workdir lease and wakes a hibernated agent.
[[file:../decide/README.org][decide]] is the question list the gate reads.
[[file:../gh-nudge/README.org][gh-nudge]] reminds reviewers. prsync does not.

* Everyday workflows

Reply to review comments. Read the dry run, then send:

#+begin_src bash
prsync dispatch --config ./prsync.config --pr acme/widgets#123
prsync dispatch --config ./prsync.config --pr acme/widgets#123 --go
#+end_src

Ask the agent to rebase (and force-push), to merge the base branch (and
push normally), or to fix red CI. ~--hint~ is a guess the agent must
check. ~--rebase~, ~--merge~, and ~--ci-fix~ do not combine:

#+begin_src bash
prsync dispatch --config ./prsync.config --rebase --pr acme/widgets#123 --go
prsync dispatch --config ./prsync.config --merge --pr acme/widgets#123 --go
prsync dispatch --config ./prsync.config --ci-fix --hint 'job X failed: boom' --pr acme/widgets#123 --go
#+end_src

Post a conversation comment. No herdr tab is required:

#+begin_src bash
prsync comment --config ./prsync.config --pr acme/widgets#123 --body "please retry"
prsync comment --config ./prsync.config --pr acme/widgets#123 --body "please retry" --go
#+end_src

Close tabs for merged pull requests. Without ~--go~ this only prints.
~--go~ closes the merged bucket, then reports Jira tickets that this
round unblocked:

#+begin_src bash
prsync tabs --orphans --close-merged --config ./prsync.config
prsync tabs --orphans --close-merged --go --config ./prsync.config
#+end_src

* Commands

The global flag ~--log-level~ is ~debug~, ~info~, ~warn~, or ~error~
(default ~info~, also ~PRSYNC_LOG~). Every command except ~logs~ takes
it. Stdout stays JSON.

#+begin_example
prsync scan     [--config PATH] [--repo owner/repo ...] [--json] [--in-scope] [--emit-jobs] [--tab-machine M] [--untabbed include|exclude] [--skip JOB ...]
prsync tabs     --orphans [--config PATH] [--json] [--stdin] [--close-merged] [--go] [--force] [--tab-machine M]
prsync dispatch [--config PATH] [--pr owner/repo#N ...] [--all] [--go] [--rebase] [--merge] [--ci-fix] [--hint TEXT] [--prompt-suffix TEXT] [--force] [--stdin] [--open-tabs] [--job ID] [--runner NAME] [--tab-machine M] [--untabbed include|exclude] [--skip JOB ...]
prsync comment  [--config PATH] [--pr owner/repo#N ...] [--all] [--go] [--stdin] [--allow-duplicate] --body TEXT
prsync gate     [--config PATH] [--tab-machine M]
prsync logs     [--path]
prsync version  [--json]
prsync update   [--check] [--ref REF] [--json]
prsync doctor   [--json] [--offline]
prsync skill    [install|uninstall|status] [--agent A] [--scope S] [--dir D] [--dry-run] [--force] [--json]
#+end_example

| Flag                | Effect                                                                          |
|---------------------+---------------------------------------------------------------------------------|
| ~--go~              | Send, post, or close. Without it, the command only prints.                      |
| ~--config PATH~     | Use this config file. It must exist.                                            |
| ~--pr owner/repo#N~ | One pull request. Repeat the flag for more than one.                            |
| ~--force~           | Send again even when dedupe would skip, or close when classification is unsure. |
| ~--open-tabs~       | Open a herdr tab for an in-scope PR that does not have one.                     |
| ~--log-level LEVEL~ | Global log verbosity. ~logs~ does not take it.                                  |

Common flags only. The full list is in the [[file:docs/reference.org][reference]].

* Configuration

Search order: ~--config~, then ~./prsync.config~, then
=~$HOME/.config/prsync/prsync.config=. Copy
[[file:prsync.config.example][prsync.config.example]] and edit it. Lines
are ~KEY=VALUE~. A ~#~ starts a comment. Unknown keys are ignored.

| Key                        | Default         | Notes                                                       |
|----------------------------+-----------------+-------------------------------------------------------------|
| ~repos~                    | empty           | Space-separated ~owner/repo~. Empty discovers open PRs.     |
| ~author~                   | empty           | GitHub login. Empty asks ~gh~ for the current user.         |
| ~title_id_pattern~         | ~[A-Z]+-[0-9]+~ | First match in the PR title is the ticket ID.               |
| ~tab_label_template~       | ~{id}~          | Tab label after substituting ~{id}~. The match is exact.    |
| ~dry_run~                  | ~true~          | Without ~--go~, commands only print. ~false~ is for cron.   |
| ~dispatch_prompt_template~ | built-in        | Review-comment prompt, or ~@/path~ to a file.               |
| ~dispatch_ask_instruction~ | route-neutral   | Text substituted for ~{ask}~ in the review-thread prompt.   |
| ~dispatch_ask_to~          | empty           | Name substituted for ~{ask_to}~ in the ask instruction.    |
| ~dispatch_park_mode~       | ~off~           | ~on~: a review job parks design threads and asks ~dispatch_ask_to~. |
| ~rebase_prompt_template~   | built-in        | Prompt used with ~dispatch --rebase~.                       |
| ~merge_prompt_template~    | built-in        | Prompt used with ~dispatch --merge~.                        |
| ~dispatch_catchup~         | ~rebase~        | ~merge~: merge-queue-fix conflicts merge, not rebase.       |
| ~ci_fix_prompt_template~   | built-in        | Prompt used with ~dispatch --ci-fix~.                       |
| ~ci_ignore_checks~         | empty           | Check names left out of ~ci_state~.                         |
| ~ci_only_checks~           | empty           | When set, only these checks feed ~ci_state~.                |
| ~dedupe_ttl~               | ~24h~           | How long the same comments stay deduped.                    |
| ~dedupe_scans~             | ~0~             | Later scans that also expire dedupe. ~0~ ignores the count. |

Every other key is in the [[file:docs/reference.org][reference]].

For example, a team using an agent manager can set
~dispatch_ask_to=review-manager~ and
~dispatch_ask_instruction=send the question with a recommended option to {ask_to} over the message bus; never wait silently in your own screen~.
Custom dispatch prompt templates can use ~{ask}~ and ~{ask_to}~ too.

With ~dispatch_park_mode=on~ as well, a review job (~dispatch --job~)
does not wait in its tab for a design answer: the agent pushes the
mechanical threads, asks ~review-manager~ over the agent bus, and parks
the design threads until it replies. A manager's reply resumes the
work; it is never the user's approval. See
[[file:docs/jobs.org::*Park mode][Park mode]].

* Exit codes

| Code | Meaning                                                                         |
|------+---------------------------------------------------------------------------------|
| 0    | Success.                                                                        |
| 1    | ~gate~ is busy or the checkout is dirty. ~dispatch --go~ reports ~gate_unsafe~. |
| 2    | Usage, config, or flag error.                                                   |
| 3    | Missing tool, auth failure, herdr too old, or a dispatch failure.               |
| 4    | Live dispatch timed out waiting on the gate or on settle.                       |

* Security

- ~prsync~ never calls ~gh auth token~ and never prints the environment. Auth is the ~gh~ login you already have, plus the local herdr socket.
- ~comment --go~ posts the body as a GitHub comment. Dry-run first.
- ~tabs --orphans --close-merged --go~ closes tabs that are still in the merged bucket. ~no_pr~ and ~unknown~ tabs are not closed unless you also pass ~--force~ on an all-~no_pr~ or ~unknown~ result.
- After a live close, ~jira issue view~ runs read-only. A failed check does not change the close result, and it does not mark a ticket as free to start.
- Review text is pasted into the prompt. prsync does not run it. The agent might follow whatever the review says.
- The config file is not sourced as shell.
- JSON on stdout can contain review bodies and logins.
- Two live dispatches on one ~state_file~ over NFS are not supported.
