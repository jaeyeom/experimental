#+TITLE: prsync
#+DATE: 2026-09-10

* Overview

~prsync~ is a JSON CLI that surveys *your* open GitHub PRs, matches each
to a local [[https://herdr.dev/][herdr]] agent tab, and — when you ask — sends that agent a
prompt or posts a GitHub comment.

| Command | What it does |
|---------+--------------|
| ~scan~ | List open PRs (including drafts), bucket which still need you, match each to a herdr tab |
| ~dispatch~ | Send that tab a prompt: review comments (default), rebase (~--rebase~), or red CI (~--ci-fix~) |
| ~comment~ | Post a conversation-level PR comment via ~gh~ (no herdr tab, no gate) |
| ~tabs --orphans~ | Flag live-agent tabs whose PR already merged; ~--close-merged --go~ closes them |
| ~gate~ | One-shot "is an agent busy?" |
| ~logs~ / ~version~ | Dump the run log / print version |

Dry-run by default (~--go~ actually sends or closes). Uses the
already-authenticated ~gh~ CLI and herdr ≥ 0.8. After a live close, the
unblock check runs ~jira issue view~ (read-only). Never embeds a GitHub
token. Dispatch is one agent at a time. All commands emit JSON on
stdout.

Typical loop:

#+BEGIN_SRC bash
prsync scan --config ./prsync.config
prsync dispatch --config ./prsync.config          # review rendered_prompt
prsync dispatch --config ./prsync.config --go     # send
prsync tabs --orphans --close-merged --config ./prsync.config
prsync tabs --orphans --close-merged --go --config ./prsync.config
#+END_SRC

Related tracker: [[https://github.com/jaeyeom/experimental/issues/211][#211]].

* Installation

#+BEGIN_SRC bash
go install github.com/jaeyeom/experimental/devtools/prsync/cmd/prsync@latest
#+END_SRC

Or with Bazel from this repo:

#+BEGIN_SRC bash
bazel run //devtools/prsync/cmd/prsync -- version
#+END_SRC

After ~go install~, put ~$GOPATH/bin~ / ~$GOBIN~ on ~PATH~.

* Prerequisites

- ~gh~ authenticated (~gh auth login~). ~prsync~ never calls ~gh auth token~.
- herdr ≥ 0.8 on ~PATH~ for matching and dispatch:
  - missing: ~scan~ degrades (tabs unset); ~dispatch~ and ~gate~ exit 3;
    ~comment~ still runs
  - present but older than 0.8, or unparseable ~herdr --version~: every
    command that would talk to herdr (including ~scan~) exits 3
  - ~comment --stdin~ never talks to herdr
- ~jira~ on ~PATH~ (or ~jira_bin~) for the post-close unblock check.
  A missing binary or a failed ~jira issue view~ fails that check only;
  the close exit code stays the same. The check does not transition,
  comment, or assign.
- ~team_cover~ lists team members with ~GET /orgs/{org}/teams/{slug}/members~,
  which needs the ~read:org~ scope. Without it, that team gets an ~error~
  and the scan continues.
- Linux or macOS. No Windows requirement.

Optional: copy [[file:prsync.config.example][prsync.config.example]] to ~./prsync.config~ or
=$HOME/.config/prsync/prsync.config= and edit.

* Commands

#+BEGIN_EXAMPLE
prsync scan     [--config PATH] [--repo owner/repo ...] [--json] [--in-scope] [--tab-machine M] [--untabbed include|exclude] [--skip JOB ...]
prsync tabs     --orphans [--config PATH] [--json] [--stdin] [--close-merged] [--go] [--force] [--tab-machine M]
prsync dispatch [--config PATH] [--pr owner/repo#N ...] [--all] [--go] [--rebase] [--ci-fix] [--hint TEXT] [--prompt-suffix TEXT] [--force] [--stdin] [--tab-machine M] [--untabbed include|exclude] [--skip JOB ...]
prsync comment  [--config PATH] [--pr owner/repo#N ...] [--all] [--go] [--stdin] [--allow-duplicate] --body TEXT
prsync gate     [--config PATH]
prsync logs     [--path]
prsync version
#+END_EXAMPLE

| ~--orphans~ | tabs | Required; report live-agent tabs with no open/draft PR |
| ~--close-merged~ | tabs | Close ~merged~-bucket orphan tabs (default is dry-run) |
| ~--pr owner/repo#N~ | dispatch, comment | Repeatable. ~dispatch~ fetches only these PRs; ~comment~ limits candidates in the scan |
| ~--all~ | dispatch, comment | Every PR in the scan document (default when no ~--pr~) |
| ~--go~ | dispatch, comment, tabs | Live send / close (default is dry-run) |
| ~--rebase~ | dispatch | Rebase-in-place prompt; skips the unaddressed-comment gate |
| ~--ci-fix~ | dispatch | CI-fix prompt; skips the unaddressed-comment gate. Mutually exclusive with ~--rebase~ |
| ~--hint TEXT~ | dispatch | Non-authoritative CI failure hint (requires ~--ci-fix~). The agent must verify it |
| ~--prompt-suffix TEXT~ | dispatch | Append TEXT after a blank line to every prompt. Overrides ~dispatch_prompt_suffix~ for this run |
| ~--force~ | dispatch, tabs | dispatch: re-dispatch even if dedupe would skip. tabs: allow ~--close-merged~ when every orphan is ~no_pr~ or ~unknown~ |
| ~--stdin~ | tabs, dispatch, comment | Read a scan document from a pipe or redirected file. Absent a document: tabs self-resolve; comment and bare dispatch self-scan; ~dispatch --pr~ fetches those PRs |
| ~--body TEXT~ | comment | Comment body to post (required) |
| ~--allow-duplicate~ | comment | Post even if the same ~(repo, number, head_sha, body)~ was already recorded |
| ~--path~ | logs | Print the run-log file path as JSON instead of dumping the file |
| ~--tab-machine M~ | scan, dispatch, tabs, gate | Scope the run to PRs whose tab is on ~M~: ~local~ or one of ~machines~. ~gate~ (and dispatch's gate) then checks ~M~'s checkout and agents. Overrides ~tab_machine~. See [[*One watcher per machine][One watcher per machine]] |
| ~--untabbed include~ / ~exclude~ | scan, dispatch | Whether PRs with no tab belong to this run. Overrides ~untabbed~ |
| ~--skip JOB~ | scan, dispatch | Repeatable. Skip a machine-wide job this run (~team-cover~). Overrides ~skip_jobs~ |

Usage errors (exit 2): ~--pr~ with ~--all~; ~--ci-fix~ with ~--rebase~;
~--hint~ without ~--ci-fix~; ~--go~ on ~tabs~ without ~--close-merged~;
a ~--tab-machine~ that is neither ~local~ nor in ~machines~; an
~--untabbed~ other than ~include~ or ~exclude~; an unknown ~--skip~ job.

~--go~ always sends (or, with ~--close-merged~, closes). ~dry_run=false~
in the config also sends / closes without ~--go~ (for cron); ~tabs~
still needs ~--close-merged~ to close anything.

~--stdin~ reads a scan document only from a FIFO or regular file (a
pipe or redirected file). Sockets, TTYs, and other non-file stdin are
ignored so they cannot hang. Decode errors are fatal. Without a
stdin document, ~comment~ always self-scans. ~dispatch~ self-scans for
~--all~ and when no ~--pr~ is given. A scan lists open PRs without
~statusCheckRollup~ or ~latestReviews~, then loads each rollup with its
own ~gh pr view~. The list request also asks for ~state~, a scalar on
each pull request already loaded, so that adds no GraphQL node.
~dispatch --pr~ fetches each named PR with one ~gh pr view~ that
includes ~state~ and the rollup fields, loads review threads for
those PRs only, and matches herdr tabs as a full scan does.

#+BEGIN_SRC bash
prsync scan --config ./prsync.config | prsync dispatch --stdin --config ./prsync.config
prsync scan --config ./prsync.config | prsync comment --stdin --body "please retry" --config ./prsync.config
#+END_SRC

* Configuration

Search order (first existing file wins):

1. ~--config PATH~ (missing file → exit 2)
2. ~./prsync.config~ (cwd; honors ~BUILD_WORKING_DIRECTORY~ under ~bazel run~)
3. =$HOME/.config/prsync/prsync.config=

If none exist, built-in defaults are used. That is not an error.

The file is ~KEY=VALUE~, one assignment per line. Blank lines and ~#~
comment lines are ignored. Inline comments (~key=value # comment~) are
not supported. Unknown keys are ignored. The parser does not ~source~
the file.

~*_ms~ keys are integers in milliseconds (~2000~ is 2s, not 2µs).
~true~ / ~false~ / ~1~ / ~0~ are accepted for booleans. ~state_file~,
~gh_bin~, ~herdr_bin~, ~jira_bin~, and ~@/path~ values (prompt templates,
~comment_strip_patterns~, and ~team_cover_exclude_logins~) expand a leading tilde.
Environment variables are not expanded.

** Live dispatch

~dispatch --go~ does three things, one PR at a time:

1. *Gate* — wait until no waited-on agent is ~working~ and no
   [[*Busy signals][busy signal]] holds (a background job, a build in
   the checkout, or an open decide question). A ~blocked~
   agent holds the gate too, unless ~concurrency_ignore_blocked~ is
   ~true~. A single idle sample is not enough (startup / mid-run flap
   still counts as busy). When a ~blocked~ tab does hold the gate,
   stderr names it, e.g. ~waiting on w2:tC — blocked awaiting your
   input~. If it still holds at ~gate_timeout_ms~, the current PR is
   ~gate_timeout~ and the rest are ~queued~ (exit 4, no prompt, no
   state write). A dirty dispatch checkout (see [[*gate][gate]]) does not
   wait: the current PR is ~gate_unsafe~ with the reason as ~detail~,
   the rest are ~queued~ (exit 1, no prompt, no state write). A dry run
   puts the same reason on each ~would_dispatch~ row.
2. *Send* — first, with ~wake_before_prompt=auto~ (the default),
   ~agentbus wake --if-hibernated --wait --machine <machine> <pane_id>~
   (~local~ for a local tab). A prompt typed into a hibernated pane
   would land in its shell, so a hibernated agent is relaunched and
   ready before the prompt; the result then has ~"woke": true~, and
   the run log a ~wake~ line and ~woke=true~ on the ~result~ line.
   When ~agentbus~ is not installed the prompt is sent as before. When
   the wake fails the PR is ~failed~ with ~detail~ ~wake before prompt:
   <error>~ and no prompt is sent. A hibernated tab is idle to the
   gate: nothing runs in its pane. Then
   ~herdr agent prompt <pane_id> <prompt> --wait --until idle
   --until done --timeout …~ (tokens from ~dispatch_wait_until~). From
   a non-~working~ pane, herdr must observe ~working~ or ~blocked~
   within five seconds (~agent_prompt_stalled~ otherwise). Pre-send
   ~idle~/~done~ does not complete the wait.
3. *Settle* — debounce-poll ~agent list~ until ~idle~/~done~ holds for
   several consecutive samples. A transient ~idle~ after you answer a
   ~blocked~ question is not completion. If the tab is still
   ~working~/~blocked~, continue with ~herdr agent wait~ using remaining
   ~dispatch_timeout_ms~. ~agent wait~ is never started from a *stable*
   ~idle~/~done~.

If the agent never picks up the prompt, or a wait expires while the tab
is still ~working~/~blocked~, the result is ~dispatched_timeout~ (exit
4; state is written so it is not retried blindly).
~dispatched_blocked~ happens only when ~blocked~ is in
~dispatch_wait_until~ *and* that status holds for the settle debounce:
the batch stops, but dedupe state is not written, so a re-run can
retry. Set ~dispatch_wait_until=idle~ only if you want to wait until
herdr reports ~idle~ (can take ~30 minutes if the agent settles to
~done~ instead).

~prsync gate~ is the same busy-set check without debounce — a snapshot,
not the wait ~dispatch --go~ uses.

prsync claims nothing; the dispatched agent claims. For a checkout
guarded by an agentbus workdir lease (see [[*Workdir lease][Workdir
lease]]), the gate only reads the lease, and after a successful
dispatch prsync does not run ~agentbus lease claim~. The agent it
prompted claims the lease before it changes the checkout, and releases
it when done.

** Other herdr machines

With ~machines=linux2~, ~scan~ lists tabs and agents on the local server
and on each machine (~herdr --machine linux2 tab list~ / ~agent list~),
and matches each PR over the combined list. A PR whose tab is only on
~linux2~ is matched like a local one, and its ~tab~ has
~"machine": "linux2"~. A local tab has no ~machine~ field, so output is
unchanged when ~machines~ is unset. A tab is keyed as ~<tab_id>@<machine>~
in warnings and in the ~managed~ gate set, so the same tab id on two
machines is two tabs. The same label on two machines is ambiguous: a
warning, ~tab~ is ~null~, and dispatch skips it with ~skipped_no_tab~.

~dispatch~ sends to a remote tab with ~herdr --machine <m> agent
prompt~, and runs the settle polls and ~agent wait~ there too. Its
result row has ~machine~. The gate watches the agents on each machine
too; see [[*Remote tabs][Remote tabs]].

Each call to a machine, other than prompt and wait, has a
~machine_timeout_ms~ deadline that kills the whole process group, since
SSH behind ~herdr --machine~ can hang on a locked key instead of
failing. A machine that fails or times out adds one warning and does
not fail the scan:

#+BEGIN_EXAMPLE
machine linux2 unreachable (host unreachable); its tabs were not searched
machine linux2 unreachable (authentication locked (unlock your SSH/gpg agent)); its tabs were not searched
#+END_EXAMPLE

~host unreachable~ means the call failed with a network error or
~herdr machine status linux2 --json~ did not report the host reachable.
~authentication locked~ means the host answered but the call hit an
authentication error or the deadline. Any other herdr error is quoted
instead.

While a machine is unreachable, a PR with an identifier that matches no
tab on any machine that was searched gets ~"tab_unknown": "machine
unreachable"~ instead of the no-tab warning: its tab may be on the
machine that was not searched. ~dispatch~ skips it with
~skipped_tab_unknown~ this run. A PR that does match a tab on a
reachable machine is matched as usual; prsync does not hold it back on
the chance that the unreachable machine has a duplicate.

** Running gh through a rate limiter

prsync runs every GitHub call through the ~gh_bin~ executable. To send
them through the client-side limiter ~gh-throttle~ (or any wrapper that
accepts ~gh~'s arguments), set either:

- ~gh_bin=gh-throttle~ in the config file, or
- ~GH_BIN=gh-throttle~ in the environment. The ~gh-nudge~ tools read the
  same variable, so one export covers both.

~gh_bin~ wins over ~GH_BIN~, which wins over the default ~gh~.

prsync makes no GitHub writes in parallel. ~team_cover~ only reports
suggested reviewers (and the ~gh pr edit --add-reviewer~ line to run);
it never adds them. The only parallel calls are reads: up to 4
per-PR status-check views at a time during a scan.

** Round cache

GitHub also caps GraphQL CPU time per user, so prsync keeps its large
queries small and skips calls whose answer cannot have changed since the
last round. Results are kept in ~round-cache.json~, next to
~state_file~: status checks for an hour, path history for at most a day.
The file is only a cache: deleting it is safe, and a corrupt one is
ignored with a warning in the run log.

- *Status checks.* The open-PR search returns each PR's ~headRefOid~ and
  ~updatedAt~. When both match the last round and every check had
  finished, the scan reuses the stored checks instead of running the
  per-PR status-check view. A pending or empty rollup is never stored,
  because a check can finish without changing ~updatedAt~.
- *Team-cover history.* Each path's history is stored per repository,
  base branch, and base branch head commit. Each round looks up the head
  of each base branch once (~GET repos/{owner}/{repo}/git/ref/heads/{base}~);
  while it has not moved, the stored history is reused and no history
  query runs. Paths that miss are fetched in one batched query per
  repository and base. The run log records ~team-cover cache~ with
  ~hits~ and ~misses~. If the head lookup fails, history is fetched on the
  branch and not stored.

~dispatch --pr~ has no search to compare against and always views each
PR. Page sizes: the open-PR search loads 50 PRs per
page; review requests and latest reviews load 20 per PR. A connection
cut off at those sizes is logged as a warning (~github connection
truncated~) in the run log.

** One watcher per machine

Every run searches the local server and all ~machines~, so two watchers
would both pick up a PR whose tab is on ~linux2~. ~--tab-machine~ (or
~tab_machine~) splits the work: each watcher handles only the PRs whose
tab is on its machine.

#+BEGIN_EXAMPLE
watcher A: prsync dispatch --tab-machine local  --untabbed include
watcher B: prsync dispatch --tab-machine linux2 --untabbed exclude --skip team-cover
#+END_EXAMPLE

Matching stays global: both watchers list tabs on every machine, so they
agree on duplicates and on which machine owns a PR. Scoping happens after
matching:

| PR | Belongs to |
|----+------------|
| Matched tab on ~M~ | the ~M~ run |
| No tab on any machine | the ~local~ run, unless ~--untabbed~ says otherwise. Set it so exactly one watcher includes these |
| ~tab_unknown~ because ~M~ is unreachable | the ~M~ run, reported as today |
| Same label on two machines | both runs: each reports the ambiguous-tab warning, and neither dispatches it |

~scan~ lists every PR on every machine. A PR owned by another run stays
in its output with ~out_of_scope~ (~tab on local~, ~no tab~, or ~tab may
be on linux2 (unreachable)~), and its per-PR warnings are dropped. When
any PR is marked, stderr says how many, e.g. ~2 out of scope
(tab_machine=linux2)~. A caller that reads ~.tab~ must skip the marked
PRs too: pass ~--in-scope~ (or ~scan_in_scope_only = true~) to leave them
out, or filter them yourself:

#+BEGIN_EXAMPLE
prsync scan --tab-machine linux2 --in-scope
prsync scan --tab-machine linux2 | jq '.prs[] | select(.out_of_scope == null)'
#+END_EXAMPLE

With ~--in-scope~, ~summary~ counts only the PRs that remain. ~dispatch~ skips it with
~skipped_out_of_scope~ and that reason as ~detail~. A ~dispatch --stdin~
document keeps the scope it was scanned with, so pipe ~scan~ with the
same ~--tab-machine~.

~tabs --orphans~ (and ~--close-merged~) looks only at tabs on
~--tab-machine~; the version check still runs on the local ~herdr~.
Without it, ~tabs~ stays local, so each machine's own watcher closes its
tabs.

Machine-wide jobs are not tied to one PR's tab, so both watchers would
run them. Skip them in all but one watcher with ~--skip~ (~skip_jobs~):

| Job | What it skips |
|-----+---------------|
| ~team-cover~ | The ~team_cover~ reviewer suggestions and their GitHub calls, even when ~team_cover=true~ |

Nudging is a separate tool (~gh-nudge~); run it next to the watcher
without ~--skip~.

Both watchers can share one ~state_file~. A scoped live dispatch holds
~<state_file>.<machine>.lock~ for the run instead of
~<state_file>.lock~, and writes each entry by re-reading the file under
~<state_file>.lock~, so neither run drops the other's entries. An
unscoped dispatch, ~comment~, and a scoped run's write all take
~<state_file>.lock~, so do not mix an unscoped watcher with scoped ones
on one state file: a scoped write waits about 5 s for the lock and then
fails.

*** Gating on another machine

~prsync gate --tab-machine M~ and the built-in gate of ~dispatch
--tab-machine M~ (or ~tab_machine = M~) check ~M~'s checkout, not the
local one. Name it in ~machine_checkouts~:

#+BEGIN_EXAMPLE
machines=linux2
machine_checkouts=linux2=/home/me/src/repo
#+END_EXAMPLE

Without an entry for ~M~ the gate fails with a config error (exit 2)
naming ~machine_checkouts~; it never falls back to the local path.
~--tab-machine local~ and an unscoped run keep the local gate.

| Check | On ~M~ |
|-------+--------|
| Lease | ~agentbus lease status --all --json~, the entry whose ~checkout~ is ~M:<path>~. A missing entry is an unguarded checkout; ~gate_lease~ keeps its meaning |
| Busy signals | ~working~, ~blocked~, ~background-job~, and ~pending-question~ from ~herdr --machine M~, with ~concurrency_cwd = checkout~ matched against ~M~'s paths. The local session is not read |
| Dirty tree, ~build-tool~ | Skipped: ~herdr --machine~ runs only herdr API calls. The JSON has the note ~checkout not inspected on M~ |
| ~M~ unreachable | Unsafe (exit 1) with ~reason~ ~machine M unreachable~; a live dispatch reports ~gate_unsafe~ at once |

The gate JSON adds ~machine~ and ~lease_key~:

#+BEGIN_SRC json
{
  "safe": false,
  "busy": [
    {
      "machine": "linux2",
      "pane_id": "",
      "tab_id": "",
      "agent_status": "",
      "checkout": "/home/me/src/repo",
      "signal": "lease",
      "detail": "held by pm/foo until 14:20"
    }
  ],
  "machine": "linux2",
  "lease_key": "linux2:/home/me/src/repo",
  "notes": [
    "checkout not inspected on linux2"
  ]
}
#+END_SRC

| ~team_review_suggestions~ | Omitted when ~team_cover~ is off, on a round ~team_cover_every~ skips, or when every requested team was skipped. ~team_cover~ is off by default, so the JSON above has no suggestion
field. With it on, stdout stays JSON. Human-readable lines and one
ready-to-run hint per pull request go to stderr, and prsync does not
run the hint:

#+BEGIN_EXAMPLE
acme/widgets#123 org/some-team: suggest alice (codeowner: src/foo/**, 3 open direct requests)
acme/widgets#123 org/other-team: covered by bob
gh pr edit 123 --repo acme/widgets --add-reviewer alice
#+END_EXAMPLE

A team is covered when one of its members is already requested
individually or has submitted a review whose state is not ~PENDING~.
~covered_by~ prefers a requested member over a reviewer, then login
order. Suggestions skip the author, bots (~[bot]~ or user type ~Bot~),
excluded logins, people who already approved, and (when
~team_cover_active_days~ is set) members with no recent org event.
Coverage still counts those people. A person who belongs to two
uncovered teams is suggested once in the hint and listed on each team
they cover. The smallest teams are filled first. Already-picked people
are reused before the next team is ranked.

Ranking uses the configured signals, then login order: more owned
touched paths (CODEOWNERS on the base branch, last match wins, user or
a team they belong to), then more recent commits authored or reviewed
on those paths, then fewer open direct review requests
(~user-review-requested:<login>~ in the repo owner org, not
~review-requested:~). Reasons name the winning CODEOWNERS pattern, the
history counts, and the open-request count.

Missing ~read:org~, or a failed member list, sets that team's ~error~
and a stderr warning. The scan continues. A search or history rate
limit skips that signal for the rest of the run, warns, and still
suggests from the remaining signals. An events-API error skips the
activity filter instead of dropping candidates. With the feature off,
scan does not call team members, CODEOWNERS, path history, or the
review-request search. With it on, a round where no PR has a requested
team makes none of those calls either, and changed files, CODEOWNERS,
and path history are fetched only for PRs with a team no member covers.

** tabs --orphans

Inverse of ~scan~: walk *this machine's* herdr tabs and flag those with
a live agent (~working~ / ~idle~ / ~blocked~) but no open or draft PR.
Usually the PR already merged — the tab, worktree, and gate slot can
be reclaimed.

Tabs whose labels yield tickets via ~title_id_pattern~ are resolved to
the author's PRs (any state) and bucketed. A label that is exactly
~#~ plus a pull request number (~#42~, not ~#1#2~ or ~#42 extra~)
is resolved instead to that number in the github.com repository of the
live agent's cwd (~git remote get-url origin~, then ~foreground_cwd~ if
the shell cwd is not a GitHub checkout). That lookup is not limited to
~author~, so a review tab for someone else's PR is included. ~--close-merged~
closes it when the pull request is merged or closed, and re-checks with
~gh pr view~ immediately before the close.

| Bucket | Meaning |
|--------+---------|
| ~merged~ | Matching PR (ticket, or ~#N~) is merged or closed → *safe to close*. ~pr~ has number, repo, ~state~, ~merged_at~ (null if closed but unmerged) |
| ~no_pr~ | No matching PR, agent is ~idle~ or ~blocked~ → *verify* (may be unpushed WIP, or ~#N~ is not a pull request in that repo). A ~working~ agent with no PR is omitted, not an orphan |
| ~unknown~ | No chunk in the sweep matched a ticket, and more than one ticket was searched (broken or throttled sweep, not N genuine ~no_pr~). An empty chunk is ~no_pr~ when another chunk mapped a PR. A ~warnings~ entry is emitted; ~working~ agents are still surfaced |

Skipped: tabs with an open/draft PR, agent-less scratch tabs, unparseable / non-ticket labels. A ~#N~ tab whose cwd is not a github.com checkout is skipped with a warning, not closed. A ~gh pr view~ error for one ~#N~ tab warns and skips that tab; it does not mark the sweep ~unknown~.

prsync tabs --orphans --config ./prsync.config
#+END_SRC

Live ~action~ values: ~closed~, ~skipped_not_merged~,
~skipped_not_found~. Dry-run emits ~would_close~. A row counts as
delivered only when ~action~ is ~closed~, ~ticket~ is set, and
~pr.merged_at~ is set.

Every close document includes ~unblock~, including a refused close.
Dry-run, a refused close, and a ~--go~ round with no ~closed~ row set
~status~ to ~not_run~ (~text~ and ~lines~ empty) and do not call Jira.
After ~--go~ closes at least one tab, ~status~ is ~ok~ or ~failed~.
~ok~ with no lines has text ~nothing newly unblocked~. With lines, ~text~
starts with ~Newly unblocked by this round~ and then one line per
ticket: a ticket clear to start, or a ticket still blocked by an open
issue. ~failed~ text is ~unblock check could not run: …~, ~lines~ stays
empty, and the close exit code is unchanged.

(tabs that already have an open PR are skipped without a ~gh search~):

#+BEGIN_SRC bash

#+END_SRC

(exit 3), since tabs are the whole input — unlike ~scan~, which
degrades.

** dispatch

Dry-run (default). ~--pr~ fetches only those PRs instead of scanning
every open PR. ~--all~ and a bare ~dispatch~ still self-scan. When a
stdin document is present, it is used as given. Review ~rendered_prompt~
and confirm ~pane_id~ is a pane (~w2:pC~), not a tab id (~w2:tC~):

#+BEGIN_SRC bash
prsync dispatch --config ./prsync.config
prsync dispatch --config ./prsync.config --pr acme/widgets#123
#+END_SRC

#+BEGIN_SRC json
{
  "generated_at": "2026-01-01T09:00:00Z",
  "dry_run": true,
  "results": [
    {
      "repo": "acme/widgets",
      "number": 123,
      "action": "would_dispatch",
      "pane_id": "w2:pC",
      "rendered_prompt": "Get onto this PR's branch before editing: ... Address the unresolved review comments on PR #123 ... State: open."
    }
  ]
}
#+END_SRC

Live send (~--go~) writes ~state_file~ on ~dispatched~ /
~dispatched_timeout~, and when a later evaluation of the same
unaddressed comment ids is still inside the dedupe window. That later
run does not send. Its action is ~dispatched_unresolved~ and ~detail~
includes the recorded time. ~prsync scan~ sets ~dispatch~ to that same
marker. The window is ~dedupe_ttl~ (default 24h) or ~dedupe_scans~
later evaluations, whichever comes first. ~dedupe_scans~ of 0 does not
expire by count. A new unaddressed comment id is a fresh dispatch.
~--force~ re-dispatches immediately. When the window expires, dispatch
sends again and refreshes ~dispatched_at~ and the scan count. Gate /
serial / wait: [[*Live dispatch][Live dispatch]]. The prompt always goes to the PR's existing herdr
tab (no new worktree). A scan ~merge-queue-fix~ action, with neither
~--rebase~ nor ~--ci-fix~, sends that prompt instead and skips the
unaddressed-comment gate. The prompt points at the RCA comment URL and
asks the tab to fix the cause. When the ejection is a merge conflict,
it asks for a rebase, regenerated lockfiles, and a push. The same head
is not prompted again until the head changes.

| Mode | Flag | Done when | Notes |
|------+------+-----------+-------|
| comments (default) | (none) | listed threads addressed | Dedupe on unaddressed comment ids until ~dedupe_ttl~ or ~dedupe_scans~, whichever comes first. While the window holds the action is ~dispatched_unresolved~ (not ~skipped_deduped~) and ~detail~ includes the recorded time. ~scan~ shows that marker on the pull request. |
| rebase | ~--rebase~ | recorded ~dispatched_head_sha~ equals the current head, and merge state is not ~BEHIND~, ~DIRTY~, or ~UNKNOWN~, and ~mergeable~ is not ~CONFLICTING~ | A new head is a fresh decision. ~BEHIND~, ~DIRTY~, ~UNKNOWN~, and ~mergeable~ ~CONFLICTING~ retry even when the recorded sha matches. ~--all~ sends to every PR with a ready tab (auto-picking behind PRs is a follow-up). Missing ~merge_state_status~ keeps head-SHA dedupe. ~skipped_deduped~ sets ~detail~ to ~recorded at <sha>, merge_state=<status>~ |
| CI-fix | ~--ci-fix~ | recorded ~dispatched_ci_fix_sha~ equals the current head, and ~ci_state~ is not ~failing~ | A new head is a fresh decision, including ~pending~, ~none~, and ~green~. A still-red check retries on the same head. ~--hint~ is a starting point the agent must verify; omit it to investigate from scratch. Caller chooses ~--ci-fix~ — ~prsync~ does not triage. Missing ~ci_state~ keeps head-SHA dedupe. ~skipped_deduped~ sets ~detail~ to ~recorded at <sha>, ci_state=<status>~ |
| merge-queue-fix | (none; scan action ~merge-queue-fix~) | recorded ~dispatched_merge_queue_fix_sha~ equals the current head | Same draft, tab, agent, and busy gate as the other modes. Skips the unaddressed-comment gate. Not prompted again until the head changes, including when the pull request is still conflicting. ~--rebase~ and ~--ci-fix~ keep their own prompts. ~--force~ re-dispatches. ~skipped_deduped~ sets ~detail~ to ~recorded at <sha>~ |

Cannot combine ~--rebase~ and ~--ci-fix~; rebase first, then CI-fix. If
you also re-trigger CI, do that last (a new commit invalidates it).
~--force~ re-dispatches even when dedupe would skip. A rebase or CI-fix
recorded for this head, once the PR is no longer in a needs-work state,
is ~skipped_deduped~ and ~detail~ says which sha and status were recorded.

#+BEGIN_SRC bash
prsync dispatch --config ./prsync.config --rebase --pr acme/widgets#123 --go
prsync dispatch --config ./prsync.config --ci-fix --pr acme/widgets#123 \
  --hint 'job X failed at step/target Y; key error: boom; looks real (not flake)'
prsync dispatch --config ./prsync.config --ci-fix --pr acme/widgets#123 --go --force
#+END_SRC

gate — a ~tab~ of ~null~ is not a skip, so this works for off-machine
PRs. Dry-run by default. ~--body~ is posted as-is. JSON matches the
~dispatch~ result shape (~would_dispatch~ / ~dispatched~ /
~skipped_not_found~ / ~skipped_deduped~), with the body in
~rendered_prompt~.

** gate

One-shot busy-set check (no debounce). ~dispatch --go~ uses the
debounced wait described under [[*Live dispatch][Live dispatch]].

#+BEGIN_SRC bash
prsync gate --config ./prsync.config
#+END_SRC

Safe:

#+BEGIN_SRC json
{
  "safe": true,
  "busy": []
}
#+END_SRC

Unsafe (exit 1) when a working or blocked agent is in the busy set. A
blocked agent is left out only when ~concurrency_ignore_blocked~ is
~true~; exempt tabs are left out even when blocked.
~agent_status~ distinguishes ~working~ (making progress) from ~blocked~
(awaiting human input):

#+BEGIN_SRC json
{
  "safe": false,
  "busy": [
    {
      "pane_id": "w2:pC",
      "tab_id": "w2:tC",
      "agent_status": "blocked",
      "signal": "blocked",
      "detail": "blocked awaiting input"
    }
  ]
}
#+END_SRC

Each busy entry has ~signal~, the reason it holds the gate (see
[[*Busy signals][Busy signals]]), and ~detail~ for the signals below.

*** Busy signals

A waited-on tab whose herdr status is ~working~ holds the gate with
signal ~working~. One that is ~blocked~ holds it with signal ~blocked~
and ~detail~ ~blocked awaiting input~, whether or not it has a decide
item and whether or not ~decide~ is installed, unless
~concurrency_ignore_blocked~ is ~true~.

herdr reports some agents ~idle~ or ~done~ while work keeps running
for them. The gate also holds a waited-on tab, whatever its status,
for the first of these that is true:

1. ~background-job~ — the tab's foreground agent (from ~herdr pane
   process-info~) has a child process that matches none of
   ~gate_ignore_procs~ and is at least ~gate_job_min_age~ old (10s by
   default), such as a background shell or build. Inside the
   ~dispatch --go~ wait loop the same pid must also be seen in the
   previous sample; a one-shot ~prsync gate~ applies the age check
   alone. So short-lived helpers an agent reruns on each UI refresh,
   such as a status-line command, never count. The processes and their
   start times come from =/proc= on Linux and ~ps~ elsewhere. ~detail~
   is ~pid 4242 (2m13s) sh -c "bazel build ..."~, with the process age.
2. ~pending-question~ — a decide item (~decide list --json~) with the
   tab's pane as ~notifyPane~ is either answered but not done (the
   agent is about to resume), with ~detail~ ~answered item D-17~, or
   open and created after the round started (the ~dispatch~ run or the
   ~gate~ check), with ~detail~ ~open item D-17~. An open item from
   before the round is parked and does not hold the gate.
   ~gate_pending_question=off~ turns it off. When ~decide~ is not
   installed, the gate warns once and checks the other signals.

These two signals hold only a tab that can touch the dispatch checkout.
When the checkout is known (see the dirty-tree check below), a tab
whose ~cwd~ and ~foreground_cwd~ are both outside it is not held by a
pending question, and is held by a background job only when that
child's own cwd is inside the checkout. So a design tab working in
another repository does not hold the gate for its long-lived helper.
Each skip is logged at debug level as ~gate_signal_out_of_checkout~,
with no output entry. ~working~ and ~blocked~ still hold a tab
anywhere, as ~concurrency_cwd=any~ says. With no known checkout, both
signals apply to every waited-on tab. A remote tab follows the same
rule with its paths on that machine: its ~cwd~ from ~agent list~ and
the child's ~cwd~ from ~pane process-info~.

A tab whose pane id matches ~gate_exempt_panes~, or whose label
matches ~gate_exempt_tabs~, is skipped by every tab signal, including
~working~ and ~blocked~, the same way as the runner pane. It is listed under
~exempt~ with the rule that matched:

#+BEGIN_SRC json
"exempt": [
  {"pane_id": "w3:p2", "tab_id": "w3:t2", "label": "pm", "rule": "gate_exempt_tabs=pm*"}
]
#+END_SRC

Each child skipped by a ~gate_ignore_procs~ pattern is listed under
~ignored~, and logged at debug level as ~gate_ignored~, so you can
check that a pattern works:

#+BEGIN_SRC json
"ignored": [
  {"pane": "w3:p2", "pid": 4242, "command": "/bin/sh -c \"claude-hud --x\"", "pattern": "claude-hud"}
]
#+END_SRC

*** Workdir lease

When the dispatch checkout is guarded by an agentbus workdir lease
(listed in agentbus ~lease_checkouts~), the lease, not the tabs,
decides who may change it. The gate first asks ~agentbus lease status
--guarded --json --path <checkout>~, which answers from the local
agentbus config without contacting the daemon or hub, once per ~gate~
check or ~dispatch --go~ wait. An unguarded checkout makes no lease
call, and the tab signals above apply as before.

For a guarded checkout the gate reads ~agentbus lease status --path
<checkout> --json~ on each sample. The checkout holds the gate with
signal ~lease~ unless the state is ~free~, and the tab signals
(~working~, ~blocked~, ~background-job~, ~build-tool~,
~pending-question~, and the remote-tab holds) are not checked. The
~detail~ names the holder and the bid's end, in local time:

| state | ~detail~ |
|-------+----------|
| ~held~ | ~held by pm/foo until 14:20~ (the holder's name, else its handle) |
| ~paused~ | ~paused by user~ |
| ~needs-adopt~ | ~needs-adopt by pm/foo~ |
| ~releasing~ | ~releasing by pm/foo~ |

#+BEGIN_SRC json
{
  "safe": false,
  "busy": [
    {
      "pane_id": "",
      "tab_id": "",
      "agent_status": "",
      "checkout": "/src/repo",
      "signal": "lease",
      "detail": "held by pm/foo until 14:20"
    }
  ]
}
#+END_SRC

The dirty-tree check still applies. When ~agentbus~ is not installed,
or ~lease status~ fails (the hub is unreachable, say), ~gate_lease=auto~
falls back to the tab signals and lists ~lease~ under
~signal_unavailable~ with the ~checkout~ and the error, logged once as
~gate_lease_unavailable~. With ~gate_lease=required~ the checkout
holds the gate instead, with ~detail~ ~cannot read the lease: <error>~,
and the tab signals are checked too. ~gate_lease=off~ never runs
agentbus.

*** Process patterns

~gate_ignore_procs~ and ~gate_build_tool_ignore~ are comma-separated
lists; whitespace around each entry is trimmed, so a pattern cannot
contain a comma. Each pattern is checked against three fields: the
process name, the base of ~argv[0]~, and the full command line (~argv~
joined with spaces).

- A plain pattern (no ~*~, ~?~, or ~[~) matches when it appears
  anywhere in one of the fields: ~claude-hud~ matches
  ~/bin/sh -c "bash -c 'cols=80; claude-hud'"~.
- A pattern with ~*~, ~?~, or ~[...]~ is a glob that may match
  anywhere in a field: ~*~ is any run of characters (including ~/~),
  ~?~ one character, and ~[...]~ a class (~[!...]~ negated).
  ~claude-hu?~ and ~*claude-hud*~ both match the command above.

Setting ~gate_ignore_procs~ replaces the default list; it does not
add to it. The defaults (also printed by ~prsync gate --help~) are:

#+BEGIN_EXAMPLE
gate_ignore_procs = caffeinate,gopls,rust-analyzer,clangd,pyright*,*language-server*,*langserver*,*mcp-server*,*mcp_server*,*modelcontextprotocol*,*-mcp,*-mcp *,statusline,status-line,claude-hud,claude-http-,*UNIX-LISTEN:*claude-*.sock*
#+END_EXAMPLE

~claude-http-~ and ~*UNIX-LISTEN:*claude-*.sock*~ cover the ~socat~
bridges Claude Code's sandbox runs for the whole session, such as
~socat UNIX-LISTEN:/tmp/claude/claude-http-<hex>.sock,fork,reuseaddr TCP:localhost:<port>~.

To add a helper, copy that line into your config and append your
pattern, then run ~prsync gate~: the process should appear under
~ignored~ with your pattern.

~build-tool~ holds the dispatch checkout rather than a tab: a
build-tool client from ~gate_build_tools~, anywhere on the machine,
whose cwd is the checkout or under it, even when its tab is exempt.
Long-lived build servers (any process with ~--workspace_directory=~,
~A-server.jar~, or ~--server~ in its ~argv~) never count, through
~gate_build_tool_ignore~; while a build runs, its client is alive. This
process and its ancestors never count, so a ~make~ that runs ~prsync~
does not block itself. The entry has ~checkout~ instead of a tab:

#+BEGIN_SRC json
{
  "safe": false,
  "busy": [
    {
      "pane_id": "w3:p2",
      "tab_id": "w3:t2",
      "agent_status": "idle",
      "signal": "background-job",
      "detail": "pid 4242 (2m13s) sh -c \"bazel build //...\""
    },
    {
      "pane_id": "",
      "tab_id": "",
      "agent_status": "",
      "checkout": "/src/repo",
      "signal": "build-tool",
      "detail": "pid 5000 bazel build //... (cwd /src/repo)"
    }
  ]
}
#+END_SRC

A signal the gate cannot evaluate (for example ~herdr pane
process-info~ or ~decide~ fails) is listed under ~signal_unavailable~
with ~tab_id~, ~pane_id~ (or ~checkout~), ~signal~, and ~error~. For a
local tab it does not make the gate unsafe; a remote tab is held (see
[[*Remote tabs][Remote tabs]]).

~dispatch --go~ waits on these signals like ~working~, with the same
debounce and ~gate_timeout_ms~; a timeout's ~detail~ names the last
signal. Each change in the holds is logged as one ~gate_hold~ line, for
example ~gate: busy tab w3:t2 (pane w3:p2): background-job pid 4242 (2m13s) sh
-c "bazel build ..."~, or ~gate: busy checkout /src/repo: build-tool
...~ for the checkout.

The gate is also unsafe (exit 1) when the dispatch checkout is dirty,
in every ~concurrency_cwd~ mode. The checkout is the git toplevel of
the current directory when its origin is a configured repo (for
~dispatch~, the repo being dispatched); if there is none, the check is
skipped. ~reason~ is one of ~dirty tree: rebase in progress~, ~dirty
tree: merge in progress~, or ~dirty tree: N files~ (staged or unstaged
tracked paths; untracked files do not count). A clean tree omits
~reason~:

#+BEGIN_SRC json
{
  "safe": false,
  "busy": [],
  "reason": "dirty tree: 2 files"
}
#+END_SRC

Self-exclusion uses ~HERDR_PANE_ID~ only. If that env var is empty,
~gate~ does not call ~herdr pane current~ (that would drop the focused
pane under cron).

*** Remote tabs

With ~machines~ set, the gate also reads ~herdr --machine <m> agent
list~ on each machine, with the same ~machine_timeout_ms~ deadline as
~scan~. A run scoped with ~--tab-machine local~ reads no other
machine; in ~managed~ mode a machine is read only when a matched tab
is on it. Local agents are read except when ~--tab-machine~ names
another machine; that gate reads only that machine against its
~machine_checkouts~ path (see [[*Gating on another machine][Gating on another machine]]). A
remote entry in ~busy~, ~exempt~, ~ignored~, and ~signal_unavailable~
has ~machine~, and its tab is named ~<tab_id>@<machine>~ in log and
wait lines.

- ~working~ and ~blocked~ hold the gate as they do locally, with
  ~concurrency_ignore_blocked~ and the exemptions applied the same way.
  ~gate_exempt_tabs~ reads that machine's tab labels.
- ~background-job~ reads ~herdr --machine <m> pane process-info~. The
  agent's children are the other processes in its pane's foreground
  process group; their age is unknown, so ~gate_job_min_age~ does not
  skip them, but the two-sample rule in the wait loop still applies.
  ~detail~ has no age: ~pid 4242 sh -c "bazel build //..."~.
- ~pending-question~ matches a decide item whose ~notifyPane~ is the
  remote handle ~herdr:<m>/<session>/<pane>~ (what agentbus sends in hub
  mode).
- ~build-tool~ and the dirty-tree check stay local: they look at the
  local dispatch checkout.

A remote tab never counts as free unseen. A machine whose agent list
fails holds the gate with a machine-level entry, logged once per cause
as ~gate_machine_unreachable~:

#+BEGIN_SRC json
{
  "machine": "linux2",
  "pane_id": "",
  "tab_id": "",
  "agent_status": "",
  "signal": "machine-unreachable",
  "detail": "host unreachable"
}
#+END_SRC

~detail~ is ~host unreachable~, ~authentication locked (unlock your
SSH/gpg agent)~, or the herdr error, as for ~scan~. Its ~gate_hold~ line
is ~gate: busy machine linux2: machine-unreachable host unreachable~.
When a remote tab's signal cannot be read (process-info fails or lists
no foreground process, or ~decide~ or the tab labels fail), it is listed
under ~signal_unavailable~ and the tab holds the gate with signal
~signal-unavailable~ and ~detail~ ~<signal>: <error>~.

** logs

Each run (except ~logs~ itself) appends JSON lines to
=$XDG_STATE_HOME/prsync/prsync.jsonl= (or
=~/.local/state/prsync/prsync.jsonl=). Rotates by size (~10 MiB~) and
age (~14 days~). Default level ~info~; stdout JSON is unchanged.
~--log-level~ overrides ~PRSYNC_LOG~.

A dispatch line of investigation includes the target pane, send, each
~agent_status~ transition, gate wait, settle decision, skip/dedupe
outcome, and process exit. Startup records the resolved config path
and ~concurrency_wait_on~.

#+BEGIN_SRC bash
prsync logs --path
prsync logs
#+END_SRC

~--path~ prints ~{"path":"…"}~. Without it, ~logs~ dumps the JSONL file
(empty stdout if no log exists yet).

* Manual smoke test

Against a real herdr ≥ 0.8 and an authenticated ~gh~, run the typical
loop from the overview plus:

#+BEGIN_SRC bash
prsync dispatch --config ./prsync.config --ci-fix
prsync comment --config ./prsync.config --body "please retry"
prsync comment --config ./prsync.config --body "please retry" --go
prsync gate --config ./prsync.config
prsync logs --path
prsync logs
#+END_SRC

Confirm ~agent prompt~ targets a ~pane_id~ (~w2:pC~, not a tab id) and
the default wait is ~--wait --until idle --until done~. README-only;
CI uses fixture binaries, not live herdr.

* Security

- ~prsync~ never calls ~gh auth token~ and never prints the
  environment. Auth is the operator's existing ~gh~ login plus the
  local herdr socket.
- ~comment --go~ posts the given body as a GitHub PR comment. Dry-run
  first; there is no extra confirmation beyond ~--go~.
- ~tabs --orphans --close-merged --go~ runs ~herdr tab close~ on each
  tab still in the ~merged~ bucket. Dry-run first; ~no_pr~, ~unknown~,
  and ~has_open_pr~ tabs are never candidates. An all-~no_pr~ or
  ~unknown~ classification refuses the close unless ~--force~.
- The unblock check runs ~jira issue view --raw~ and does not
  transition, comment, or assign. A failed check does not invent a
  ticket that is free to start.
- Review comment bodies are interpolated into the dispatch prompt as
  text. ~prsync~ does not execute them. The *agent* may follow
  malicious review text — this is inherent to the product. Do not treat
  the prompt as sanitized English.
- The config parser does not ~source~ the file, so values cannot
  execute as shell.
- JSON on stdout can contain review bodies and logins. That is the
  operator's responsibility.
- Concurrent ~prsync dispatch --go~ across machines sharing
  ~state_file~ over NFS is unsupported.

* Exit codes

| Code | Meaning |
|------+---------|
|    0 | Success |
|    1 | ~gate~: busy set is non-empty or the dispatch checkout is dirty; ~dispatch --go~: dirty dispatch checkout (~gate_unsafe~) |
|    2 | Usage, config, or flag error |
|    3 | Missing tool, auth failure, herdr too old, or mid-loop dispatch failure |
|    4 | Live dispatch timed out waiting on the gate or settle |
