#+TITLE: decide

decide is a small inbox for questions that AI coding agents need a human
to answer. An agent runs ~decide ask~ with a question and a few options.
You answer in ~decide inbox~ (a terminal UI) or in Emacs, and decide
notifies the agent's terminal pane with your answer. It also carries
short notes and status between you and your agents, and one inbox can
be shared by two machines.

* Overview

~decide~ works standalone; companion tools such as
[[https://herdr.dev/][herdr]] (the terminal multiplexer for agent panes)
and [[file:../agentbus/README.org][agentbus]] (for ~agentbus:<name>~
delivery) are optional -- see [[*Ecosystem]]. ~decide skill~ prints the
agent rules (~cmd/decide/skill.md~). This file is the human guide.

* Install

#+begin_src sh
go install github.com/jaeyeom/experimental/devtools/decide/cmd/decide@latest
#+end_src

~go install ./devtools/decide/cmd/decide~ is the same from a checkout.
~devtools/setup-dev/ansible/setup-decide.yml~ installs the binary and
the agent skill. ~decide follow~ as a service is manual; see
[[*Getting answers back]].

Config is JSON at ~$XDG_CONFIG_HOME/decide/config.json~, or
=~/.config/decide/config.json= when ~XDG_CONFIG_HOME~ is unset. A
missing file is an empty config.

* Quick start

Inside a [[https://herdr.dev/][herdr]] pane the owner defaults to that
tab's label, and the pane is stored so the answer can be delivered
there. Outside herdr, pass ~--owner~; answers default to ~pull~
delivery unless ~notifyPane~ is set in config or ~--notify-pane~ is
passed.

#+begin_src sh
decide ask --kind relay --option y:Yes --option n:No --rec y "Merge the release branch?"
#+end_src

The command prints the new id and nothing else. The first item is
~D-001~, then ~D-002~, and so on.

#+begin_src sh
decide inbox
#+end_src

The list is one row per item. The columns are the id, the owner, the
age, the kind, and the latest message:

#+begin_example
>   D-001  review  5m  relay  Merge the release branch?
#+end_example

Enter opens the item. Press ~y~ to pick the Yes option, or answer from
the shell. Answering records the answer and marks the item ~answered~;
it never closes the thread (~done~ stays the owner's step). ~--via ui~
records that a person answered in the inbox or Emacs; a bare ~decide
answer~ records ~cli~.

#+begin_src sh
decide answer --via ui D-001 y
decide show D-001
#+end_src

~decide show~ prints the item. Times are UTC. This sample's owner is
the tab ~review~ and its notify pane is ~w6:pM~:

#+begin_example
id: D-001
question: Merge the release branch?
owner: review
kind: relay
state: answered
freeText: true
unread: false
option: y: Yes recommended
option: n: No
createdAt: 2026-11-15T05:11:55.210872Z
answeredAt: 2026-11-15T05:11:55.511414Z
answer: y: Yes
answeredBy: human
via: ui
notifyPane: w6:pM
message: 2026-11-15T05:11:55.210872Z review Merge the release branch?
message: 2026-11-15T05:11:55.511414Z human y: Yes
#+end_example

~decide show --json D-001~ prints that item as JSON and adds
~ownerLocation~. The answer object is ~value~ ~y~, ~key~ ~y~, ~label~
~Yes~, ~answeredBy~ ~human~, and ~via~ ~ui~. A pane herdr does not list
has ~"state": "closed"~. Unset ~doneAt~ and ~withdrawnAt~ are the zero
time. An empty ~notifyTemplate~ runs nothing. With a template set, the
command's environment has ~DECIDE_ID=D-001~, ~DECIDE_ANSWER=y~,
~DECIDE_ANSWER_LABEL=Yes~, ~DECIDE_OWNER~, and ~DECIDE_PANE~. The full
list is under [[file:docs/delivery.org][docs/delivery.org]].

Close the item when the work is finished:

#+begin_src sh
decide done D-001 "merged"
#+end_src

That prints the item again with ~state: done~ and ~outcome: merged~.

An agent cannot remove an unread item from the user's inbox. When the
item is unread, or an agent message is newer than both ~readAt~
(opening the item in the inbox marks it read) and the user's last
message, ~decide done~ stores
the outcome and the done time, appends ~done: <outcome>~ to the thread,
and sets ~state: done-unread~. The item stays in the inbox, marked
unread, until the user reads and archives it or answers it. The command
prints that on stderr and exits 0. Archiving keeps the agent's outcome.
~decide done --via ui~ is the user's own done from the inbox and Emacs.
It closes the item at once. Agents have no bypass, and ~decide
withdraw~ refuses a done-unread item.

* Concepts

- An *item* is one question or note, id ~D-001~ and up. Its *thread*
  is ~messages~. The ask is the first. ~decide reply~ and ~decide send
  --id~ append. ~decide send --to~ starts a thread.
- The *owner* is who you find the ask by: inside herdr, the pane's tab
  label, unless ~--owner~ is set. A name that matches neither that tab
  nor the pane's agentbus names still files, and asks print a warning
  on stderr.
- *relay* is a choice. It needs at least two ~--option key:label~
  values and ~--rec~ set to one of those keys. Free text is allowed
  unless ~--options-only~ is set or ~optionsOnly~ is true in the config.
  *type-in* is "type this exact text". It needs ~--type-text~ and
  ~--where~.
- *States* are ~open~, ~answered~, ~done~, ~done-unread~, and
  ~withdrawn~. ~done-unread~ is done for the agent but still in the
  user's inbox: ~decide list~ (open) and the inbox show it, and it is
  not counted as the owner's open work. Snoozed is not a state: the
  item keeps its state and is hidden until it wakes.
- The *ledger* is ~ledger.json~ in ~$XDG_STATE_HOME/decide~, or
  =~/.local/state/decide= when ~XDG_STATE_HOME~ is unset. ~status.json~
  in that same directory holds agent and resource rows, separate from
  the ledger.
- The *notify pane* is where the answer is delivered. An ask from a
  herdr pane stores that pane. Outside herdr (with no ~notifyPane~ in
  config), ~decide ask~ stores ~pull~ so the owner polls for answers
  instead of receiving push notifications. ~--notify-pane~ wins; pass
  ~--notify-pane pull~ to force pull delivery inside herdr or when
  ~notifyPane~ is configured. A value of ~agentbus:<name>~ delivers
  with ~agentbus send~ instead of a pane command. A value of
  ~target:<name>~ delivers to a named entry in ~targets~ (such as a
  command target configured with ~targets[].command~).
- A *hub* is a second machine's ssh target. The hub holds the ledger.
  The other machine runs the same commands against it. See
  [[*Using two machines]].
- The *inbox tick* is the reload. A local inbox reloads the ledger every
  250ms. A hub inbox asks the hub once a second and keeps the last good
  view while a request is in flight.

may be a positional argument, ~--text-file <path>~, or ~-~ for stdin.

that hub for one invocation.

* Asking and answering

~decide ask~ files an item (~--class~ sets ~decision~, ~approval~,
~request~, ~fact~, ~inbound~, ~task~, or ~note~; ~--kind~ sets ~relay~
or ~type-in~). Author text stored in the ledger or status board must
follow inbox shape rules, while ~--verbatim~ / ~--verbatim-file~ stores
exact drafts without shape checks. ~decide log search~ and ~decide
supersede~ manage the decision log; ~decide assign~ records a separate
worker while keeping the original owner; ~decide snooze~ hides an item
until a time or new message.

Full flags, shape rules, item classes, approval cards, backfill,
decision log, owner/worker routing, and snooze formats are in
[[file:docs/items.org][docs/items.org]]. Provenance rules (~via~ and
~by~) are in [[file:docs/provenance.org][docs/provenance.org]].

* The inbox

~decide inbox~ is the terminal UI with folders for Inbox, Snoozed,
Answered, Done, Withdrawn, Status, and Contacts (plus Outbox in hub
mode). It loads the ledger in the background, pins the item title and
reply box, persists unsent drafts to ~drafts.json~ (synced across hub
clients with conflict resolution), supports clickable OSC 8 links,
copy menus, snooze presets, and focusing the owner's herdr tab (~o~).

The full keybindings table, item view and reply box behavior,
persistent drafts summary, and UI options are in
[[file:docs/inbox.org][docs/inbox.org]]. Draft storage and sync design
are in [[file:docs/drafts.org][docs/drafts.org]], and terminal key
sequences (~Ctrl+Enter~, ~DECIDE_KEYDEBUG~) are in
[[file:docs/keys.org][docs/keys.org]].

* Notes and status

~decide send --to <name> "<text>"~ starts a thread. ~decide send --to~ and
~decide send --id~ also accept ~--verbatim <text>~ and ~--verbatim-file
<path>~ (alone, without positional text, ~--text-file~, or stdin, or
alongside short author text). A configured target
uses ~sendTemplate~, which defaults to ~herdr agent prompt {pane}~ with
the note as its own argument. ~{pane}~ is replaced. The note is not
interpolated into a shell. With ~"recipients": {"agentbus": true}~,
~--to~ also accepts a name from ~agentbus list~, and the note goes
through ~agentbus send~. ~--via~ defaults to ~cli~.

The compose dropdown has at most eight rows and filters as you type.
Bus names load in the background, at start and every 30 seconds, so
compose does not wait. ~recipientsTimeout~ bounds a load (default 3s).
Dead names come last. A slow load says ~agentbus: slow (>3s)~. A failure
says ~agentbus: unavailable~ and keeps the last good names.

While the bus cannot deliver, the inbox's top line says ~Bus down:
messages to agents are waiting.~, then the first problem, dimmed and
cut to the screen width. The inbox runs ~agentbus health --json~ in the
background every ~ui.busHealthInterval~ (default 15s), and the line
goes on the first check after the bus recovers. A check that is slow
(over 5s), or an agentbus that is missing or has no ~health~, shows no
line and is logged once at debug level. In hub mode the check runs on
the hub, where agent messages are sent.

While that line is up, sending a reply or a compose note to an agent
on the bus (a bus name, or a pane that starts with ~agentbus:~) first
asks ~The bus is down. This message will wait until it's fixed.~ with
~[Send anyway]~ focused and ~Cancel~. Enter picks the focused choice,
Tab moves the focus, ~y~ sends, and ~n~ or Esc cancels. Cancel keeps the
draft. The prompt uses the last background check and runs none of its
own. A local pane target sends without asking.

~decide status~ uses ~status.json~. ~set --agent~ writes one row. A new
row with no ~--state~ is ~working~, and a later set keeps the state.
~list~ prints name, state, age, and text. A row older than five minutes
is dim. ~set --resource <name> free|busy~ writes a shared flag. ~clear~
removes one row or one flag. ~checkouts~ maps a resource name to a
checkout path and shows that path's agentbus lease (~free~, ~held by
<name> until 14:20~, ~paused by user~, ~needs adopt~, plus ~, <n>
queued~), or the stored row with ~(guess)~. The choice is in
[[file:docs/leases.org][docs/leases.org]].

* Getting answers back

After a relay answer is saved, local panes run ~notifyTemplate~ (with
~DECIDE_*~ environment variables), remote herdr panes use the compose
command with ~--machine~, ~agentbus:<name>~ panes deliver via
~agentbus send --client-id~, and ~target:<name>~ delivers to a named
entry in ~config.json~ ~targets~. For non-LLM CLI tools (such as
~slackwatch~, ~gh-outbox~, or scripts), configure a command target with
~targets[].command~ (mutually exclusive with ~pane~) and file asks with
~--notify-pane target:<name>~:

#+begin_src json
{
  "targets": [
    {"name": "slackwatch", "command": ["slackwatch", "decide-callback"]}
  ]
}
#+end_src

When an answer or human reply arrives for ~target:slackwatch~, ~decide~
executes ~command[0]~ with ~command[1:]~ directly (no shell), passes the
~DECIDE_*~ environment variables, and writes the JSON-encoded item
(matching ~decide show --json~) on stdin. Every message tracks a delivery
mark (~waiting~, ~delivered HH:MM~, or ~failed~), retries transient
failures up to three times, and follows up once on stale answers via an
open local inbox, the hub's ~decide serve --stdio~, or ~decide follow~.

The full ~DECIDE_*~ environment reference, delivery marks, retry and
stale follow-up rules, and the four-stage Outbox / Answered / delivery
mark / Done lifecycle are in [[file:docs/delivery.org][docs/delivery.org]].
Custom executable ~Transport~ plugins (~transports~ in ~config.json~,
routed by ~<scheme>:<address>~ over a v1 JSON stdin/stdout protocol) are
documented in [[file:docs/plugins.org][docs/plugins.org]].
The systemd unit and launchd agent for ~decide follow~ are in
[[file:docs/follow.org][docs/follow.org]].

* Emacs

~devtools/decide/emacs/decide.el~ is a plain Emacs frontend that lists,
opens, answers, and composes items by calling the ~decide~ CLI, recording
~via: "ui"~ like the terminal inbox. Setup, keybindings, Evil support,
and hub-mode wrapper configuration (~decide-program~) are in
[[file:docs/emacs.org][docs/emacs.org]].

* Configuration

Config is one JSON object at ~$XDG_CONFIG_HOME/decide/config.json~
(default =~/.config/decide/config.json=). Unset keys keep their
defaults, and ~decide keys~ prints the active ~ui.keys~ keymap. The
full config key table and ~ui.keys~ action-name reference are in
[[file:docs/configuration.org][docs/configuration.org]].

* Web and mobile

~decide web~ serves the inbox as a web app and installable PWA from the
machine that holds the ledger, with a single-column phone layout and a
split-pane desktop one. It reads and writes the same ledger as the
terminal inbox, and answers record ~via: "ui"~. It binds
~127.0.0.1:8787~ and expects an HTTPS ingress such as Tailscale Serve,
Cloudflare Tunnel, or Caddy. Token auth is optional on loopback and
needed for anything else; mode ~none~ is refused off loopback. Web Push
(~web.push.enabled~) notifies actionable items, never notes, and skips
items you read in the terminal or while a page is open. Setup, ingress
recipes, service files, Android and iPhone install, and the security
notes are in [[file:docs/web.org][docs/web.org]].

* Using two machines

One machine (the hub) holds the ledger; the other sets ~hub~ (or
~DECIDE_HUB~) and runs CLI commands over ~ssh -T -o BatchMode=yes~.
~decide inbox~ syncs a local replica over ~decide serve --stdio~ and
queues writes in a local outbox so the UI never blocks. Hub setup,
~DECIDE_AS_HANDLE~, replica/outbox sync, and local-vs-hub config
precedence are in [[file:docs/hub.org][docs/hub.org]].

* Who may open items

In a multi-agent setup, ~owners~ (~mode: off | warn | enforce~,
~allowed~, ~managers~) restricts which agents may open new items via
~decide ask~ and ~decide send --to~, tagging or refusing non-direct
reports while allowing replies and UI actions. Configuration,
~decide list --off-line~, and hub-mode rules are in
[[file:docs/owners.org][docs/owners.org]].

* Customizing

Avatars are optional 10x6 figures beside an item header and beside the
compose recipient. An exact ~match~ wins, then the first glob. ~file~
may start with =~/=. A PNG or WEBP is drawn as characters. Any other
file is text. ~builtin~ names a shipped figure. Both in one rule is an
error. ~"hide": true~ shows nothing.

#+begin_src json
{"avatars": [{"match": "pm-*", "builtin": "owl"}], "avatarDefault": true}
#+end_src

~avatarDefault~ is off until you set it. The same name always gets the
same figure. ~decide avatars list~ previews them. ~--name~ shows one
name's figure, and ~--ids~ prints the ids. ~decide avatars set ops/x
owl~ saves a name. ~default~ drops that exact rule. ~none~ hides it.
~--local~ writes this machine even in hub mode. Otherwise a hub-mode
set saves on the hub. ~A~ opens the picker. With mouse capture on, a
click on a cell saves it, a click outside the picker or on its border
cancels, and the wheel moves one row. The id list, the hash, and the
config write are in [[file:docs/avatars.org][docs/avatars.org]].

Contacts (~g~ then ~c~) lists ~agentbus list~ names plus ledger owners
and senders, with hiding, starring, aliasing, pruning, a contact detail
panel, and an optional org-tree view (~ui.orgTree~ / ~ui.orgSpec~). See
[[file:docs/contacts.org][docs/contacts.org]].

* Ecosystem

~decide~ works standalone with only its CLI, ledger, and inbox UI. Every
connected tool below is optional and connects through a narrow boundary:
human UIs read and write the same ledger, producers invoke the CLI, and
outbound delivery routes through the agnostic ~Target~ -> ~Transport~
interface (see [[file:docs/delivery.org][docs/delivery.org]]):

#+begin_example
  Producers (ask / reply / done)               Human UIs (optional frontends)
  +-------------------------------+            +-----------------------------+
  | coding agents, slackwatch,    |            | Terminal TUI (decide inbox) |
  | gh-outbox, memstore, scripts  |            | Web / PWA    (decide web)   |
  +---------------+---------------+            | Emacs        (decide.el)    |
                  |                            | CLI          (decide ...)   |
                  |                            +--------------+--------------+
                  v                                           v
  +---------------+-------------------------------------------+--------------+
  |                        CORE decide (standalone)                          |
  |  CLI: ask / answer / reply / done / show / list / send                   |
  |  Ledger: ledger.json, status.json, drafts.json                           |
  |  Optional SSH hub: decide serve --stdio (two-machine sync)               |
  +-------------------+-----------------------------------+------------------+
                      |                                   ^
                      | answers / notes                   | read-only context
                      | (Target -> Transport)             | & checkout gate
                      v                                   |
  +-------------------+-------------------+    +----------+------------------+
  | Agnostic Delivery Plugins (Transport) |    | Context & Gate Companions   |
  +---------------------------------------+    |  orgctl (Contacts org tree) |
  | herdr:<pane> (or bare <pane>)         |    |  prsync (reads open items)  |
  |   pane delivery & tab focus (herdr)   |    +-----------------------------+
  |                                       |
  | agentbus:<name>                       |
  |   bus delivery, status polling,       |
  |   health, contacts, leases (agentbus) |
  |                                       |
  | pull (or pull:<detail>)               |
  |   no-op push; caller polls            |
  |   decide show/list --json             |
  |   (CI, desktop apps, scripts)         |
  |                                       |
  | target:<name>                         |
  |   targets[].command (DECIDE_* env +   |
  |   item JSON on stdin) for non-LLM     |
  |   tools (slackwatch, gh-outbox, etc.) |
  +---------------------------------------+
#+end_example

Optional companion tools that extend ~decide~ when installed:

- [[https://herdr.dev/][herdr]] -- terminal multiplexer for agent panes;
  auto-populates ~--owner~ from the tab label, delivers answers to panes,
  and lets ~o~ focus the owner's tab.
- [[file:../agentbus/README.org][agentbus]] -- local agent message bus;
  adds ~agentbus:<name>~ delivery, live compose recipients
  (~recipients.agentbus~), the bus health banner, delivery status
  tracking, Contacts liveness and release, and checkout leases.
- [[file:../orgctl/README.org][orgctl]] -- declarative agent-team org
  spec; enables the Contacts org-tree view (~ui.orgTree~ / ~ui.orgSpec~)
  and complements ~owners~ allow-lists.
- [[file:../slackwatch/README.org][slackwatch]] -- Slack bridge; routes
  agent-drafted Slack posts through ~decide~ approval items before
  posting.
- [[file:../gh-outbox/README.org][gh-outbox]] -- GitHub PR comment
  outbox; lints agent-drafted PR comments and gates posting on ~decide~
  UI approval.
- [[file:../prsync/README.org][prsync]] -- PR-to-tab sync; reads open
  ~decide~ items as a busy signal in its checkout gate.
- [[file:../memstore/README.org][memstore]] -- personal memory store;
  routes automated routine outbox actions and proposals through ~decide~
  for human approval and triage.
- [[file:../setup-dev/README.org][setup-dev]] -- Ansible playbooks
  (~setup-decide.yml~) for installing ~decide~ and its agent skill.

* Troubleshooting

~DECIDE_KEYDEBUG=/tmp/decide-keys.log decide inbox~ logs each key.
~1~ uses ~decide-keys.log~ in the temp directory. Ctrl+Enter is
recognized only as the two sequences in
[[file:docs/keys.org][docs/keys.org]]. A terminal that sends it as Enter
gets Enter. A config that does not parse is left unchanged. Avatar and
contact writes touch only their own key, and the first write in a
process copies the file to ~config.json.bak~.
