#+TITLE: decide follow as a service

~decide follow~ retries a failed delivery and sends one stale
follow-up. Run it on the machine that holds the ledger. The README
says what the loop does. These are the unit files.

The service needs ~decide~, the notify command, and herdr on ~PATH~.
Add ~Environment=PATH=...~ to the systemd unit, or an
~EnvironmentVariables~ dictionary to the plist, when they are not on
the default path.

* Linux

Put this at =~/.config/systemd/user/decide-follow.service=:

#+begin_src conf
[Unit]
Description=decide stale-answer follow-up

[Service]
ExecStart=%h/go/bin/decide follow
Restart=on-failure

[Install]
WantedBy=default.target
#+end_src

Then ~systemctl --user daemon-reload~ and ~systemctl --user enable
--now decide-follow~. ~loginctl enable-linger~ keeps it running after
you log out.

* macOS

Put this at
=~/Library/LaunchAgents/com.github.jaeyeom.decide-follow.plist=.
Replace =/Users/me= with your home directory:

#+begin_src xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
  <key>Label</key>
  <string>com.github.jaeyeom.decide-follow</string>
  <key>ProgramArguments</key>
  <array>
    <string>/Users/me/go/bin/decide</string>
    <string>follow</string>
  </array>
  <key>RunAtLoad</key>
  <true/>
  <key>KeepAlive</key>
  <true/>
  <key>StandardErrorPath</key>
  <string>/Users/me/Library/Logs/decide-follow.log</string>
</dict>
</plist>
#+end_src

Then ~launchctl bootstrap gui/$(id -u)
=~/Library/LaunchAgents/com.github.jaeyeom.decide-follow.plist=~.
