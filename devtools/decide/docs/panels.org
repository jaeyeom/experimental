#+TITLE: decide dashboard panels

The Status view in ~decide inbox~ and ~decide web~ displays built-in
Status panels and external dashboard panels stored on the hub. ~decide~
only displays panels; it never runs the jobs that produce them.

* Storage and file contract

Each external panel is one JSON file in =panels/<id>.json= under the
decide state directory on the hub (=$XDG_STATE_HOME/decide/panels/= or
=~/.local/state/decide/panels/=).

#+begin_src json
{
  "id": "ci-status",
  "title": "CI Status",
  "kind": "List",
  "data": {"rows": [{"label": "main", "value": "passing", "state": "ok"}]},
  "updatedAt": "2026-11-26T22:00:00Z",
  "staleAfter": "5m",
  "source": "github-actions"
}
#+end_src

| Field        | Required | Format / rule                                            |
|--------------+----------+----------------------------------------------------------|
| ~id~         | yes      | Matches ~[a-z0-9-]+~ and the filename without ~.json~.   |
| ~title~      | yes      | Non-empty display title.                                 |
| ~kind~       | yes      | Component name (see Panel kinds below).                  |
| ~data~       | yes      | Valid non-null JSON payload for ~kind~.                  |
| ~updatedAt~  | yes      | RFC 3339 timestamp.                                      |
| ~staleAfter~ | no       | Positive Go duration (e.g. ~5m~, ~1h~).                  |
| ~source~     | no       | Free text naming the writer.                             |

Writers must write a temporary file in =panels/= and rename it into
place (via ~renameio.WriteFile~ with ~WithTempDir~) so readers never see
a half-written file. Dotfiles and non-=.json= files in =panels/= are
ignored.

* Panel kinds

Kind names follow A2UI (~a2ui.org~) component names where one exists.
~decide.RegisterPanelKind~ validates ~data~ for each built-in kind on
~decide panel set~ and when loading =panels/*.json=. Unknown kinds are
accepted without error and rendered as ~Text~ (pretty-printed JSON,
truncated).

- ~Text~: ~{"text": "..."}~
  - ~text~ (string, required): multi-line plain text.
- ~List~: ~{"rows": [{"label": "...", "value": "...", "state": "ok|warn|fail"}]}~
  - ~rows~ (array, required): each row requires ~label~ and ~value~
    strings; optional ~state~ is ~ok~, ~warn~, or ~fail~.
- ~Gauge~: ~{"value": 72, "max": 100, "warn": 75, "fail": 90, "unit": "%"}~
  - ~value~ (number, required) and ~max~ (number > 0, required).
  - ~warn~ and ~fail~ (numbers, optional): threshold colors on the bar.
  - ~unit~ (string, optional): suffix shown next to the values.
- ~Chart~: ~{"series": [{"t": "...", "v": 40}], "unit": "%", "limit": 100, "projection": {"to": 100, "at": "2026-11-26T16:30:00Z"}}~
  - ~series~ (array of ~{t, v}~, required): ~t~ is a non-empty string
    and ~v~ is a finite number.
  - ~unit~ (string, optional) and ~limit~ (number, optional).
  - ~projection~ (optional): ~to~ (finite number) and ~at~ (RFC 3339
    timestamp) draw a projection line in the web SVG and print the
    crossing time. In the terminal, ~Chart~ renders a sparkline plus
    summary text.
- ~Table~: ~{"columns": ["Col1", "Col2"], "rows": [["a", "b"]]}~
  - ~columns~ (string array, required) and ~rows~ (array of scalar cell
    arrays, required). Renders up to 5 rows and truncates remaining rows
    with ~+N more~.

* Staleness

When a panel is past ~staleAfter~, both ~decide inbox~ and ~decide web~
dim the panel and show its age (e.g. ~stale · updated 3h ago~).

* Built-in panels

The Status page sections are built-in panels rendered through the same
dashboard pipeline:

- ~agents~: agent status table (~agent~, ~state~, ~updated~, ~text~),
  preserving row highlighting and ~c~ to compose.
- ~resources~: resource leases and checkouts (~resource~, ~free/busy~,
  ~updated~, ~note~).
- ~bus-health~: ~agentbus health --json~ status (~daemon~, ~transport~,
  and any ~problems~) rendered as a ~List~ panel.
- ~outbox~: offline outbox queue entries (terminal inbox) rendered as a
  ~List~ panel.

* On, off, and order

~ui.dashboard.panels~ in ~config.json~ stores panel visibility and order:

#+begin_src json
{
  "ui": {
    "dashboard": {
      "panels": [
        {"id": "ci-status", "enabled": true, "order": 0},
        {"id": "resources", "enabled": false, "order": 1}
      ]
    }
  }
}
#+end_src

- Panels listed in ~ui.dashboard.panels~ appear first sorted by ~order~.
- Panels not listed appear after the listed ones, enabled.
- On the terminal Status page (~g s~):
  - ~space~ toggles the selected panel on or off (disabled panels collapse
    to a dimmed ~(off)~ header line so they can be toggled back on).
  - ~J~ / ~K~ moves the selected panel down or up.
  - Changes persist immediately to ~config.json~.
- The Settings page (~g ,~) lists all dashboard panels with their order
  and ~enabled~ / ~disabled~ state.
- ~decide web~ renders the same enabled panels in the same order,
  read-only.

* CLI

- ~decide panel set <id> --title T --kind K (--data JSON | --file F) [--stale-after D] [--source S]~:
  validates ~id~, JSON, and ~data~ shape for known kinds; sets
  ~updatedAt~ to the current UTC time; and writes atomically. In hub
  mode, ~--file F~ is read on the client machine and sent to the hub as
  ~--data~; panels live only on the hub.
- ~decide panel rm <id>~: removes =panels/<id>.json=.
- ~decide panel ls [--json]~: lists id, title, kind, age, and ~stale~
  or ~unreadable~ status.

* Change-driven watching and robustness

- Both ~decide inbox~ (local and hub-mode) and ~decide web~ watch
  =panels/= with ~fsnotify~ via ~inboxrpc/watch.go~ and ~decide.WatchPanels~,
  redrawing only when a panel file changes. No timer-based polling is
  used for panels.
- Staleness uses a single one-shot wakeup scheduled at the earliest
  ~updatedAt + staleAfter~.
- A panel file that cannot be read, cannot be parsed, has a bad id, or
  has missing or unknown required fields is shown as
  ~panel unreadable: <file>~ and never breaks the page.
- ~decide doctor~ reports bad panels (unreadable, bad id, missing or
  unknown required fields) and stale panels.
