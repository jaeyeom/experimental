#+TITLE: decide persistent drafts

Persistent drafts keep unsent replies, free-text answers, and compose
notes across TUI restarts and across hub clients. This doc covers the
on-disk format, hub protocol, save timing, conflict handling, limits,
and local replica and ~$EDITOR~ behavior.

* Storage format and location

Drafts live in =drafts.json= alongside =ledger.json= in the ledger
directory (=$XDG_STATE_HOME/decide/drafts.json= when =XDG_STATE_HOME=
is set, or =~/.local/state/decide/drafts.json=). Both local mode and
the hub store =drafts.json= in that same ledger directory.

Writes are atomic via ~renameio.WriteFile~ with mode ~0o600~ and
serialized by a dedicated =drafts.lock= (~flock~) so debounced draft
saves never contend with =ledger.lock=.

#+begin_src json
{
  "seq": 4,
  "drafts": {
    "reply:42": {
      "text": "Let's ship it.",
      "rev": 2,
      "updatedAt": "2026-11-21T20:00:00Z",
      "updatedBy": "dragon",
      "conflicts": []
    },
    "compose": {
      "to": "worker",
      "bus": "agentbus",
      "forward": "",
      "text": "Status check",
      "rev": 1,
      "updatedAt": "2026-11-21T20:01:00Z",
      "updatedBy": "dragon"
    }
  }
}
#+end_src

- Keys: ~reply:<itemID>~, ~answer:<itemID>~, ~forward:<itemID>~, and
  ~compose~. ~compose~ and ~forward:<itemID>~ additionally store ~to~,
  ~bus~, and ~forward~ alongside ~text~.
- Top-level ~seq~ is a monotonic counter incremented on every mutation
  for ~watch~ change detection.
- Each draft stores ~rev~ (monotonic per draft), ~updatedAt~,
  ~updatedBy~ (machine or client label), and ~conflicts[]~.

* Protocol ops (~inboxrpc~)

Bump ~inboxrpc.Version~ from ~10~ to ~11~ and add three RPC ops:

- ~list-drafts~: returns the current draft map and ~seq~.
- ~put-draft~: writes a draft with ~baseRev~ for optimistic concurrency,
  returning the resulting draft (~rev~, ~seq~, and ~conflict: true~ if
  a conflict was recorded).
- ~delete-draft~: removes a whole draft by key, or removes a single
  entry from ~conflicts[]~ when ~conflictId~ is specified.

~connWatcher~ polls =drafts.json= mtime using the same pattern as
=status.json= and pushes ~Drafts~ and ~DraftSeq~ on ~watch~ updates.

* Save timing

- Debounce: save 1.5s after typing stops in reply, free-text answer, or
  compose (and on compose recipient changes when ~text~ is non-empty).
- Immediate flush: save immediately when leaving the detail or compose
  view, switching threads, or exiting the TUI.
- Immediate delete: delete immediately on send or discard, or when the
  draft text is cleared to empty or whitespace-only.

* Conflict detection and UI

Drafts use optimistic concurrency via ~baseRev~ on ~put-draft~ so
concurrent edits never silently overwrite each other:

- Matching ~baseRev~: update the draft in place and increment ~rev~.
- Mismatched ~baseRev~ with identical content: treat as a no-op.
- Mismatched ~baseRev~ with different content: keep the existing draft
  intact, append the incoming version to ~conflicts[]~ (with
  ~conflictId~, ~baseRev~, ~updatedAt~, and ~updatedBy~), increment
  ~rev~, and return ~conflict: true~.

In the TUI:

- The list view shows a ~draft~ mark on threads with a saved draft, or
  ~draft!~ when unresolved ~conflicts[]~ exist.
- Opening a draft with unresolved conflicts shows an editor banner
  offering *Keep current* (delete conflict entry), *Use other* (replace
  draft with conflict entry and delete conflict entry), and *Merge
  both* (insert git-style conflict markers editable inline or in
  ~$EDITOR~).

* Size limits and cleanup

- Max draft text size: 64 KiB. Oversized saves are refused with a
  status warning while keeping the in-memory text intact.
- Max conflict copies per draft: 10.
- Lifecycle cleanup: ~reply:<id>~ and ~answer:<id>~ are deleted
  automatically when the item is archived, marked done, withdrawn, or
  deleted. A ~PruneDrafts~ sweep removes orphaned drafts whose items no
  longer exist.

* Local replica and ~$EDITOR~

- Local replica: ~replicaData~ caches ~Drafts~ and ~DraftSeq~ so list
  ~draft~ / ~draft!~ marks and thread opens read drafts immediately with
  zero hub round-trip.
- Offline edits: unsynced local draft edits made while disconnected
  from the hub are preserved in the replica and flushed with their
  ~baseRev~ on reconnect, triggering normal conflict detection if the
  hub's ~rev~ moved on.
- External editor (~$EDITOR~): flush and record ~baseRev~ before
  suspending the TUI; on return, immediately save if the text was
  modified (or delete if emptied). Concurrent remote edits while
  ~$EDITOR~ was open trigger normal ~baseRev~ conflict handling.
