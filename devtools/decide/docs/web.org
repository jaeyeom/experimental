#+TITLE: decide web

~decide web~ serves the inbox as a web app and Progressive Web App
(PWA) from the machine that holds the ledger. It is the same ledger,
drafts, and status that ~decide inbox~ uses, so an answer given in a
browser records ~via: "ui"~ like one given in the terminal. The README
says what the inbox does. This doc covers setup, auth, the HTTPS
ingress, Web Push, and the limits.

Run it on the hub: it always reads this machine's ledger and never
connects to another one, even when ~hub~ is set in the config. The page
is plain ES modules and CSS embedded in the binary, so there is no
build step and no Node.

* Quick start

#+begin_src sh
decide web --token-file ~/.config/decide/web-token
#+end_src

The command prints ~decide web: listening on http://127.0.0.1:8787~ and
runs until SIGINT or SIGTERM, then shuts down within five seconds. The
token file is created with a random 64-character token (mode 0600) the
first time; its directory must exist. Print it with ~cat~ and type it
into the sign-in page at http://127.0.0.1:8787/.

Flags:

| Flag                      | Meaning                                                              |
|---------------------------+----------------------------------------------------------------------|
| ~--addr~                  | Listen address. Wins over ~web.addr~. Default ~127.0.0.1:8787~.      |
| ~--token-file~            | Turn on token auth, with the token read from (or created at) this file. |
| ~--allow-insecure-unauth~ | Allow auth mode ~none~ on a non-loopback address.                    |
| ~--no-follow~             | Do not run the stale-answer follow-up loop.                          |

Unless ~--no-follow~ is set, ~decide web~ also runs the loop of
~decide follow~ once a minute, so do not run both as services.

* Configuration

~web~ in =~/.config/decide/config.json= (=$XDG_CONFIG_HOME/decide/config.json=
when set). It is machine-local; a hub never sends it to clients. A
bad value makes every ~decide~ command fail at load.

#+begin_src json
{
  "web": {
    "addr": "127.0.0.1:8787",
    "publicUrl": "https://decide.example.ts.net",
    "auth": {"mode": "token", "tokenFile": "/home/me/.config/decide/web-token"},
    "push": {"enabled": true, "subject": "mailto:me@example.com", "grace": "5s"}
  }
}
#+end_src

| Key                | Default                 | Meaning                                                        |
|--------------------+-------------------------+----------------------------------------------------------------|
| ~web.addr~         | ~127.0.0.1:8787~        | Listen address, ~host:port~.                                   |
| ~web.publicUrl~    | empty                   | The HTTPS address people open. Used only for the same-origin check. |
| ~web.auth.mode~    | ~none~                  | ~none~ or ~token~.                                             |
| ~web.auth.tokenFile~ | empty                 | Token file for mode ~token~. ~--token-file~ sets both this and the mode. |
| ~web.push.enabled~ | false                   | Turn on Web Push. Off means the API answers 503 and no key is written. |
| ~web.push.subject~ | ~mailto:decide@localhost~ | VAPID contact, a ~mailto:~ or ~https:~ URL. Set a real contact for Apple's push service; the default may be refused. |
| ~web.push.grace~   | ~5s~                    | How long a push waits so an item read elsewhere is skipped. A positive Go duration. |

The environment variable ~DECIDE_WEB_TOKEN~ overrides the token file;
the file is not read when it is set. A token must be at least 16
characters.

* Auth and security

Read this before you open the port to anything but yourself.

- *Mode ~none~* (the default) has no sign-in. Everyone who can reach the
  port has the whole inbox: answers, replies, sends. Use it only on
  loopback behind an ingress that already authenticates people.
- *Loopback bind refusal.* ~decide web~ refuses to start in mode ~none~
  on any address that is not ~localhost~, ~127.0.0.0/8~, or ~::1~
  (including ~0.0.0.0~ and ~:8787~), unless ~--allow-insecure-unauth~
  is passed. The flag is the only override. Prefer token mode.
- *Mode ~token~.* The sign-in page posts the token and gets a
  ~decide_session~ cookie: ~HttpOnly~, ~SameSite=Lax~, 30 days, and
  ~Secure~ when the request was TLS or carried ~X-Forwarded-Proto:
  https~. The session is an HMAC of an expiry and a nonce, keyed from
  the token, so changing the token signs everyone out. ~Authorization:
  Bearer <token>~ also works, for scripts. The token compare is
  constant time.
- *Sign-out is in memory.* A signed-out cookie is refused until the
  server restarts; after a restart it is valid again until it expires
  or the token changes.
- *No login rate limiting.* There is no lockout or delay on wrong
  tokens. The token is 256 random bits when generated, so guessing is
  not a concern; a short token you chose is. Put the ingress
  (Tailscale, Cloudflare Access) in front of anything on the internet.
- *CSRF.* Every state-changing request (POST, PUT, DELETE) must be
  same-origin: ~Sec-Fetch-Site~ is ~same-origin~ or ~none~, or, when the
  browser sends no such header, ~Origin~ matches the ~Host~ or
  ~web.publicUrl~. Mode ~none~ is checked too. A valid Bearer token
  skips the check. A proxy that rewrites ~Host~ needs ~web.publicUrl~
  set to the address people open.
- The page is served with a strict ~Content-Security-Policy~ (same-origin
  scripts and styles only) and sets item text with ~textContent~. The
  shell, manifest, and ~/api/v1/health~ are public; the rest of
  ~/api/v1~ answers 401 without a session.
- There is no TLS in ~decide web~. Terminate it at the ingress.

* HTTPS ingress

Keep ~decide web~ on ~127.0.0.1:8787~ and let one of these publish it.
Browsers need HTTPS for the service worker, install, and push, except
on ~localhost~. The event stream is long-lived; do not buffer it.

** Tailscale Serve

Only devices on your tailnet reach it. Enable MagicDNS and HTTPS
certificates in the tailnet admin console first; without them, Serve
has no certificate for the ~ts.net~ name.

To run ~tailscale serve~ as a normal user, grant operator permission
once (or run with ~sudo~):

#+begin_src sh
sudo tailscale set --operator=$USER
tailscale serve --bg http://127.0.0.1:8787
#+end_src

Open the ~https://<machine>.<tailnet>.ts.net~ address that
~tailscale serve status~ prints, and set ~web.publicUrl~ to it.
Tailscale Serve sets ~X-Forwarded-Proto: https~, so the session cookie
gets ~Secure~.

Use token mode (~--token-file~ or ~web.auth.mode: "token"~) even behind
Tailscale Serve: every device on the tailnet, including shared or
borrowed ones, can reach the app, and mode ~none~ gives each of them
the whole inbox.

On a phone, the Tailscale app must be connected to open the app, to
open an item from a notification, and for the "Snooze 1h" action. Push
delivery itself goes through the platform push service and does not
need the tailnet.

** Cloudflare Tunnel

#+begin_src sh
cloudflared tunnel --url http://127.0.0.1:8787
#+end_src

That gives a throwaway ~trycloudflare.com~ address that anyone can
open: use token mode. For a permanent address, create a named tunnel
with a ~service: http://127.0.0.1:8787~ ingress rule, and put
Cloudflare Access in front of it.

** Caddy

#+begin_src conf
decide.example.com {
	reverse_proxy 127.0.0.1:8787 {
		flush_interval -1
	}
}
#+end_src

~flush_interval -1~ sends the event stream at once. Caddy sets
~X-Forwarded-Proto~, so the cookie is ~Secure~. nginx needs
~proxy_buffering off~ for ~/api/v1/events~; the server also sends
~X-Accel-Buffering: no~.

* Run as a service

~decide web~ needs ~decide~ on ~PATH~ for the same reasons as the
follow loop; see [[file:follow.org][follow.org]]. Add ~Environment=PATH=...~
(or ~EnvironmentVariables~) when the notify command or herdr is
elsewhere.

** Linux

Put this at =~/.config/systemd/user/decide-web.service=:

#+begin_src conf
[Unit]
Description=decide web inbox

[Service]
ExecStart=%h/go/bin/decide web --token-file %h/.config/decide/web-token
Restart=on-failure

[Install]
WantedBy=default.target
#+end_src

Then ~systemctl --user daemon-reload~ and ~systemctl --user enable
--now decide-web~. ~loginctl enable-linger~ keeps it running after you
log out.

* Using the app

The inbox has five folders (Inbox, Snoozed, Answered, Done, Withdrawn),
search, class chips, and an agent filter. Swiping a row right archives
it and left snoozes it; both also have buttons. An item opens as a
thread with option buttons (an approval asks you to confirm before
Approve), a pinned reply box whose draft syncs with the terminal
inbox, and conflict copies when two clients edit one draft. There are
also Compose and Forward, the Status board, Contacts (with the org tree
when ~ui.orgTree~ is on), Settings (theme, notifications, sign out),
and light and dark themes.

The page keeps a read cache in IndexedDB and follows the ledger over
~/api/v1/events~ (server-sent events). It resumes from the last event
id after a drop and resyncs when it fell too far behind. Writes go straight to the
server; there is no offline write queue.

* Install on Android

In Chrome open the HTTPS address, sign in, then use the menu's
"Install app" or "Add to Home screen". It then opens standalone, with no
browser bar. The manifest is =/manifest.webmanifest= and the worker is
=/sw.js=; a new ~decide~ build changes the worker, and the app
refreshes its cache on the next load.

* Web Push

Push is off until ~web.push.enabled~ is true. Set ~web.push.subject~ to
a real ~mailto:~ or ~https:~ contact if you use Apple's push service;
the default ~mailto:decide@localhost~ may be refused. Then open
Settings on the phone, tap "Turn on notifications", and allow the
permission. The server needs outbound HTTPS to the browser's push
service (Google, Mozilla, Apple). It refuses to deliver to a loopback,
private, or link-local address, and the subscription endpoint must be
~https~.

What is pushed:

- A new open item of class approval, decision, fact, task, request, or
  inbound, or a new message on one from someone other than you or the
  system. Notes are never pushed, even if asked for.
- After the grace delay (~web.push.grace~, ~5s~), and only if the item
  is still open, not snoozed, and not read since its latest message. An
  item you read or answered in the terminal inside the window is
  skipped.
- Not while a web page is open and visible: each page sends a heartbeat
  every 30 seconds, and a heartbeat under 60 seconds old suppresses the
  push.
- Not inside the subscription's quiet hours (Settings, in that
  device's time zone), and only for the classes ticked there.
- A snoozed item is pushed when it wakes.
- Items already in the ledger when ~decide web~ starts are not pushed,
  and nothing is replayed for what arrived while it was down.

The notification has a "Snooze 1h" button and nothing else: Approve and
Decline are never offered outside the thread. Tapping it posts a
one-hour snooze with the session cookie, so it needs a live session.
Tapping the body opens the item.

State is =$XDG_STATE_HOME/decide/webpush.json=, or
=~/.local/state/decide/webpush.json=. It holds the VAPID private key
and every subscription (endpoint and keys), written mode 0600 in a 0700
directory. It is created on first use when push is enabled. Treat it as
a secret. Delete it to rotate the key; every device then has to turn
notifications on again. The public key is served at
=/api/v1/push/vapid-key=.

** Troubleshooting

- "Notifications need HTTPS": you opened the plain-http address. Use
  the ingress address.
- *iPhone and iPad* deliver push only to an installed app. In Safari
  choose Share, then Add to Home Screen, open decide from the Home
  Screen, and turn notifications on there. A Safari tab cannot.
- "Turned off on the hub": set ~web.push.enabled~ and restart.
- "Blocked for this site": allow notifications in the browser's site
  settings, then try again.
- "Send test notification" answers 410 when the push service dropped the
  device (turn notifications on again) and 502 when it refused the
  message; the server logs the cause on stderr.
- Nothing arrives, no error: a page may be open and visible, the item
  may have been read, or the time may be in quiet hours. Close the tab
  and wait out the grace delay.
- Android may hold pushes while the phone dozes or the app is
  restricted; check battery settings for Chrome.

* API

The page uses a JSON API under =/api/v1= that scripts can call with a Bearer
token. It is not versioned beyond ~v1~ and may change with the app. Reads: ~snapshot~, ~items/{id}~,
~status~, ~contacts~, ~org-tree~, ~search?q=~, and ~events~ (SSE with
~resync~, ~delta~, and ~ping~ events; ~Last-Event-ID~ or ~?since=~
resumes). Writes: ~items/{id}/{read,answer,reply,archive,done,snooze,
unsnooze}~, ~notes/archive-all~, ~send~, ~contacts/favorites~, and
~drafts/{key}~. ~answer~, ~reply~, and the other item writes accept
~writtenAt~ and a ~conflictCheck~ (~baseState~, ~baseMessageCount~,
~baseLastMessageAt~, ~baseAnswered~); a stale view gets 409 with the
current item. A draft ~PUT~ with an old ~baseRev~ saves a conflict copy
and answers 409.

The end-to-end test in =devtools/decide/web/e2e_test.go= drives this
stack, with a fake push service, through sign-in, CSRF, the event
stream, triage, answers, draft conflicts, and push suppression.
