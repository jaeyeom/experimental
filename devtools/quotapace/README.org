#+TITLE: quotapace

* What it is

~quotapace~ tracks usage of rolling quota windows, such as a coding
agent's 5-hour and 7-day limits. You record the percent used and the
reset time. It projects whether you will pass the limit before the
reset, compares usage with a plan, and fills in a checkpoint table.
It is a CLI and a Go library. Any agent or script can feed it.

Tracking issue: [[https://github.com/jaeyeom/experimental/issues/937][#937]].

* Install

#+BEGIN_SRC bash
go install github.com/jaeyeom/experimental/devtools/quotapace/cmd/quotapace@latest
#+END_SRC

* Concepts

- Reading :: a percent of one window at one time, with the reset time,
  the profile, and the source. Readings are appended to a log.
- Profile :: an account or a machine. Each profile has its own log and
  plans. Profiles are never added together.
- Plan :: a straight on-track line from a baseline to a target at the
  reset. The amber line is a number of points above it. The limit is
  100%. Without a plan, the whole window from 0% to 100% is used.
- Offset :: points added to every reading of a profile, to correct a
  known gap between the CLI and the vendor's usage page.
- Pace :: points per hour. The pace so far runs from the baseline. The
  recent pace runs over the last ~--recent~ hours (default 6h). The
  current pace is the recent pace when there is one.
- State :: green at or under on track; red when the percent at reset,
  at the current pace, passes 100%; amber otherwise; missing when the
  latest reading is older than ~--stale~ (default 6h) or the window
  has reset since.

* Example

A fictional account, ~work~, reads 40% of its 7-day window with 4 days
to the reset. That is 72 hours into the window.

#+BEGIN_SRC bash
quotapace record --profile work --window 7d --percent 40 --resets-in 4d --source statusline
quotapace status --profile work
#+END_SRC

#+BEGIN_EXAMPLE
7d 40% (on track 43%) green, projected 93%
#+END_EXAMPLE

To spend only 95% by the reset, and to see checkpoints at 09:00 and
21:00 in Seoul, start a plan from the current 40%:

#+BEGIN_SRC bash
quotapace plan start --profile work --window 7d --baseline 40 \
  --target 95 --checkpoints 09:00,21:00 --tz Asia/Seoul
quotapace report --profile work
#+END_SRC

~report~ prints Markdown: the plan, the percent now, the paces, the
projection at reset, the hours until 100%, the pace that ends at the
target, then one table row per checkpoint with on track, amber, the
limit, the actual reading, and its state.

* Commands

#+BEGIN_EXAMPLE
quotapace [dashboard] [--profile P] [--window W] [--recent 6h] [--stale 6h] [--watch D]
quotapace collect claude [--json | --jsonl] [--profile P [--auto-start]]
quotapace record --profile P --window W --percent N (--resets-in D | --resets-at T) [--source S] [--at T] [--auto-start]
quotapace record --profile P [--stdin] [--format jsonl|claude-usage] [--auto-start] < input
quotapace plan start --profile P --window W [--baseline N [--at T]] [--resets-at T | --resets-in D]
                     [--offset N] [--target N] [--amber N] [--every D] [--checkpoints HH:MM,...] [--tz Area/City]
quotapace plan set   --profile P --window W [--reset "Thu 15:00"] [--tz Area/City] [--rate R] [--offset O] [--amber N]
quotapace status [--profile P] [--json] [--recent 6h] [--stale 6h]
quotapace report [--profile P] [--window W] [--json] [--recent 6h] [--stale 6h]
quotapace check  [--profile P] [--stale 6h] [--repeat 6h] [--notify-cmd CMD] [--recent 6h]
quotapace gate   --profile P [--window 7d] [--min-gap N] [--stale 6h] [--json]
                 [--watch --every 1m --notify-cmd CMD]
#+END_EXAMPLE

Windows and durations take whole days (~7d~), a Go duration (~5h~,
~90m~), or both (~6d5h~). Times are RFC 3339.

- ~dashboard~ (default when run with no arguments) :: prints a
  plain-text per-profile, per-window dashboard with a chart of
  recorded samples and the plan's projection line to the reset,
  current usage against the plan target (state and gap), reset
  countdown, and reading freshness (marked stale past ~--stale~).
  Profiles without a plan still show their samples and reset time.
  With ~--watch D~, it refreshes every ~D~ until interrupted.
- ~collect claude~ :: fetches Claude Code's 5-hour and 7-day
  subscription usage windows from Anthropic's OAuth usage endpoint and
  prints a human summary, ~--json~ (same JSON contract accepted by
  ~record --format claude-usage~), or ~--jsonl~ (compact JSON lines
  for ~record --stdin~; ~--quotapace~ is an alias). When ~--profile P~
  is passed, it also records the windows into that profile's log
  (with optional ~--auto-start~).
- ~record~ :: appends a reading. Without ~--percent~ it reads standard
  input: JSON lines (~window~, ~percent~, ~resetsAt~ or ~resetsIn~, and
  optionally ~profile~, ~at~, ~source~), or with ~--format claude-usage~
  the JSON object ~collect claude --json~ prints. A reading after the plan's
  reset time, with a reset more than an hour later than the plan's, or
  20 points below the previous reading means the window reset. The
  plan is closed with its last percent. ~--auto-start~ starts a fresh
  plan for the new window with the same target and checkpoints;
  otherwise ~record~ prints the command to start one.
- ~plan start~ :: starts a plan. Without ~--baseline~ it starts at the
  window start at 0%. With ~--baseline N~ it starts at ~--at~ (default
  now) with N%, a re-baseline. The reset time defaults to the latest
  reading's. An existing plan for the window is closed as
  ~rebaselined~ and kept in the history. ~--offset~ sets the
  profile's offset. Checkpoints fall on the ~--checkpoints~ clock times
  each day in ~--tz~ (default UTC), so a DST change keeps the wall-clock
  time. Without them, they fall every ~--every~ from the baseline
  (default a day for windows of two days or more, otherwise an hour).
  The reset is always the last checkpoint.
- ~plan set~ :: configures a recurring schedule whose line is
  ~offset + rate * hours since window start~, capped at 100, and
  restarts automatically at each reset. ~--reset~ (for example
  ~"Thu 15:00"~) and ~--tz~ set the weekly reset boundary and override
  the reading's reset time; without ~--reset~, the latest reading's
  reset time is used. When the configured reset and the reading's
  reset disagree by more than an hour, ~status~ and ~doctor~ warn.
- ~status~ :: one line per window, such as
  ~7d 31% (on track 33%) green, projected 91%~. Without ~--profile~
  every profile is shown, each line prefixed by the profile.
- ~report~ :: the Markdown report of each window.
- ~check~ :: for cron. It is silent when every window is green. On
  amber, red, or a missing or stale reading it prints one line per
  problem and runs the notify command once with those lines on
  standard input. It does so only when a state changed, or after
  ~--repeat~ (default 6h, ~0~ never). The notify command comes from
  ~--notify-cmd~ or ~QUOTAPACE_NOTIFY_CMD~. It is split on spaces and
  run without a shell, with a 30-second limit.
- ~gate~ :: fail-closed headroom gate for loops and scripts. It reads
  only the given ~--profile~ and computes ~gap = plan_line_now -
  percent_now~ where ~plan_line_now~ is the plan line at the time of
  the latest reading. Exits ~0~ when ~gap >= N~, ~1~ when ~gap < N~,
  and ~3~ when the answer cannot be computed (no reading, reading
  older than ~--stale~, no plan, or window reset since the last
  reading). Human output is one line:
  ~gap=4.2 line=37.5 used=33.3 (7d, profile P, reading 3m old)~.
  ~--json~ prints ~{gap, budgetLine, sevenDay, fiveHour (if recorded),
  window, profile, source, readingAt, ageSeconds, exit}~. With
  ~--watch --every D --notify-cmd CMD~, ~gate~ polls every ~D~ and
  runs ~CMD~ once each time the gap crosses ~--min-gap~ in either
  direction, passing the gate JSON on standard input.

** Exit codes

| Code | status, report, check                      | gate                     | collect claude                           | Other commands |
|------+--------------------------------------------+--------------------------+------------------------------------------+----------------|
| 0    | every window green                         | gap >= min-gap (pass)    | success                                  | success        |
| 1    | the worst window is amber                  | gap < min-gap            |                                          |                |
| 2    | the worst window is red                    |                          | no usage data / custom base URL / unauth |                |
| 3    | a reading is missing or stale              | unreadable (fail closed) |                                          |                |
| 64   | usage error                                | usage error              | usage error                              | usage error    |
| 70   | any other error, such as an unreadable log | other error              | other error                              | other error    |

The code is the highest one among the selected windows.

* status --json

~status --json~ (and ~report --json~) prints one object. Without
~--profile~ it covers every profile. The schema is versioned; fields
are only added within a version.

#+BEGIN_SRC json
{
  "version": 1,
  "now": "2026-11-17T00:30:00Z",
  "profiles": [
    {
      "profile": "work",
      "offset": 0,
      "windows": [
        {
          "window": "7d",
          "state": "green",
          "latest": {"at": "…", "percent": 33, "resetsAt": "…", "source": "statusline", "ageSeconds": 1800},
          "plan": {
            "implicit": false, "baselineAt": "…", "baseline": 22, "resetsAt": "…",
            "target": 95, "amber": 5,
            "onTrack": 37.4, "amberLine": 42.4, "limit": 100,
            "nextCheckpoint": {"at": "…", "onTrack": 44.0, "amberLine": 49.0, "limit": 100, "actual": null, "actualAt": null}
          },
          "projection": {
            "at": "…", "percent": 33, "onTrack": 37.1, "amberLine": 42.1, "limit": 100,
            "paceSoFar": 0.44, "paceRecent": 0.5, "projectedAtReset": 81,
            "hoursTo100": 134, "neededPace": 0.65, "state": "green"
          },
          "history": {
            "readings": [],
            "checkpoints": [],
            "closedPlans": []
          }
        }
      ]
    }
  ]
}
#+END_SRC

- ~latest~ is null when the window has no reading. ~plan~ and
  ~projection~ are null when there is nothing to project. ~plan~ lines
  are at ~now~; ~projection~ lines are at the latest reading.
- ~paceRecent~, ~hoursTo100~, and ~neededPace~ are null when they
  cannot be computed, for example at zero pace.
- ~history.readings~ and ~history.checkpoints~ belong to the active
  plan. A checkpoint's ~actual~ is the last reading since the previous
  checkpoint, and its ~state~ uses the pace so far at that reading.
  ~closedPlans~ carry ~closed.at~, ~closed.final~, and ~closed.reason~
  (~reset time passed~, ~new window~, ~percent dropped~, or
  ~rebaselined~).

* Cron example for check

#+BEGIN_SRC bash
# Every 30 minutes: collect Claude Code usage into profile work, then alert on a problem.
*/30 * * * * quotapace collect claude --profile work --auto-start && quotapace check --notify-cmd 'mail -s quotapace you@example.com'
#+END_SRC

Any command that reads standard input works as the notify command.

* Sources

The core ~quotapace~ library and tracking engine stay agnostic to
specific coding agents. Built-in collectors live under ~collect~ and
feed readings into the same log:

- Claude Code (~quotapace collect claude~) :: reads the subscription
  OAuth login already stored by Claude Code (macOS Keychain service
  ~Claude Code-credentials~, or ~Claude Code-credentials-<sha256[:8]>~
  for custom ~CLAUDE_CONFIG_DIR~, falling back to
  ~$CLAUDE_CONFIG_DIR/.credentials.json~ / =~/.claude/.credentials.json=
  which is also the primary path on Linux) and fetches 5-hour and 7-day
  utilization from ~https://api.anthropic.com/api/oauth/usage~. Tokens
  are read-only, kept only in memory for the request, never printed or
  logged, and macOS Keychain calls invoke =/usr/bin/security= by
  absolute path. Setting ~ANTHROPIC_BASE_URL~ or
  ~ANTHROPIC_API_BASE_URL~ to a non-Anthropic origin, or using an API
  key login, returns exit code 2 with a non-subscription message.
- Antigravity CLI (~agy~) :: read the percent and the time to reset
  from its usage display and pass them to ~record~ with ~--percent~
  and ~--resets-in~. There is no collector for it yet.

When the CLI and the vendor's usage page disagree by a steady amount,
set the profile's offset with ~plan start --offset~.

* Remote accounts

Profiles stay strictly separate, and ~gate~ reads only the profile
given with ~--profile~. To track or gate a remote machine's quota from
a local controller, pipe its usage readings into a dedicated profile:

#+BEGIN_SRC bash
ssh host quotapace collect claude --jsonl | quotapace record --profile remote --stdin
quotapace plan set --profile remote --window 7d --reset "Thu 15:00" --tz America/Los_Angeles --rate 0.55 --offset 8
quotapace gate --profile remote --window 7d --min-gap 5
#+END_SRC

To watch for threshold crossings and publish gate JSON to a bus:

#+BEGIN_SRC bash
quotapace gate --profile remote --window 7d --min-gap 5 --watch --every 1m \
  --notify-cmd "agentbus send --to coordinator --stdin"
#+END_SRC

* Data layout

Data lives under ~$XDG_DATA_HOME/quotapace~, or
=~/.local/share/quotapace= when ~XDG_DATA_HOME~ is unset.

| Path                                | Contents                                |
|-------------------------------------+-----------------------------------------|
| ~profiles/<profile>/readings.jsonl~ | append-only readings, one JSON per line |
| ~profiles/<profile>/plans.json~     | offset, active plans, closed plans      |
| ~check.json~                        | the state ~check~ last notified         |

* Standard CLI protocol

~quotapace~ implements ~version [--json]~, ~update [--check] [--ref <ref>] [--json]~, ~doctor [--json] [--offline]~, and ~skill [install|uninstall|status ...]~.
