#+TITLE: claude-usage
#+DATE: 2026-11-15

* Overview

~claude-usage~ shows how much of your Claude Code subscription's
5-hour and 7-day limits you have used, and when each window resets.
It reads the login Claude Code already saved on this machine, so
there is nothing to configure. Pass ~--json~ to feed the numbers to
a status bar or a script. It works only for subscription logins
(Pro, Max, and Team), not API keys.

* Prerequisites

- A Claude Code subscription login (Pro, Max, or Team). An API-key
  login has no usage window, and the command exits 2.
- macOS reads the Keychain service ~Claude Code-credentials~. When
  ~CLAUDE_CONFIG_DIR~ is not =~/.claude=, that name gains a hyphen
  and the first 8 hex characters of the SHA-256 of the config
  directory. Claude Code must already have stored an OAuth access
  token. If the Keychain token is missing or expired, macOS reads
  the credentials file instead.
- Linux: reads =~/.claude/.credentials.json=. Other systems without
  Keychain read that same file.
- Network access to ~https://api.anthropic.com/api/oauth/usage~.

~CLAUDE_CONFIG_DIR~ replaces =~/.claude= on every OS, for both the
file and the Keychain service name.

| Variable                 | Effect                                                                                             |
|--------------------------+----------------------------------------------------------------------------------------------------|
| ~CLAUDE_CONFIG_DIR~      | Config root. Default =~/.claude=. Changes the Keychain service name and the credentials file path. |
| ~ANTHROPIC_BASE_URL~     | Checked first. An origin other than https://api.anthropic.com means no usage data (exit 2).        |
| ~ANTHROPIC_API_BASE_URL~ | Same check when ~ANTHROPIC_BASE_URL~ is unset.                                                     |

* Installation

#+BEGIN_SRC bash
go install github.com/jaeyeom/experimental/devtools/claude-usage/cmd/claude-usage@latest
#+END_SRC

That writes the binary to ~GOBIN~, or to =$(go env GOPATH)/bin= when
~GOBIN~ is unset. From this repo:

#+BEGIN_SRC bash
bazel run //devtools/claude-usage/cmd/claude-usage
#+END_SRC

* Usage

Pass ~--json~ for a single JSON object or ~--quotapace~ for JSON lines
compatible with ~quotapace record --stdin~ (mutually exclusive). Any
other positional argument is an error.

#+BEGIN_SRC bash
claude-usage
claude-usage --json
claude-usage --quotapace | quotapace record --profile work --stdin
#+END_SRC

Human output (rounded to whole percentages):

#+BEGIN_EXAMPLE
plan: Team
  5-hour    2%   resets 2026-07-24 03:29 UTC
  7-day    12%   resets 2026-07-27 22:59 UTC
#+END_EXAMPLE

A missing percentage is =?= and a missing reset time is =n/a=.

~--json~ keeps the utilization precision returned by the API without
rounding (for example ~33.3~; if the API itself only returns whole
numbers, ~--json~ keeps the integers), and adds ~fetchedAt~ (RFC 3339)
and ~source~ (~keychain:<configDir>~ or ~credentials-file:<configDir>~):

#+BEGIN_SRC json
{
  "planName": "Team",
  "fiveHour": 2.4,
  "sevenDay": 33.3,
  "fiveHourResetAt": "2026-07-24T03:29:59.312Z",
  "sevenDayResetAt": "2026-07-27T22:59:59.312Z",
  "fetchedAt": "2026-07-24T01:00:00Z",
  "source": "keychain:/Users/alice/.claude"
}
#+END_SRC

~--quotapace~ prints one compact JSON line per window (~5h~ and ~7d~) in
~quotapace record --stdin~ format (~window~, ~percent~, ~resetsAt~,
~source~, ~at~), skipping any window without both utilization and reset
time (exiting 2 if neither window has both):

#+BEGIN_EXAMPLE
{"window":"5h","percent":2.4,"resetsAt":"2026-07-24T03:29:59.312Z","source":"keychain:/Users/alice/.claude","at":"2026-07-24T01:00:00Z"}
{"window":"7d","percent":33.3,"resetsAt":"2026-07-27T22:59:59.312Z","source":"keychain:/Users/alice/.claude","at":"2026-07-24T01:00:00Z"}
#+END_EXAMPLE

* Exit codes

| Exit | When                                                                           |
|------+--------------------------------------------------------------------------------|
| 0    | Success.                                                                       |
| 2    | Not logged in, no Keychain item, and no credentials file.                      |
| 2    | The OAuth access token is expired. Log in again with Claude Code.              |
| 2    | API-key login. subscriptionType contains api, so there is no usage window.     |
| 2    | The token was rejected (HTTP 401 or 403). Log in again with Claude Code.       |
| 2    | ANTHROPIC_BASE_URL or ANTHROPIC_API_BASE_URL is not https://api.anthropic.com. |
| 1    | HTTP 429, the usage API rate limit.                                            |
| 1    | Network failure or timeout.                                                    |
| 1    | Keychain lookup failed, including access denied.                               |
| 1    | Bad arguments, or any other unexpected error.                                  |

* Security

- Credentials are read-only. The tool never refreshes or writes tokens.
- The OAuth access token stays in memory only for the API request.
- The token is never printed, and error text does not include it.
- On macOS the Keychain lookup runs =/usr/bin/security= by that absolute
  path. It does not use a shell or ~PATH~.

* Development

#+BEGIN_SRC bash
go test ./devtools/claude-usage/...
bazel test //devtools/claude-usage/...
#+END_SRC

On a machine where Claude Code is already logged in with a subscription:

#+BEGIN_SRC bash
go run ./devtools/claude-usage/cmd/claude-usage
go run ./devtools/claude-usage/cmd/claude-usage --json
go run ./devtools/claude-usage/cmd/claude-usage --quotapace
#+END_SRC

Unit tests cover formatting, the Keychain service name, credential
parsing, and HTTP status mapping. They use fake transports, so CI does
not touch a Keychain or the network.

* Standard CLI protocol

~claude-usage~ implements ~version [--json]~, ~update [--check] [--ref <ref>] [--json]~, ~doctor [--json] [--offline]~, and ~skill [install|uninstall|status ...]~.
