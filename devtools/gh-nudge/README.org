** Prerequisites

1. [[https://cli.github.com/][Github CLI]] installed and authenticated
2. Slack API token for sending notifications

*** Obtaining a Slack API Token

To get a Slack API token for GitHub Nudge:

1. *Create a Slack App*:
   - Go to the [[https://api.slack.com/apps][Slack API website]]
   - Click "Create New App"
   - Choose "From scratch"
   - Name your app (e.g., "GitHub Nudge") and select your workspace
   - Click "Create App"

2. *Add Bot Permissions*:
   - In the left sidebar, click on "OAuth & Permissions"
   - Scroll down to "Scopes" section
   - Under "Bot Token Scopes", add the following permissions:
     - ~chat:write~ (to send messages)
     - ~im:write~ (to send direct messages)
     - ~users:read~ (to look up user information)

3. *Install App to Workspace*:
   - Scroll up to the top of the "OAuth & Permissions" page
   - Click "Install to Workspace"
   - Review the permissions and click "Allow"

4. *Get Your Bot Token*:
   - After installation, you'll be redirected back to the "OAuth & Permissions"
     page
   - Copy the "Bot User OAuth Token" that starts with ~xoxb-~
   - This is the token you'll need to add to your configuration file under
     ~slack.token~

*Note*: Slack tokens are sensitive credentials. Consider using environment
variables or a secrets manager in production environments rather than hardcoding
the token in your configuration file.

** Configuration

GitHub Nudge supports two configuration formats: *Pkl* (recommended) and *YAML*.
The configuration file should be placed at ~$HOME/.config/gh-nudge/~.

*** Pkl Configuration (Recommended)

[[https://pkl-lang.org/][Pkl]] is a configuration language that provides type safety, validation, and
better IDE support. New users should prefer Pkl configuration.

Create a configuration file at ~$HOME/.config/gh-nudge/config.pkl~:

#+begin_src pkl
amends "package://github.com/jaeyeom/experimental/devtools/gh-nudge/pkl/Config.pkl"

github {
  owner = "organization-name"  // Optional, defaults to authenticated user
  repos {
    "repo-name-1"
    "repo-name-2"
  }
}

slack {
  // Read token from environment variable for security
  token = read("env:SLACK_TOKEN")
  default_channel = "#code-reviews"

  // GitHub username to Slack user ID mapping (for @mentions)
  // User IDs typically start with "U" (e.g., "U12345")
  user_id_mapping {
    ["github-username-1"] = "U12345"
    ["github-username-2"] = "U67890"
  }

  // GitHub username to Slack DM channel ID mapping
  // DM channel IDs typically start with "C" (e.g., "C12345")
  dm_channel_id_mapping {
    ["github-username-1"] = "C12345"
    ["github-username-2"] = "C67890"
  }

  // Channel routing based on file patterns
  channel_routing {
    new {
      pattern = "frontend/.*\\.js$"
      channel = "#frontend"
    }
    new {
      pattern = "backend/.*\\.go$"
      channel = "#backend"
    }
    new {
      pattern = "docs/.*"
      channel = "#documentation"
    }
  }
}

settings {
  reminder_threshold_hours = 24  // Hours between reminders for the same outstanding review request
  working_hours_only = true
  dm_by_default = true
  // Skip nudging unless the PR has all of these labels. Empty means no requirement.
  require_labels {
    "ready-for-review"
  }
  // Skip nudging if the PR has any of these labels. Empty means no skip filter.
  skip_labels {
    "wip"
    "do-not-nudge"
  }
  // Skip nudging these GitHub users. They do not need a Slack mapping.
  skip_users {
    "bot-account"
    "contractor-who-opted-out"
  }
  // Also require each label to have been on the PR this long since it was last added.
  // Empty means no age requirement. Every entry is required.
  require_label_ages {
    new {
      label = "X"
      min_hours = 24
    }
  }
  // Hours since this reviewer was first requested. Zero disables the gate.
  // A later request does not restart the clock.
  min_first_review_request_hours = 24
  // gh-merge skips a pull request that has any of these labels.
  // gh-nudge ignores this list. Empty means no label blocks a merge.
  block_merge_labels {
    "do-not-merge"
  }
  // gh-merge queue: check names that must be green. Empty turns the gate off.
  required_checks {
    "ci"
  }
  // Regular expressions matched against a failing merge-queue log. A match is a hint.
  flake_signatures {
    "connection reset"
  }
  // Comment template required before requeue. {event_id} and {class}.
  // Class is our-code, flake, or infra.
  rca_marker = "RCA {event_id} class={class}"
  // Refuse when earlier flake or infra requeues are greater than this.
  max_requeues = 2
}

// gh-merge only. One entry per <owner>/<repo>.
// A set field replaces settings. An omitted field inherits.
// An explicit empty list does not inherit. gh-nudge ignores this mapping.
repo_settings {
  ["<owner>/<repo>"] {
    required_checks {
      "lint"
    }
  }
}
#+end_src

**** Benefits of Pkl

- *Type Safety*: Configuration errors are caught at load time
- *Validation*: Built-in constraints (e.g., ~reminder_threshold_hours~ must be > 0)
- *IDE Support*: Autocompletion and inline documentation
- *Environment Variables*: Securely read secrets with ~read("env:VAR_NAME")~
- *Schema Documentation*: Self-documenting configuration structure

*** YAML Configuration (Legacy)

YAML configuration is still supported for backwards compatibility. If both
~config.pkl~ and ~config.yaml~ exist, Pkl takes precedence.

Create a configuration file at ~$HOME/.config/gh-nudge/config.yaml~:

#+begin_src yaml
  github:
    owner: "organization-name"  # Optional, defaults to authenticated user
    repos:
      - "repo-name-1"
      - "repo-name-2"

  slack:
    token: "your-slack-token"
    default_channel: "#code-reviews"  # Fallback channel if no patterns match

    # GitHub username to Slack user ID mapping (for @mentions in messages)
    # User IDs typically start with "U" (e.g., "U12345")
    user_id_mapping:
      "github-username-1": "U12345"
      "github-username-2": "U67890"

    # GitHub username to Slack DM channel ID mapping (for sending direct messages)
    # DM channel IDs typically start with "C" (e.g., "C12345")
    dm_channel_id_mapping:
      "github-username-1": "C12345"
      "github-username-2": "C67890"

    # Channel routing based on file patterns
    channel_routing:
      - pattern: "frontend/.*\\.js$"
        channel: "#frontend"
      - pattern: "backend/.*\\.go$"
        channel: "#backend"
      - pattern: "docs/.*"
        channel: "#documentation"

  settings:
    reminder_threshold_hours: 24  # Once per period for the same outstanding review request
    working_hours_only: true
    message_template: "Hey <@{slack_id}>, the PR '{title}' has been waiting for your review for {hours} hours. {url}"
    dm_by_default: true  # Send DMs to reviewers by default
    require_labels:  # Skip unless the PR has all of these labels
      - "ready-for-review"
    skip_labels:  # Skip if the PR has any of these labels
      - "wip"
      - "do-not-nudge"
    skip_users:  # Skip these GitHub users (no Slack mapping required)
      - "bot-account"
      - "contractor-who-opted-out"
    require_label_ages:  # Also require each label to have aged since it was last added
      - label: "X"
        min_hours: 24
    # Hours since this reviewer was first requested. 0 disables the gate.
    # A later request does not restart the clock.
    min_first_review_request_hours: 24
    block_merge_labels:  # gh-merge skips a PR with any of these labels
      - "do-not-merge"
    required_checks:  # gh-merge queue refuses when empty unless --allow-no-required-checks
      - "ci"
    flake_signatures:  # hints matched against a failing log
      - "connection reset"
    rca_marker: "RCA {event_id} class={class}"  # {class} is our-code, flake, or infra
    max_requeues: 2
  # gh-merge only. A set field replaces settings for <owner>/<repo>.
  # An omitted field inherits. An empty list does not inherit.
  repo_settings:
    "<owner>/<repo>":
      required_checks:
        - "lint"
#+end_src

*Note*: YAML support may be deprecated in a future release. Consider migrating
to Pkl for new installations.

** gh-approve

~gh-approve~ approves pull requests that match rules you write in config. It
approves as the logged-in ~gh~ user, through the ~gh~ CLI. It leaves every
other pull request for a human. It runs no LLM review itself, but a rule can
run a command of yours as a last check. See [[*Agent command][Agent command]].

It looks only at open pull requests that request you *as an individual*. It
finds them with the search ~user-review-requested:@me~. It ignores a pull
request that requests only a team you belong to.

#+begin_src shell
  # Dry run (the default): print what would be approved. Nothing is approved.
  gh-approve

  # Approve for real
  gh-approve --apply

  # Evaluate one pull request and print every condition with the value it saw
  gh-approve --pr acme/widgets#12 --explain
  gh-approve --pr https://github.com/acme/widgets/pull/12
#+end_src

The output is a table with the pull request, the action, the matched rule, and
the title. When no rule matches, the rule column shows ~manual~. Then, for each
rule, it shows the first condition that failed.

*** Rules

Add rules to the ~approve~ section of ~config.pkl~. The conditions in one rule
are ANDed. Rules are ORed, and the first rule that matches is used. Every
condition is optional. An empty list or an unset limit adds no condition.

| Condition                | Meaning                                                                           |
|--------------------------+-----------------------------------------------------------------------------------|
| ~repos~                  | Repositories as ~owner/name~ or globs, such as ~acme/*~                           |
| ~paths_all_match~        | Globs. Every changed file must match one of them                                  |
| ~paths_none_match~       | Globs. No changed file may match any of them, such as CI config, infra, lockfiles |
| ~max_changed_lines~      | Maximum added plus deleted lines                                                  |
| ~max_added_lines~        | Maximum added lines                                                               |
| ~max_files~              | Maximum changed files                                                             |
| ~pure_deletion~          | The pull request adds no lines                                                    |
| ~authors_allow~          | The author must be one of these logins                                            |
| ~authors_deny~           | The author must not be one of these logins                                        |
| ~labels_required~        | Every one of these labels must be present                                         |
| ~labels_forbidden~       | None of these labels may be present                                               |
| ~required_approvals_by~  | Each login's latest review on the current head SHA must be ~APPROVED~             |
| ~checks~                 | ~"green"~ or ~"allow_pending"~. See below                                         |
| ~not_draft~              | Default ~true~. A draft does not match                                            |
| ~max_unresolved_threads~ | Default ~0~                                                                       |
| ~agent_command~          | A command, as argv, that must print ~approve~. Runs last. See below               |
| ~agent_timeout~          | Default ~120.s~. How long ~agent_command~ may run                                 |

Globs use ~**~ for any number of directories. Logins match without regard to
case. Labels match exactly, including case. For ~required_approvals_by~, a
~COMMENTED~ review does not replace an earlier approval on the same head.

~checks = "green"~ requires that no check failed and every required check
passed. When the head has no required check, every check counts as required.
~checks = "allow_pending"~ requires only that no check failed. A failed check
always fails.

Global settings:

- ~body~ is the approval body. Default ~LGTM~. The matching rule name is
  appended as ~<!-- gh-approve: <rule> -->~.
- ~skip_already_approved~ skips a pull request you already approved at the
  current head. Default ~true~.
- gh-approve never approves a pull request you authored. This is always on and
  cannot be configured.

Starter rule shapes. These are examples. Nothing is hard-coded.

#+begin_src pkl
  approve {
    rules {
      // Only files under one internal dashboard directory.
      new {
        name = "internal-dashboard"
        paths_all_match { "tools/internal-dashboard/**" }
        checks = "green"
      }
      // Pure deletions.
      new {
        name = "pure-deletion"
        pure_deletion = true
        checks = "green"
      }
      // At most 50 changed lines outside CI and infra paths.
      new {
        name = "small-outside-infra"
        max_changed_lines = 50
        paths_none_match { ".github/**"; "infra/**"; "**/*.lock"; "**/go.sum" }
        checks = "green"
      }
      // Small pull requests, up to 200 lines, that carry an "internal-only" label.
      new {
        name = "internal-only"
        max_changed_lines = 200
        labels_required { "internal-only" }
        checks = "allow_pending"
      }
    }
  }
#+end_src

The ~approve~ section is supported only in Pkl config. A YAML config that has
an ~approve~ key fails to load.

*** Agent command

A rule may set ~agent_command~, such as a script that asks an LLM to review
the diff. It is a list of arguments, run directly, not through a shell. It
runs only when every other condition of the rule passed and no earlier rule
matched, and never for a pull request that is skipped anyway, such as your own.
It runs in dry run too.

#+begin_src pkl
  new {
    name = "docs-reviewed-by-agent"
    paths_all_match { "docs/**" }
    checks = "green"
    agent_command { "/home/me/bin/review-agent"; "--strict" }
    agent_timeout = 60.s
  }
#+end_src

Its stdin is one JSON object:

#+begin_src json
  {
    "rule": "docs-reviewed-by-agent",
    "pr": {"repo": "acme/widgets", "number": 12, "url": "...", "title": "...",
           "author": "alice", "headSha": "...", "draft": false, "additions": 3,
           "deletions": 1, "changedFiles": 1, "labels": ["docs"]},
    "files": [{"path": "docs/a.md", "additions": 3, "deletions": 1}],
    "diff": "diff --git a/docs/a.md b/docs/a.md\n..."
  }
#+end_src

~filesError~ is added when the file list could not be read completely. The
command must print one JSON object, ~{"decision": "approve" | "defer",
"reason": "..."}~. ~approve~ lets the rule match. ~defer~ leaves the pull
request for a human, and the reason is shown in the table. A non-zero exit, a
timeout, output that is not one JSON object, or an unknown decision all count
as ~defer~, with the error as the reason. A diff that cannot be read defers
without running the command. On timeout, the command's whole process group is
killed.

*** Safety

- *Dry run by default.* Only ~--apply~ approves.
- *Head pinning.* gh-approve evaluates one head SHA. With ~--apply~, it reads
  the head again just before it approves. If the head moved, it skips the pull
  request and says so. The approval is posted with ~gh api~ to the pull
  request reviews endpoint, with ~event=APPROVE~ and ~commit_id~ set to the
  evaluated head SHA.
- *Fail loud.*
  - A ~gh~ error stops that pull request with a clear error. The other pull
    requests still run, and gh-approve exits non-zero.
  - An unknown config key is a load error.
  - Data that cannot be read, such as missing review thread or check data or a
    truncated file list, never counts as a met condition. The condition fails
    with ~unreadable:~ and the reason.
- *Audit log.* Each decision is appended as one JSON line to
  =~/.config/gh-nudge/approve-log.jsonl=. A line has ~time~, ~pr~, ~url~,
  ~title~, ~headSha~, ~rule~ (~null~ when none matched), ~rules~ (each rule's
  per-condition ~pass~ and ~saw~, and ~agent~ with ~decision~, ~reason~ and
  ~durationMs~ when the rule's agent command ran), ~action~, and ~reason~.
  ~--explain~ shows the same agent decision, reason and duration. The action is
  ~approved~, ~would_approve~, ~skipped~, ~manual~, or ~error~.
