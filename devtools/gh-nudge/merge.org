#+TITLE: gh-merge - Automated GitHub PR Merge Tool
#+AUTHOR: Jaehyun Yeom

* Github Merge

** Overview

~gh-merge~ is a command-line utility that finds pull requests with no pending
review requests and are ready to merge (status: MERGEABLE). It can automatically
merge these PRs and optionally delete the source branch after merging.

** Features

- Find PRs that have no pending review requests
- Verify PRs are in a mergeable state
- Merge PRs automatically with optional branch deletion
- Skip PRs that have a configured block label, such as ~do-not-merge~
- Support for dry-run mode to preview actions without executing them
- Reuse existing configuration from ~gh-nudge~

** Usage

#+begin_src shell
  # List mergeable PRs without taking action
  gh-merge list

  # Stream verdicts with skip reasons and debug timing logs to stderr
  gh-merge -v
  gh-merge --log-level debug list

  # Limit listing to specific PRs (with --pr or positional PR refs)
  gh-merge -v --pr 12 --pr 34
  gh-merge -v 12 acme/widgets#34

  # Bound the overall listing time (prints partial results + not checked count)
  gh-merge -v --timeout 30s

  # Merge all eligible PRs
  gh-merge --auto

  # Merge and delete branches after merging
  gh-merge --auto -d

  # Dry run to preview what would be merged
  gh-merge --auto --dry-run

  # Use a custom config file
  gh-merge --config /path/to/config.pkl

  # Enqueue one pull request. The argument is owner/repo#n or a pull request URL.
  gh-merge queue acme/widgets#12

  # A stack whose enqueue answer requires the async API also queues pull
  # requests below it. That needs an explicit flag, unless the pull request
  # targets the default branch and no open pull request is below it.
  gh-merge --include-downstack queue acme/widgets#12

  # Wait until each pull request merges, is ejected, or times out.
  gh-merge watch acme/widgets#12 acme/widgets#13
  gh-merge --json watch acme/widgets#12

  # Print the failure evidence for the latest removal, or one removal event.
  gh-merge evidence acme/widgets#12
  gh-merge evidence acme/widgets#12 --event <id> --json
#+end_src

A pull request is not merged when it has any label listed in
~settings.block_merge_labels~, for example ~do-not-merge~. ~--force~ does not
override that label. ~gh-merge list~ still prints the pull request and marks
the label that blocks it.

~gh-merge list~ prints ~checking N PRs~ to stderr at the start and streams
each pull request's verdict to stdout (flushed per line) as soon as it is
known. Cheap filters (draft, review requests, non-mergeable state, and
blocking labels when ~mergeable~ is ~UNKNOWN~) run before refreshing
~UNKNOWN~ mergeable state, and mergeable state plus ~statusCheckRollup~ for
candidates are fetched in batched GraphQL queries (up to 50 PRs per query;
any per-PR fallback runs with bounded concurrency respecting
~GH_THROTTLE_MAX_CONCURRENT~). Passing ~--pr <ref>~ (repeatable) or
positional pull request numbers/refs skips listing all authored PRs and
queries only those pull requests. Setting ~--timeout <duration>~ (or
~-timeout~) sets an overall deadline: when exceeded, ~list~ prints all
decided results so far followed by ~not checked: <N>~ and exits non-zero.
~--log-level~ (~debug~, ~info~, ~warn~, ~error~) or ~-v~ logs phase and
per-call durations to stderr.

~gh-merge queue~ checks one pull request, prints removal evidence when the
latest merge-queue timeline event is a removal, and then calls
~enqueuePullRequest~. ~--when-green~ waits only when every preflight problem
is a required check still pending on the current head, or missing because CI
has not reported it yet (right after a push or base retarget). It polls with
backoff and enqueues once those checks appear and pass. The wait timeout is a Go duration and
defaults to 2h; ~--timeout~ overrides it. Pending conclusions are an empty
conclusion, PENDING, EXPECTED, QUEUED, IN_PROGRESS, and WAITING. FAILURE,
CANCELLED, TIMED_OUT, and ACTION_REQUIRED refuse immediately. A draft, block label, missing approval, unresolved thread, base or stack
refusal, or RCA refusal also refuses immediately. The wait records the head
SHA and reloads the pull request between polls. A transient load error
retries until the timeout. The wait aborts without enqueueing when a required
check fails, the head SHA changes, approval is lost, an unresolved thread
appears, another preflight problem appears, or the timeout is reached. A
timeout names the required checks still missing or not green. Without
~--when-green~, a missing check refuses immediately.
~--dry-run~ does not poll: pending or missing checks report ~would-wait~, and a green
pull request still reports ~would-enqueue~. ~--json~ includes that result.
~queue~ and ~queue --dry-run~ run one shared preflight and print the same
gate line, for example
~latest queue event: removed <id> at <time>; RCA: flake (matched)~.
~--json~ includes it as ~gate~. The shared preflight also reads GitHub's
~mergeable~. CONFLICTING refuses with ~pull request has merge conflicts~.
UNKNOWN is re-read after 2s, 4s, 8s, then every 16s, for up to 60s, and
refuses if it is still UNKNOWN. With ~--when-green~, a still-UNKNOWN state is
pending instead, and the wait aborts if it turns CONFLICTING.
~gh-merge dequeue~ polls
the timeline for up to 30s until the removal appears, then prints
~Dequeued~. If the removal does not appear, it also warns that ~queue~
checks may be stale, and still exits 0.
Queue does not classify the failure or write the RCA
comment. ~required_checks~, ~flake_signatures~, ~rca_marker~, and
~max_requeues~ come from config. Empty ~required_checks~ makes ~queue~ refuse
unless ~--allow-no-required-checks~ is set. That flag does not skip a draft,
approval, a block label, unresolved threads, or the RCA gate. ~queue~ also
refuses when ~owner/name~ is not ~github.owner~ plus a name in ~github.repos~.
A flake-signature match is printed as a hint, not a verdict. ~gh-merge watch~
decides merged, ejected, or timeout from the timeline. ~isInMergeQueue=false~
alone is not an ejection. ~--json~ prints one result per pull request:
~merged~, ~ejected:<reason>~, or ~timeout~. The command exits non-zero unless
every pull request merged. For an ejection, ~--json~ also prints ~event_id~
(the removal event), ~commit~ (the merge-group commit), and ~rca_class~: the
class of the gh-merge RCA marker for that event (~our-code~, ~flake~,
~infra~, or ~manual~), or ~unclassified~ when none matches. Pass ~event_id~
to ~gh-merge rca --event~.

~watch~ exits with the code of the first pull request that did not merge:

| code | meaning                     |
|------+-----------------------------|
|    0 | every pull request merged   |
|    2 | ejected for failed checks   |
|    3 | ejected for merge conflict  |
|    4 | removed by hand (~manual~)  |
|    5 | timeout                     |
|    1 | other ejections and errors  |

~gh-merge evidence~ prints the same removal evidence as ~queue~ for the
latest removal, or for ~--event <id>~. It skips checks cancelled after the
ejection. ~--json~ prints one object: ~event_id~, ~reason~, ~commit~, the
~check~ name and URLs, the ~workflow~, the failed ~job~, ~failing_tests~
(from CircleCI test results when available), an ~excerpt~ of the lines
~failure_log_pattern~ matches (at most 50 lines and 8 KiB, with a ~log_url~),
the other jobs of the workflow as ~siblings~, ~infra~, and ~flake_hints~.
Log text has ANSI escapes removed in both text and JSON output.

*** RCA marker format

~gh-merge rca~ ends its comment with the ~rca_marker~ template, for example
~<!-- gh-merge-rca {event_id} class={class} -->~. After the last placeholder
the marker may carry optional ~ key=value~ tokens, before the rest of the
template:

#+begin_example
<!-- gh-merge-rca <event_id> class=<class> [tool=<name>] [commit=<sha>] [job=<job>] [test=<test>] [supersedes=<comment id>] -->
#+end_example

- ~class~ is ~our-code~, ~flake~, ~infra~, or ~manual~.
- ~tool~ names the tool that wrote the marker. A marker without ~tool=~ was
  written by gh-merge. ~gh-merge rca~ never writes it.
- ~commit~, ~job~, and ~test~ are the merge-group commit, the failed job, and
  the first failing test. ~gh-merge rca~ adds each one the evidence has.
- ~supersedes~ marks a correction of an earlier RCA comment.

A key is a letter followed by letters, digits, ~_~, or ~-~. A value has no
spaces and no ~-->~; ~gh-merge rca~ turns whitespace into ~_~ and ~-->~ into
~--~. Unknown keys are ignored. A malformed token, such as a bare word or an
empty value, makes the line not a marker. When the template ends with a
placeholder, the marker must end its line. Markers without keys match as
before.

The requeue gate reads only gh-merge markers. For one removal, a marker with
~supersedes=~ replaces every earlier marker for it. Otherwise ~our-code~ wins
over the other classes, and the last class is used. A marker with
~tool=<other>~ never satisfies the gate and is never counted as a requeue.
~evidence~ prints it as ~RCA from <tool>: <class> (context, not counted)~,
~evidence --json~ lists it under ~rca_context~, and ~watch --json~ lists it
under ~rcaContext~.

~manual~ is for a pull request someone removed from the queue by hand
(removal reason ~manual~). It allows the requeue, needs no CI evidence, and,
like ~our-code~, the requeue after it does not count toward ~max_requeues~.
~gh-merge rca --class manual~ refuses unless the removal's reason is
~manual~.

Another tool can write a marker for gh-merge readers with at least the event
id, ~class=~, and ~tool=~.

*** One RCA per removal

~gh-merge rca~ posts at most one RCA comment for a removal. When a gh-merge
marker for the latest removal already exists, it refuses and names the
current class. Markers with ~tool=<other>~ are not ours and never count. To
correct an RCA, pass one of:

- ~--update~ edits our latest RCA comment for the removal in place, with the
  new body and class. A ~supersedes=~ key on that marker is kept.
- ~--supersedes~ posts a new comment whose marker carries
  ~supersedes=<comment id>~, the id of our latest RCA comment for the
  removal. The newest superseding marker's class wins for that removal.

Both refuse when there is no RCA to correct. They cannot be used together.

~gh-merge rca --check <owner/repo#n|url|number> [--event <id>] [--json]~
reports the RCA for the latest removal, or for ~--event~, and never posts.
It prints ~RCA for <id>: <class>~, ~RCA for <id>: none~, or
~RCA for <id>: <class> (superseded)~ when a gh-merge marker for the removal
carries ~supersedes=~, followed by any other-tool markers as context.
~--json~ prints ~pullRequest~, ~eventId~, ~exists~, ~class~ (omitted when
none), ~superseded~, and ~rcaContext~.

*** Handle an ejection

#+begin_example
gh-merge handle-ejection <owner/repo#n|url|number> --class our-code|flake|infra|manual --file body.md [--event <id>] [--when-green] [--dry-run] [--json]
#+end_example

~handle-ejection~ runs the mechanical steps after an ejection in order. The
caller still picks the class and writes the RCA text.

1. It resolves the removal: ~--event~, or the latest removal.
2. If the removal has no gh-merge RCA, it posts one the same way as ~rca~.
   If it has one with the same class, it leaves it. If it has one with a
   different class, it refuses and suggests ~rca --supersedes~.
3. Unless the pull request merged, is in the merge queue, or was added to it
   after the removal, it runs the ~queue~ preflight and RCA gate and enqueues
   once when they allow it. ~--when-green~ passes through. For ~our-code~ on
   an unchanged head the gate refuses and the message says to push a fix
   first. ~manual~ requeues outside ~max_requeues~, as with ~queue~.

Running it again for the same removal posts nothing and enqueues nothing.
~--dry-run~ posts nothing and enqueues nothing; the gate still decides as if
the RCA were posted. It exits 0 when it acted or had nothing to do, 2 when
the queue preflight or RCA gate refused, and 1 on errors, including a class
mismatch. ~--json~ prints one object with ~pullRequest~, ~eventId~,
~class~, ~dryRun~, and ~steps~. Each step has a ~name~ (~event~, ~rca~, or
~queue~), an ~action~, such as ~posted~, ~would-post~, ~kept~, ~refused~,
~enqueued~, ~would-enqueue~, or ~already-queued~, and a ~detail~. The
~queue~ step also carries the ~queue --json~ result, with its ~requeue~
decision. Other output goes to stderr.

** Configuration and Setup

Please see [[file:README.org][README.org]] file for the full configuration.

~gh-merge~ loads ~-config~ when it is set, otherwise ~GH_MERGE_CONFIG~,
otherwise ~$HOME/.config/gh-merge/config.pkl~ when that file exists,
otherwise the ~gh-nudge~ default at ~$HOME/.config/gh-nudge/config.pkl~.
~gh-nudge~ itself still uses only that default.

~repo_settings~ overrides the global settings for one ~<owner>/<repo>~ key.
~queue~, ~watch~, and ~rca~ use the entry for the target repository. ~list~
and ~merge~ use the entry for the pull request they are handling.
A field set on the entry replaces the global field. A field left unset
inherits it. An explicit empty list is set, and it does not inherit.
~github.repos~ is unchanged. Empty effective ~required_checks~ still makes
~queue~ refuse unless ~--allow-no-required-checks~ is set, including when the
entry sets that list to empty and the global list is not. Readiness text
includes ~settings from: <owner>/<repo>~ or ~settings from: global~. ~queue
-json~ adds ~settingsFrom~. ~watch -json~ and ~rca -json~ include ~config~ and
~settingsFrom~.

The relevant sections for GitHub integration are:

#+begin_src pkl
github {
  owner = "your-github-org"
  repos {
    "repo1"
    "repo2"
  }
}

settings {
  // Skip merging a pull request that has any of these labels.
  // Empty means no label blocks a merge. Names match exactly, including case.
  // --force does not override a block label.
  block_merge_labels {
    "do-not-merge"
  }
}

// A set field replaces settings for this repository. An omitted field inherits.
// An empty list does not inherit. The key is <owner>/<repo>.
repo_settings {
  ["<owner>/<repo>"] {
    required_checks {
      "lint"
    }
  }
}
#+end_src

~gh-nudge~ ignores ~block_merge_labels~. The other merge keys
(~required_checks~, ~flake_signatures~, ~rca_marker~, ~max_requeues~,
~repo_settings~) are on this page. Nudge keys are in
[[file:pkl/Config.pkl][Config.pkl]] and [[file:README.org][the suite guide]].
