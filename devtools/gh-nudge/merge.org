#+TITLE: gh-merge - Automated GitHub PR Merge Tool
#+AUTHOR: Jaehyun Yeom

* Github Merge

** Overview

~gh-merge~ is a command-line utility that finds pull requests with no pending
review requests and are ready to merge (status: MERGEABLE). It can automatically
merge these PRs and optionally delete the source branch after merging.

** Features

- Find PRs that have no pending review requests
- Verify PRs are in a mergeable state
- Merge PRs automatically with optional branch deletion
- Skip PRs that have a configured block label, such as ~do-not-merge~
- Support for dry-run mode to preview actions without executing them
- Reuse existing configuration from ~gh-nudge~

** Usage

#+begin_src shell
  # List mergeable PRs without taking action
  gh-merge list

  # Merge all eligible PRs
  gh-merge --auto

  # Merge and delete branches after merging
  gh-merge --auto -d

  # Dry run to preview what would be merged
  gh-merge --auto --dry-run

  # Use a custom config file
  gh-merge --config /path/to/config.pkl

  # Enqueue one pull request. The argument is owner/repo#n or a pull request URL.
  gh-merge queue acme/widgets#12

  # A stack whose enqueue answer requires the async API also queues pull
  # requests below it. That needs an explicit flag.
  gh-merge --include-downstack queue acme/widgets#12

  # Wait until each pull request merges, is ejected, or times out.
  gh-merge watch acme/widgets#12 acme/widgets#13
  gh-merge --json watch acme/widgets#12
#+end_src

A pull request is not merged when it has any label listed in
~settings.block_merge_labels~, for example ~do-not-merge~. ~--force~ does not
override that label. ~gh-merge list~ still prints the pull request and marks
the label that blocks it.

~gh-merge queue~ checks one pull request, prints removal evidence when the
latest merge-queue timeline event is a removal, and then calls
~enqueuePullRequest~. It does not classify the failure or write the RCA
comment. ~required_checks~, ~flake_signatures~, ~rca_marker~, and
~max_requeues~ come from config. Empty ~required_checks~ makes ~queue~ refuse
unless ~--allow-no-required-checks~ is set. That flag does not skip a draft,
approval, a block label, unresolved threads, or the RCA gate. ~queue~ also
refuses when ~owner/name~ is not ~github.owner~ plus a name in ~github.repos~.
A flake-signature match is printed as a hint, not a verdict. ~gh-merge watch~
decides merged, ejected, or timeout from the timeline. ~isInMergeQueue=false~
alone is not an ejection. ~--json~ prints one result per pull request:
~merged~, ~ejected:<reason>~, or ~timeout~. The command exits non-zero unless
every pull request merged.

** Configuration and Setup

Please see [[file:README.org][README.org]] file for the full configuration.

~gh-merge~ loads ~-config~ when it is set, otherwise ~GH_MERGE_CONFIG~,
otherwise ~$HOME/.config/gh-merge/config.pkl~ when that file exists,
otherwise the ~gh-nudge~ default at ~$HOME/.config/gh-nudge/config.pkl~.
~gh-nudge~ itself still uses only that default.

~repo_settings~ overrides the global settings for one ~<owner>/<repo>~ key.
~queue~, ~watch~, and ~rca~ use the entry for the target repository. ~list~
and ~merge~ use the entry for the pull request they are handling.
A field set on the entry replaces the global field. A field left unset
inherits it. An explicit empty list is set, and it does not inherit.
~github.repos~ is unchanged. Empty effective ~required_checks~ still makes
~queue~ refuse unless ~--allow-no-required-checks~ is set, including when the
entry sets that list to empty and the global list is not. Readiness text
includes ~settings from: <owner>/<repo>~ or ~settings from: global~. ~queue
-json~ adds ~settingsFrom~. ~watch -json~ and ~rca -json~ include ~config~ and
~settingsFrom~.

The relevant sections for GitHub integration are:

#+begin_src pkl
github {
  owner = "your-github-org"
  repos {
    "repo1"
    "repo2"
  }
}

settings {
  // Skip merging a pull request that has any of these labels.
  // Empty means no label blocks a merge. Names match exactly, including case.
  // --force does not override a block label.
  block_merge_labels {
    "do-not-merge"
  }
}

// A set field replaces settings for this repository. An omitted field inherits.
// An empty list does not inherit. The key is <owner>/<repo>.
repo_settings {
  ["<owner>/<repo>"] {
    required_checks {
      "lint"
    }
  }
}
#+end_src

~gh-nudge~ ignores ~block_merge_labels~. See [[file:README.org][README.org]] for the
rest of the shared configuration.

** Known Issues
*** Sometimes it needs to run 2 times
- Sometimes gh-merge merge should run 2 times to find the PRs to merge. I didn't
  dig into it, but that's probably because some reviewer team list is not
  processed (removed) until it is queried on the GitHub side.
