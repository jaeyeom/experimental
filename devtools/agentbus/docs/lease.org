Only needed if several agents share one git checkout.
The lease says which agent may change that checkout right now; everyday commands are in [[file:../README.org][the agentbus guide]].

* Workdir lease

Several agents can share one checkout. The lease says who may change
it right now. Each machine lists its guarded checkouts, the git
top-levels that need the lease, in its config:

#+BEGIN_SRC toml
lease_checkouts = ["/home/u/src/repo"]
#+END_SRC

Every ~lease~ subcommand but ~hook~ and ~install-hook~ takes ~--path~ (default: the current
directory, resolved to its git top-level) and ~--json~. The checkout
key is ~<machine>:<git top-level>~, such as ~local:/home/u/src/repo~.
A path outside every guarded checkout, or in a separate repository or
worktree nested inside one, is not guarded.

#+BEGIN_SRC bash
agentbus lease claim --for 40m --why "issue 623"
agentbus lease extend --for 20m
agentbus lease leave
agentbus lease status --all
agentbus lease check --path src/main.go
agentbus lease release
agentbus lease adopt
agentbus lease pause --with w1:p2
agentbus lease unshare w1:p2
agentbus lease resume --as-is
agentbus lease install-hook
#+END_SRC

| Subcommand | What it does |
|------------+--------------|
| ~claim --for <d> [--urgent] [--why <text>]~ | Take a free checkout, or join its queue. Never blocks. Prints ~granted until HH:MM; checkout on <branch>~ (or ~checkout at <sha> (detached)~) or ~queued, position N (holder X, bid ends HH:MM)~. Re-claimed by the same holder within 1 hour of a release that switched branches, it adds ~(you were on <branch> when you released at HH:MM)~; ~--json~ adds ~branch~ and ~previous_branch~. |
| ~extend --for <d>~ | Holder only. Move the soft deadline to now plus ~--for~. |
| ~leave~ | Leave the queue. |
| ~status [--all]~, ~status --guarded~ | Holder, deadline, state, and queue. ~--all~ lists every checkout the daemon has seen. ~--guarded~ only tells whether ~--path~ is in a guarded checkout, from this machine's ~lease_checkouts~, without contacting the daemon or hub; it exits 0 either way, and ~--json~ prints ~{"guarded": true, "checkout": "<key>"}~ or ~{"guarded": false}~. Tools such as prsync use it to skip unguarded checkouts. |
| ~check~ | Exit 0 when you hold the lease or the path is not guarded, 1 with a one-line reason when you do not, 3 when it cannot tell. |
| ~release~ | Holder only. Leave the checkout clean on the default branch and hand it to the next waiter. See [[*Release]]. |
| ~adopt [--force]~ | The needs-adopt holder, or the user. Save leftovers to a backup ref, then reset the checkout. See [[*Takeover and adopt]]. |
| ~pause [--with <pane or name>]...~ | The user only. Take the checkout, or go to the front of the queue and ask the holder to release. See [[*User pause and resume]]. |
| ~unshare <pane or name>...~ | The user only. Take panes off the pause's ~--with~ list. |
| ~resume [--as-is]~ | The user only. Release for the user. |
| ~hook~ | The Claude Code ~PreToolUse~ hook. See [[*Enforcement hook]]. |
| ~install-hook [--write]~ | Print the hook and its settings entry; ~--write~ installs them. |

The queue puts the user first, then ~--urgent~ claims, then the rest,
each in arrival order. Claiming again as the holder or a waiter keeps
the place and updates ~--for~ and ~--why~. A free checkout whose tree
is dirty, or has a rebase, merge, cherry-pick, or revert in progress,
is granted in state ~needs-adopt~; ~check~ refuses it until it is
adopted. ~check~ on an unguarded path reads only the local config and
never contacts the daemon.

When a claim joins the queue of a ~held~ lease, the daemon tells the
holder once, from ~agentbus~, with the queue length after the claim and
the waiter's name (or handle), ~--why~, and ~--for~:

#+BEGIN_SRC text
[lease] 1 waiting for local:/home/u/src/repo: ops/bob (issue 624, for 30m). Release when you can: agentbus lease release
#+END_SRC

Without ~--why~ the parentheses hold only ~for 30m~. Claiming again
while queued tells nobody, and a holder granted later is not told about
waiters already queued. The user's hold is never told, a holder past
its bid gets the check-in instead (see [[*Soft deadline and check-in]]),
and the user's own queued ~pause~ sends only its ask. Each notice is a
~lease_notify_waiting~ event naming the holder, the waiter, and the
queue length.

A notice not sent is a ~lease_notify_skipped~ event, with the waiter as
its actor and ~holder <holder>; reason <reason>; queue <n>~ as its
detail. The reason is ~user-holder~ (the user holds or paused the
checkout), ~past-deadline~ (the holder is past its bid), or ~repeat~
(the waiter claimed again while queued). Each holder, waiter, and
reason is logged once while that holder keeps the lease, so ten repeat
claims leave one line; a new holder starts afresh, and a daemon restart
may log one more. The user's own queued claim logs nothing. ~agentbus
log --event lease_notify_skipped~ answers why a holder was not told.

~status --json~ prints this shape, which other tools read and which
stays stable. ~--all~ prints an array of them. ~state~ is ~free~,
~held~, ~paused~, ~releasing~, or ~needs-adopt~. ~holder~ is absent
when the checkout is free. ~name~ is the registered name, or empty.

#+BEGIN_SRC json
{"checkout": "local:/home/u/src/repo", "state": "held",
 "holder": {"handle": "...", "name": "...", "since": "RFC3339",
            "deadline": "RFC3339", "why": "..."},
 "queue": [{"handle": "...", "name": "...", "urgent": false,
            "for": "40m", "since": "RFC3339"}],
 "backup_ref": "... (only when there is one)",
 "with": ["... (panes the user's pause is shared with, when any)"]}
#+END_SRC

The daemon keeps lease state in ~leases.json~ in its state directory,
so a restart keeps holders, queues, and deadlines. Every claim, grant,
extend, leave, release, and skip is a ~lease_claim~, ~lease_grant~,
~lease_extend~, ~lease_leave~, ~lease_release~, or ~lease_skip~ event
in the event log, with the checkout key as its name, and so are the
~lease_notify_waiting~ and ~lease_notify_skipped~ notice events above.
A tool call the [[*Enforcement hook][enforcement hook]] denies is a
~lease_hook_deny~ event.

** Lease in hub mode

On a second machine in hub mode, ~lease~ does not run on the hub. It
runs here, on the checkout's machine: ~lease_checkouts~ is read from
this machine's config, so an unguarded path costs no hub call, and the
git top-level, the clean/mid-operation check, release's and adopt's git
steps, and adopt's process check all run here. The checkout key is
~<machine>:<top-level>~, such as ~linux2:/home/u/src/repo~. Only the
lease request and what the CLI found (the tree state, a failed pull,
the backup refs, the processes ~--force~ went past) go to the hub. The
hub's daemon never runs git or looks at processes for a checkout on
another machine.

The request goes over the tunnel socket when the hub answers there,
with the caller's handle, as for the other tunnelled commands.
Otherwise it goes over ssh to ~agentbus lease forward~ on the hub, a
hidden subcommand that reads the request as JSON on stdin, hands it to
the hub's daemon with ~AGENTBUS_AS_HANDLE~ (from a herdr pane) as the
caller, and prints the daemon's reply as JSON. The holder is the
caller's handle as ~agentbus whoami~ resolves it in hub mode. ~pause
--with~ and ~unshare~ turn a pane id on this machine into its
~herdr:<machine>/...~ handle first; names and handles go as they are.

A hub that cannot be reached fails a lease command with ~hub <target>
unreachable: host unreachable~ or ~authentication locked (unlock your
SSH/gpg agent)~. ~lease check~ and the lease hook give up within 3
seconds and allow, with that cause and ~allowing~ on stderr. The
hook's cache is on this machine; ~release~, ~resume~ and ~unshare~
drop it here, and a takeover on the hub leaves it to expire.

** Release

~lease release~ runs its git steps in the CLI, on the checkout's
machine:

1. Refuse when the tree is dirty (modified, staged, or untracked and
   not ignored), listing the files. Unpushed commits on a branch are
   fine.
2. Refuse when a rebase, merge, cherry-pick, or revert is in progress.
3. ~git switch~ to the default branch, the one ~origin/HEAD~ points at
   (set it with ~git remote set-head origin --auto~), then ~git pull
   --rebase --prune~. A failed pull is reported and the release goes
   ahead; a pull that stops mid-rebase is aborted so the tree stays
   clean. A failed switch keeps the lease with you.
4. Tell the daemon, which grants the next waiter. While the git steps
   run, the state is ~releasing~.

The daemon grants the first waiter whose pane is not ~gone~ and drops
the gone ones from the queue. The new holder gets an agentbus message
from ~agentbus~:

#+BEGIN_SRC text
[lease] granted local:/home/u/src/repo until 10:40 (for: issue 624). Release with: agentbus lease release
#+END_SRC

With nobody waiting, the checkout becomes ~free~. A failed pull is
the ~lease_release~ event's reason.

** Soft deadline and check-in

The ~--for~ bid is soft: it never cuts anyone off by itself. When a
holder's bid ends, the daemon sends it a check-in from ~agentbus~:

#+BEGIN_SRC text
[lease] your bid on local:/home/u/src/repo ended. Run 'agentbus lease extend --for <d>' or 'agentbus lease release'.
#+END_SRC

Then, every check interval, it reads the holder's herdr state:

- ~working~ or ~blocked~: extend the bid silently by one interval. The
  check-in is sent again at most every ~lease_checkin_repeat~.
- ~idle~, ~done~, or ~no-agent~, with no ~extend~ or ~release~ since
  the check-in: start a silence timer. After ~lease_idle_grace~ of
  continued idle and silence, take over.
- ~unknown~ (the machine cannot be reached): never take over; keep
  waiting. The silence timer starts over.

With nobody queued, an overrun holder is checked in on once and then
left alone. A holder whose pane herdr reports ~gone~ is taken over at
once when a waiter is queued, without waiting for the bid to end. The
user's hold is never checked in on. ~extend~ or claiming again resets
the check-in. A lease left ~releasing~ by a release that died midway
gets the same rules as ~held~, so it never blocks the queue; the holder
can still run ~release~ again.

Each check-in and silent extend is a ~lease_checkin~ or
~lease_auto_extend~ event. The timers are kept in ~leases.json~, so
they survive a daemon restart; a takeover decided but not carried out
before a restart is carried out on the next check. All of this
takeover runs only with ~lease_takeover = "on"~; see below.

The daemon reads the timing from its config:

#+BEGIN_SRC toml
lease_check_interval = "2m"   # how often, and how far a working holder is extended
lease_checkin_repeat = "15m"  # least time between check-ins
lease_idle_grace = "5m"       # idle and silent this long: take over
lease_takeover = "log"        # "on" carries out takeovers; "log" (default) only logs them
#+END_SRC

** Staged rollout: ~lease_takeover~

agentbusd has no config reload, so turning on ~lease_checkouts~ needs a
restart. ~lease_takeover~ keeps that restart from also turning on
takeover. It is ~"log"~ by default, and takeover runs only when it is
exactly ~"on"~. A missing key is ~"log"~; any other value is ~"log"~
too, with a warning at start naming the key and the value, and the
daemon still starts.

With ~"log"~, a takeover the daemon would carry out is not: the state,
the holder, and the queue stay as they are, no backup ref is named, and
nobody gets a message or a decide note. Instead the daemon logs one
~lease_would_take_over~ event with the checkout, the holder, the reason,
and the first waiter. It logs it once per holder: again only after the
holder claims or extends, the holder changes, or the lease is released.
A takeover that a run with ~"on"~ decided but did not carry out is not
carried out either. Everything else stays on: check-ins, silent
auto-extend, granting a dirty free checkout as ~needs-adopt~, and ~lease
adopt~ for any ~needs-adopt~ lease, including one left by an earlier run
with ~"on"~.

The effective mode is visible: agentbusd prints ~lease_takeover=<mode>~
to stderr at start and records it in the ~start~ event, ~lease status~
prints ~takeover: log~ or ~takeover: on~, and ~lease status --json~ has
a top-level ~"takeover"~ field (with ~--all~, on each element).

** Takeover and adopt

A takeover never loses uncommitted work. The daemon runs no git: it
names a backup ref, ~refs/lease-backup/<UTC time>-<old holder name or
pane>~, tells the old holder

#+BEGIN_SRC text
[lease] taken over from you: local:/home/u/src/repo; your uncommitted work will be saved to refs/lease-backup/20261110T094500Z-ops-alice
#+END_SRC

and grants the first waiter whose pane is not ~gone~ in state
~needs-adopt~, with a wake message that says to run ~agentbus lease
adopt~ first. ~check~ refuses everyone, the adopter included, until
the adopt is done. ~status --json~ carries ~backup_ref~ while the state
is ~needs-adopt~. When ~decide~ is on the daemon's ~PATH~, the user
also gets a relay item in the decide inbox (~decide ask --owner
agentbus~) naming the checkout.

If the adopter's pane goes ~gone~ before it adopts, the lease passes to
the next waiter, still ~needs-adopt~ with the same backup ref. With
nobody waiting it stays ~needs-adopt~ with no holder, and the next
~claim~ gets it.

~lease adopt~ runs on the checkout's machine:

1. *Process check.* Refuse, keeping the lease ~needs-adopt~ with you,
   while a process still has its working directory inside the checkout
   (Linux: ~/proc/*/cwd~; macOS: ~lsof~), naming each one, such as
   ~make (pid 4242)~. Ignored: interactive shells (~sh~, ~bash~, ~zsh~,
   ~fish~), agent CLIs (~claude~, ~codex~, ~gemini~, and ~node~ or ~bun~
   running one), editors and pagers (~emacs~, ~vim~, ~nvim~, ~less~),
   ~agentbus~, and the adopt's own chain of parent processes.
   ~lease_ignore_procs~ replaces that list. ~adopt --force~ prints the
   processes and goes on.
2. *Save leftovers.* When the tree is dirty or a rebase, merge,
   cherry-pick, or revert is in progress, commit the whole working tree,
   untracked files included, through a temporary index, to the backup
   ref. Its parents are ~HEAD~ and the index as it was, and its message
   records the branch, the operation's state, and the changed files.
   Then abort the operation; if the abort brings back changes (a
   rebase's autostash), save those too, as ~<ref>-2~. Ignored files are
   neither saved nor removed. A ref is never overwritten, never a
   branch, and ~git stash~ is never used.
3. *Reset.* ~git reset --hard~, ~git clean -d~, switch to the default
   branch, and ~git pull --rebase --prune~. A failed pull is reported
   and the adopt goes ahead; any earlier failure leaves the lease
   ~needs-adopt~ with you.
4. The lease becomes ~held~ by you.

The user may always run ~adopt~ from a pane with no agent or from
outside herdr; the checkout is then held by ~user~, and an agent that
was to adopt goes back to the front of the queue.

~lease status~ lists the checkout's backup refs; the tool never deletes
them. Look at one with ~git show <ref>~ or ~git log -p <ref>~, and get
the files back with ~git restore --source <ref> -- <path>~. Takeovers
and adopts are ~lease_takeover~ and ~lease_adopt~ events.

#+BEGIN_SRC toml
lease_ignore_procs = ["sh", "bash", "zsh", "fish", "claude", "codex", "gemini", "emacs", "vim", "nvim", "less", "agentbus"]
#+END_SRC

** User pause and resume

The user takes the checkout with ~agentbus lease pause~ and gives it
back with ~agentbus lease resume~. Both, and ~unshare~, are refused from
a herdr pane that runs an agent (any state but ~no-agent~) and allowed
from a plain terminal pane or from outside herdr. This guards against
mistakes; it is not security.

- ~pause~ on a free checkout makes it ~paused~, held by ~user~ with no
  deadline.
- ~pause~ while an agent holds it puts ~user~ at the front of the queue
  and sends the holder, at once:

  #+BEGIN_SRC text
  [lease] the user asked for local:/home/u/src/repo; please finish up and release
  #+END_SRC

  The ask counts as the holder's check-in and its bid ends then, so the
  check-in rules above follow: a working holder is extended, an idle
  and silent one is taken over (with ~lease_takeover = "on"~). When the
  checkout is later granted to the user, the user gets a decide note
  when decide is on the daemon's ~PATH~.
- The user's hold is never checked in on and never taken over, with
  either ~lease_takeover~ mode.
- ~pause --with <pane or name>~ (repeatable; a herdr pane id, a
  registered name, or a handle) lets those agent panes edit under the
  pause: ~check~ passes for them, but they cannot ~release~, ~extend~,
  or ~resume~. ~pause --with X~ while already paused or queued adds X;
  ~unshare X~ removes it. ~status~ shows the list as ~with~.
- ~resume~ is ~release~ for the user: the same clean check, switch to
  the default branch, and pull, so the next holder starts clean. The
  ~with~ list clears and the next waiter is granted and woken.
  ~resume --as-is~ skips the switch and pull, for a checkout the user
  leaves on a branch on purpose; a dirty tree is still refused.
  ~resume~ also works after the user adopted. While the user is still
  queued, ~resume~ withdraws the pause without touching the tree.

Pauses, resumes, ~--with~, and unshares are ~lease_pause~,
~lease_resume~, ~lease_with~, and ~lease_unshare~ events. The ~with~
list is kept in ~leases.json~.

** Enforcement hook

~agentbus lease hook~ is a Claude Code ~PreToolUse~ hook that refuses
changes to a guarded checkout from a pane that does not hold its lease.
You install it; no command edits your Claude Code settings on its own.
~agentbus lease install-hook~ prints the script and the settings entry
and writes nothing. ~agentbus lease install-hook --write~ saves the
script as ~~/.claude/hooks/agentbus-lease.sh~ and adds this entry to
~hooks.PreToolUse~ in ~~/.claude/settings.json~, once:

#+BEGIN_SRC json
{"matcher": "Edit|Write|MultiEdit|NotebookEdit|Bash",
 "hooks": [{"type": "command", "command": "/home/u/.claude/hooks/agentbus-lease.sh"}]}
#+END_SRC

What it checks:

- ~Edit~, ~Write~, ~MultiEdit~, and ~NotebookEdit~ on a file inside a
  guarded checkout.
- ~Bash~ that runs a git command that changes a checkout: ~checkout~,
  ~switch~, ~commit~, ~merge~, ~rebase~, ~reset~, ~stash~ (not ~stash
  list~ or ~show~), ~pull~, ~cherry-pick~, ~revert~, ~am~, ~apply~,
  ~clean~, ~restore~, ~rm~, ~mv~, ~add~, ~tag~ (not a bare or ~-l~
  listing), ~branch -d/-D/-m~ (and ~-M~, ~-c~, ~-C~, ~-f~), and
  ~worktree~ (not ~worktree list~), in the tool's working directory, a
  ~cd~ or ~pushd~ target, or a ~git -C~, ~--work-tree~, or ~--git-dir~
  target. The reading is conservative: it splits at ~;~, ~&&~, ~||~,
  ~|~, ~&~, parentheses, backticks, and newlines, skips ~NAME=value~,
  ~env~, ~command~, ~exec~, ~nohup~, and ~time~, and reads ~sh -c~ and
  ~bash -c~ scripts. A git command after a ~cd~ counts in both the
  ~cd~ target and the starting directory, since a ~cd~ in a pipe or
  subshell does not last. Read-only git (~status~, ~log~, ~diff~,
  ~show~, ~fetch~, ...) and any other program pass.

A matched call runs the ~lease check~ logic. When the caller does not
hold the lease (and is not on the user's ~--with~ list), the call is
denied with the reason and the hint ~agentbus lease claim --for
<duration>~. A ~needs-adopt~ checkout is denied to everyone, the
adopter too, until ~agentbus lease adopt~ succeeds.

Each denial is a ~lease_hook_deny~ event, so ~agentbus log --event
lease_hook_deny~ shows what the hook stopped. Its name is the checkout
key, its actor the caller's pane handle, and its detail the holder, the
lease state, the tool, and the target: the file path relative to the
checkout root, or the git command, such as ~git switch~. In hub mode
the hub logs it and adds the caller's machine. The event is written
while answering the same check; a log that cannot be written does not
change the answer. Allows, answers from the cache, and a plain ~lease
check~ are not logged.

It is fast and fails open:

- A path outside every guarded checkout is decided from the local
  config, with no daemon call.
- "You hold it" is cached for 30 seconds per pane and checkout in
  ~$XDG_RUNTIME_DIR/agentbus/lease-cache~. The daemon drops a
  checkout's cache on ~release~, ~resume~, ~unshare~, and takeover. A
  denial is never cached.
- When agentbusd does not answer within 3 seconds, the call is allowed
  with ~agentbus lease hook: ...; allowing~ on stderr. The hook never
  starts the daemon. In hub mode the 3 seconds cover reaching the hub,
  over the tunnel or ssh, and the warning names the cause, such as
  ~host unreachable~ or ~authentication locked~.

Not covered, by design: ~sed -i~ and other in-place edits by programs,
shell redirects (~>~, ~>>~, ~tee~), and editors you run yourself. The
hook guards Claude Code's edit tools and git, not every write.
