Read this when a command cannot reach the daemon, or when an agent runs inside a sandbox that blocks sockets.
~agentbus doctor --sandbox~ is explained below, and everyday commands are in [[file:../README.org][the agentbus guide]].

* Sockets, state directory, and daemon start-up

The CLI has to connect to the daemon socket. On Linux that socket is
~$XDG_RUNTIME_DIR/agentbus/daemon.sock~, and ~XDG_RUNTIME_DIR~ is
required. On macOS, when ~XDG_RUNTIME_DIR~ is unset, the sockets are
under ~~/Library/Caches/agentbus/run/agentbus/~ (~daemon.sock~,
~hub.sock~, and ~tunnel.sock~). That directory is created with mode 0700
and is not ~$TMPDIR~. A socket path of 104 bytes or more,
including the terminating NUL, is an error that names the path. When
~XDG_RUNTIME_DIR~ is set, both systems use it and the macOS default
directory is not created. The daemon's state directory is
~$XDG_STATE_HOME/agentbus~, or ~$HOME/.local/state/agentbus~ when
~XDG_STATE_HOME~ is unset. A hub client's outbox on macOS is
~~/Library/Caches/agentbus/state~ instead, so a sandbox allowlist can
name one directory next to the run sockets. ~XDG_STATE_HOME~ still
wins. The CLI reports a missing state directory,
or a missing Linux runtime directory, instead of guessing.

The daemon needs that state directory. It also needs the ~herdr~
command and the herdr socket for the local server the panes use. Without
them it cannot see panes or deliver.

A daemon that starts before the herdr server, as at boot when both are
user services, does not need a restart. While herdr does not answer,
the daemon tries it again after 1s, then twice as long each time, up to
30s, running ~herdr~ afresh so the binary and the socket are looked up
again. Meanwhile search is empty, names are ~unreachable~, and sends
are held; once herdr answers, the next poll fills search and liveness,
and held messages are delivered. The event log gets one ~adapter_error~
(~herdr unreachable~) when herdr goes down and one ~adapter_reachable~
(~herdr reachable~) when it comes back, not one per retry. While it is
down, ~agentbus doctor~ prints ~herdr transport unreachable: <error>~,
where herdr's error names the socket it tried.

~agentbus install~ is the supervisor: a launchd plist on macOS, or a
systemd user unit on Linux. The CLI still starts ~agentbusd~ itself when
the daemon is down. That start is detached, in its own session. If the
CLI cannot reach the daemon and cannot start it, the command fails and
the error says so:

- ~agentbus: agentbusd is not running and no daemon binary was given to start it~
- ~agentbus: start agentbusd: ...~
- ~agentbus: agentbusd did not become ready: ...~
- ~agentbus: XDG_RUNTIME_DIR is not set; the agentbus daemon socket needs it~
  (Linux; macOS uses ~~/Library/Caches/agentbus/run~ instead)
- =agentbus: HOME is not set; agentbus state belongs in ~/.local/state/agentbus=

~agentbusd~ is the binary next to ~agentbus~. A sandbox that cannot
reach the socket and cannot execute that binary gets one of those
errors.

** Running inside an agent sandbox

An agent sandbox, such as Claude Code's sandbox (Seatbelt on macOS,
bubblewrap on Linux), denies unix sockets and network hosts it does not
list. A hub-mode command makes up to three kinds of connection, and
each failure names its step, the socket or ssh target, and what to
allow:

1. *Identify the pane.* The ~herdr~ CLI connects to the herdr socket,
   ~$HERDR_SOCKET_PATH~ (for example ~~/.config/herdr/herdr.sock~ on
   macOS), to look up the pane's agent session. A denied connect fails
   with
   ~identify this pane: connect /path/herdr.sock: operation not permitted (sandbox? allow this unix socket)~.
2. *Talk to the hub* over the tunnel socket, when it is there. On Linux
   that is ~$XDG_RUNTIME_DIR/agentbus/tunnel.sock~ (usually
   ~/run/user/<uid>~). On macOS it is that path when ~XDG_RUNTIME_DIR~
   is set, and ~~/Library/Caches/agentbus/run/agentbus/tunnel.sock~
   otherwise. ~agentbus doctor --sandbox~ prints the resolved path.
3. *Otherwise run on the hub over ssh*, which needs network access to
   the hub and read access to ~~/.ssh~.

herdr exports ~HERDR_PANE_ID~, ~HERDR_TAB_ID~, ~HERDR_WORKSPACE_ID~ and
~HERDR_SOCKET_PATH~ to each pane, but not the agent session, so the
handle cannot be built from the environment alone. Instead, ~agentbus
register~ in hub mode asks herdr for this pane's handle and caches it in
~$XDG_RUNTIME_DIR/agentbus/panes/<pane-id>~ (mode 0600), or under
~~/Library/Caches/agentbus/run/agentbus/panes/~ on macOS when
~XDG_RUNTIME_DIR~ is unset. Later calls
use the cached handle and ask herdr only when nothing is cached, so a
sandboxed agent that registered once (or whose first register ran
unsandboxed) needs no herdr socket. ~register~ always asks herdr again
when it can, which refreshes the cache after the pane starts a new
agent session; when herdr is denied it keeps the cached handle.

Inside a sandbox, a tunnel socket that is there but fails (denied, not
answering, or another protocol) fails the command with
~reach the hub over the tunnel: ...; not falling back to ssh inside a sandbox~
instead of falling back to ssh, so ~~/.ssh~ is never needed. Hooks
still exit 0. agentbus counts as sandboxed when ~SANDBOX_RUNTIME~ is
set (Claude Code's sandbox sets it), when ~AGENTBUS_SANDBOX=1~, or when
a connect fails with "operation not permitted";
~AGENTBUS_SANDBOX=0~ turns the environment check off. A failed ssh
fallback inside a sandbox says what ssh needs and points at the tunnel.

~agentbus doctor --sandbox~ prints the entries this machine needs in
the shape of Claude Code's sandbox settings, then tests each
connection:

#+begin_example
Claude Code sandbox settings this machine needs (merge into settings.json):
{
  "sandbox": {
    "network": {
      "allowUnixSockets": [
        "/Users/me/.config/herdr/herdr.sock",
        "/Users/me/Library/Caches/agentbus/run/agentbus/tunnel.sock"
      ],
      "allowedDomains": [
        "hub"
      ]
    },
    "filesystem": {
      "write": {
        "allowOnly": [
          "/Users/me/Library/Caches/agentbus/state",
          "/Users/me/Library/Caches/agentbus/run"
        ]
      }
    }
  }
}
allowedDomains is only for the ssh fallback to me@hub, which also reads ~/.ssh; the tunnel needs neither.

Checks:
  herdr socket /Users/me/.config/herdr/herdr.sock: ok
  tunnel socket /Users/me/Library/Caches/agentbus/run/agentbus/tunnel.sock: ok
  ssh me@hub: ok (its ssh port answers)
  outbox flusher: present (/Users/me/Library/LaunchAgents/com.agentbus.outbox.plist)
  outbox: no pending entries
#+end_example

A hub-mode client does not list or check the local daemon socket.
~doctor~ reports the tunnel, the ssh port, the outbox flusher unit, and
pending outbox entries, and it exits 0 when those are healthy even
though no local daemon socket exists. A machine that is not a hub
client still lists the daemon socket. Each socket is ~ok~, ~missing~,
~blocked (sandbox? allow this unix socket)~, or ~failed: <error>~. The
ssh check only connects to the hub's ssh port; it does not log in. The
hub entry is the host part of ~hub~, so for a ~Host~ alias in
~~/.ssh/config~ allow its real ~HostName~ as well. doctor only prints
the entries; it never edits your settings.
