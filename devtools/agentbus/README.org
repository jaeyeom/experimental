#+TITLE: agentbus
#+DATE: 2026-11-15

agentbus lets coding agents in separate [[https://herdr.dev/][herdr]] panes
message each other. It requires herdr. Agents in different panes cannot
talk, and Claude Code's SendMessage only reaches its own subagents. It
is for people who run several agents at once. A bus message is never
the user's approval.

A small daemon, ~agentbusd~, stores and delivers the messages. The
~agentbus~ CLI talks to it. Anything that needs the user's OK still
needs the user. Agent rules live in ~.claude/skills/agentbus/SKILL.md~.
After a host reboot, follow [[file:reboot.org][the reboot runbook]].

* Concepts

| Term        | Meaning                                                                                 |
|-------------+-----------------------------------------------------------------------------------------|
| name        | A short name an agent claims, such as ~ops/inbox~.                                      |
| handle      | ~herdr:<machine>/<session>/<pane>~. ~<machine>~ is ~local~ or a saved herdr machine.    |
| ~--when~    | What the agent is actually doing. ~register~ and ~describe~ require it.                 |
| composer    | The input box. A message is held while that box is not empty.                           |
| delivery    | ~queued~, ~held: <reason>~, ~delivered~, or ~expired~.                                  |
| hub mode    | One daemon shared by several computers. See [[file:docs/multi-machine.org][hub mode]].  |
| lease       | Which agent may change one shared git checkout. See [[file:docs/lease.org][the lease]]. |
| hibernation | An idle agent is stopped. Its pane and names stay, and a message wakes it.              |
| job         | Work on the daemon's queue that a runner claims. See [[file:docs/jobs.org][the job queue]].                     |

~--when~ has to name the work. ~reviewing the queue~ is a meaningful
value. ~agent~ is not. Taking over a checkout can also open a
[[file:../decide/README.org][decide]] item for the user. Herdr is the
terminal multiplexer the panes run in.

* Quick start

You need herdr running, on Linux or macOS. On Linux, ~XDG_RUNTIME_DIR~
must be set. Install both binaries into the same directory. ~agentbus~
starts ~agentbusd~ from that directory when the daemon is down.

#+BEGIN_SRC bash
go install github.com/jaeyeom/experimental/devtools/agentbus/cmd/agentbus@latest github.com/jaeyeom/experimental/devtools/agentbus/cmd/agentbusd@latest
#+END_SRC

From a checkout of this repo, install ~./devtools/agentbus/cmd/agentbus~
and ~./devtools/agentbus/cmd/agentbusd~. ~bazel build
//devtools/agentbus/...~ builds both.

~agentbus install~ writes the supervisor and loads it. On macOS that is
=~$HOME/Library/LaunchAgents/com.agentbus.agentbusd.plist=. On Linux it
is the systemd user unit ~agentbus.service~ under
=~$XDG_CONFIG_HOME/systemd/user/=, or under
=~$HOME/.config/systemd/user/= when ~XDG_CONFIG_HOME~ is unset.

In two herdr panes:

#+BEGIN_SRC bash
# pane A
agentbus register demo/a --when "trying agentbus"
#+END_SRC

#+BEGIN_EXAMPLE
registered demo/a
#+END_EXAMPLE

#+BEGIN_SRC bash
# pane B, which has not claimed a name
agentbus send demo/a "hello"
#+END_SRC

#+BEGIN_EXAMPLE
m-7f3a queued for delivery
#+END_EXAMPLE

Pane A is idle and its input box is empty, so the paste arrives. The
sender has no name, so the header shows its handle.

#+BEGIN_EXAMPLE
[agentbus m-7f3a from herdr:local/default/w1:p2 → demo/a · 15:04]
hello
↩ reply: agentbus reply m-7f3a "..."
#+END_EXAMPLE

#+BEGIN_SRC bash
agentbus status m-7f3a
#+END_SRC

#+BEGIN_EXAMPLE
id: m-7f3a
state: delivered
waited: 1s
#+END_EXAMPLE

~agentbus install-hooks~ is optional. It records Claude Code
~SendMessage~ calls and blocks a prompt that pastes a bus message into
a draft. See [[file:docs/delivery.org][delivery]].

* Everyday use

** Register and describe

~register~ claims a name for this pane. A live holder is not overridden.

#+BEGIN_EXAMPLE
ops/inbox is held by herdr:local/default/w2:p3 (alive); message them with: agentbus send ops/inbox
#+END_EXAMPLE

Message that holder. Do not take the name. The holder hands off with
~release ops/inbox --to <claimer>~ only after sending the context: the
work in progress, and what it was monitoring. ~release <name>~ without
~--to~ drops the name. Any caller may drop a name whose holder is
gone; the log records the caller and the gone handle.

When a name changes holder (via ~release <name> --to <claimer>~ or a
~register~ that replaces a gone or dead-hibernated holder), any
undelivered messages addressed to that name move from the old holder's
queue to the new holder's queue, merged in send order. Messages sent to
the raw old handle stay on the old handle.

#+BEGIN_SRC bash
agentbus describe --when "waiting on a reply from ops/inbox"
agentbus whoami
#+END_SRC

#+BEGIN_EXAMPLE
described ops/inbox
ops/inbox
when: waiting on a reply from ops/inbox
#+END_EXAMPLE

** Send and reply

The body comes from the argument, from ~--file~, or from stdin (no body
words, or a body of ~-~). Exactly one of those, and it must not be
empty. A token that starts with ~--~ and is not a known flag is a usage
error and is not sent. Words after ~--~ are the body, even when they
start with ~--~.

~--ttl 30m~ sets a deadline for that one message. ~--wait~ blocks until
it is delivered or the deadline passes. Without ~--wait~, a message
that passes the checks prints ~<id> queued for delivery~ and exits 0.
A hold prints ~held: <reason>~ at once and exits 0, except when herdr
cannot be reached: the message is stored, stderr says
~agentbus: held: the daemon can't reach herdr (<reason>); the message will be delivered when it recovers. See: agentbus doctor~,
and the process exits 3. A registered pane stamped ~anon:~ because herdr
could not identify it also prints
~sent as anonymous: the daemon couldn't identify this pane (herdr unreachable)~.
~--wait~ does not use exit 3. ~reply~ answers the same way. ~to~ is the
original sender and ~re~ is the id.

Exit codes of ~send~ and ~reply~:

- ~0~: stored (queued, delivered, or held).
- ~1~: bus, daemon or transport error.
- ~2~: unknown target or bad usage. A name that is not registered says
  ~<name> is not registered; try agentbus search~, and so does a reply
  whose original sender no longer resolves. Nothing is sent.
- ~3~: stored, but the daemon can't reach the transport (not with
  ~--wait~).

A target whose pane is gone is held as ~held: gone~. For a registered
name the message keeps waiting, with no limit but ~--ttl~, and moves
to the new holder if the name is later claimed or handed off with
~release --to~. For a raw
pane handle that no name holds, nothing can accept it once the pane is
gone, so it expires after the pane has been gone for ~gone_after~
(default 1h; ~"0s"~ expires it at the first gone check). The event log
gets one ~expired~ event with ~reason=gone~, ~status --json~ shows
~"state":"expired","reason":"gone"~, and the sender is told
~agentbus: message <id> to <handle> not delivered: target pane is gone~.
Only a positive ~gone~ from every adapter counts: a machine or
transport that cannot be reached, or an ~unknown~ state, keeps the
message held, and any answer other than ~gone~ restarts the clock. A
hold is logged once as a ~held~ event, and again only when its reason
changes.

#+BEGIN_SRC bash
agentbus reply m-7f3a "yes, the queue is in progress"
#+END_SRC

#+BEGIN_EXAMPLE
m-7f3b queued for delivery
#+END_EXAMPLE

Drafts, ambiguous retries, and ~--client-id~ are in
[[file:docs/delivery.org][delivery]].

** Check on a message

When something seems lost, check ~agentbus status <id>~ and
~agentbus log~ before resending. ~status~ prints the state and how long
the message has waited. Resending first creates a second message.

** Restart an agent fresh in its pane

To replace a hibernated (or ~stop-failed~) session with a fresh one in
the same pane:

1. Hibernate the old session (~agentbus hibernate <name>~). Its pane
   returns to a shell prompt and the old handle keeps its names.
2. Start a new agent session in that same pane (for example ~claude~
   without ~--resume~).
3. In the new session, run ~agentbus register <name> --when "<text>"~.
   Because the pane now runs a new session, the dead hibernation record
   gives way: the record is dropped, the new session takes over the old
   session's names, and a ~takeover~ event is logged.

If a message arrives before the new session runs ~register~, wake checks
the pane before launching the resume command. When the pane already runs
another session (or another foreground program), wake refuses
(~pane runs another session; not waking <handle>~), drops the dead
record, logs ~agent_wake_skipped~, and leaves the message queued while
notifying the sender. You can also drop a dead hibernation record by
hand with ~agentbus forget <name or handle>~ (which refuses a live
holder). ~forget~ leaves the name registered to the gone handle and says
so; any caller can then drop it with ~agentbus release <name>~, which is
refused while the holder is alive or unreachable. Messages held for that
name stay in ~status~.

** Find agents

~list~ prints registered names. ~search~ with no query lists everyone
the daemon can see. A query is a case-sensitive substring of the name,
~--when~, tab label, or title. An agent that has not registered has an
empty name and a raw handle. ~send~ accepts that handle. The bus does
not invent a name from a title or a label.

#+BEGIN_SRC bash
agentbus list
#+END_SRC

#+BEGIN_EXAMPLE
name: demo/a
when: trying agentbus
liveness: alive
transport: herdr
handle: herdr:local/default/w1:p1
#+END_EXAMPLE

~list --json~ fields, and the other ~--json~ shapes, are in
[[file:docs/json-reference.org][the JSON reference]].

* Commands

| Command                           | What it does                                                                                   |
|-----------------------------------+------------------------------------------------------------------------------------------------|
| ~register <name> --when <text>~   | Claim a name. ~--when~ is required and says what you are doing.                                |
| ~describe --when <text>~          | Replace ~--when~ on the names this caller holds.                                               |
| ~whoami~                          | Print those names, or the raw handle when none are registered.                                 |
| ~release <name> [--to <claimer>]~ | Drop a name, or hand it to a claimer. Send context first. Any caller may drop a name whose holder is gone. |
| ~list [--json] [--fresh]~         | Registered names, ~--when~, liveness, and transport.                                           |
| ~search [query]~                  | Every reachable agent, registered or not.                                                      |
| ~send <name or handle> [<body>]~  | Send. The body comes from the argument, ~--file~, or stdin. ~--expect-reply~ marks it for ~asks~. |
| ~reply <id> [<body>]~             | Reply. ~to~ is the original sender and ~re~ is ~id~.                                           |
| ~show <id>~                       | Print one stored message.                                                                      |
| ~thread <id>~                     | Print the chain.                                                                               |
| ~status [--json] <id>...~         | Print id, state, client id when set, and how long it has waited. ~--json~ takes several ids.   |
| ~log~                             | Read the daemon event log.                                                                     |
| ~outbox <ls|flush> [--watch]~     | List or flush hub-mode messages waiting on this machine.                                       |
| ~lease <subcommand>~              | Guard a shared checkout. See [[file:docs/lease.org][the lease]].                               |
| ~jobs <subcommand>~               | Enqueue, claim, and settle jobs; hold the queue; ~jobs runner~ runs them. See [[file:docs/jobs.org][the job queue]]. |
| ~mem [--json]~                    | Memory per local agent pane. See [[file:docs/hibernate.org][memory]].                          |
| ~hibernate <name or handle>...~   | Stop idle agents but keep their panes and names. See [[file:docs/hibernate.org][hibernation]]. |
| ~wake [--model <m>] <name or handle>~ | Relaunch a hibernated agent now (~--model keep~ keeps original). A message to it wakes it too. |
| ~forget <name or handle>~         | Drop a dead hibernation record by hand. Refuses a live holder. The name stays registered; ~release~ it. |
| ~release-held <name>~             | Clear a login-expired hold on a recipient and flush held messages.                             |
| ~replay [flags]~                  | Resend ~delivered-unprocessed~ messages in order (~--to~, ~--since~, ~--reason~, ~--dry-run~, ~--force~). |
| ~install~                         | Install the supervisor and load it. In hub mode, install the tunnel.                           |
| ~paths --json~                    | Print ~socket~, ~hub_socket~, ~tunnel_socket~, and ~state_dir~.                                |
| ~doctor [--sandbox]~              | Other ~agentbusd~ processes; in hub mode, the tunnel, ssh, and outbox.                         |
| ~health [--json]~                 | Whether the bus can deliver now. Exit 0 ok, 1 daemon unreachable, 4 a transport down.          |
| ~held [flags]~                    | List held messages (~--older-than~, ~--reason~, ~--not-reason~, ~--to~, ~--json~). Exit 0/1/2. |
| ~asks [flags]~                    | List unanswered asks (~--unanswered~, ~--from~, ~--to~, ~--json~). Exit 0/1/2.                 |
| ~dialogs [--machine M] [--json]~  | List panes showing a pending dialog or input prompt. Exit 0/1/2.                               |
| ~install-hooks~                   | Install the observe-only ~SendMessage~ hook and the prompt guard.                              |
| ~hook~                            | Internal. ~install-hooks~ runs it to record one ~SendMessage~ call.                            |
| ~prompt-hook~                     | Guard merged drafts; ~prompt-hook off [--session <id>]~ disables it until ~on~.                  |

~agentbus --help~ (or ~-h~, or ~help~) lists these commands.
~agentbus help <command>~ prints that command's flags and an example
without contacting the daemon. ~agentbus~ with no arguments prints the
list, then starts ~agentbusd~ if needed and prints the daemon status.
~agentbusd --help~ lists the daemon's environment variables.

~doctor~ with no flag reports other ~agentbusd~ processes for this
user. In hub mode it fails if a local ~agentbusd~ is running or its
sockets exist (printing the pid, start time, socket paths, and the
~kill~ / socket-removal hint without killing it), and reports the
tunnel, the ssh port, and the outbox instead of the local daemon socket.
~doctor --sandbox~ prints the Claude Code sandbox allowlist and tests each
connection. See [[file:docs/sandbox.org][sockets and the sandbox]].

~health~ is the cheap check for scripts and UIs. It makes one request
to the daemon, within 2s, and the daemon tests each transport now. It
never starts the daemon. In hub mode it asks the hub's daemon, over the
tunnel or ssh. It prints ~ok~, or one line per problem, such as
~herdr transport unreachable: <reason>~. ~health --json~ prints one
object:

#+begin_src json
{"daemon":"up","transport":"ok","problems":[]}
#+end_src

~daemon~ is ~up~ or ~down~. ~transport~ is ~ok~, ~down~, or ~unknown~
(the daemon, or the hub, cannot be reached, or cannot report). It exits 0
when everything is ok, 1 when the daemon is unreachable or cannot
report, and 4 when the daemon is up but a transport is down.

*** Health-check queries (~held~, ~asks~, ~dialogs~)

~held~, ~asks~, and ~dialogs~ report stuck messages, unanswered asks,
and panes waiting on dialogs without starting the daemon. All three
follow the same exit codes for scripts: ~0~ when nothing matches, ~1~
when one or more items match, and ~2~ on a bus, config, or usage error.

- ~agentbus held [--older-than D] [--reason R]... [--not-reason R]... [--to NAME] [--json]~:
  lists messages in ~held~ state with id, from, to, held reason text,
  stable ~reason_code~, ~held_since~, and ~age~. ~--reason~ and
  ~--not-reason~ are repeatable and match stable reason codes: ~draft~,
  ~draft-unknown~, ~scrolled~, ~focused~, ~ordering~, ~login-expired~,
  ~unreachable~, ~hibernated~, ~waking~, ~wake-failed~, ~pane-gone~,
  ~parked~, ~ambiguous~, ~ambiguous-unverified~, ~blocked~, ~no-agent~,
  ~gone~, ~unknown~, ~transport-refused~, or ~other~.
- ~agentbus asks [--unanswered D] [--from NAME] [--to NAME] [--json]~:
  lists delivered messages that expect a reply and have no non-expired
  reply (~re~) after ~D~ (by message age since ~sent~). A message
  expects a reply when sent with ~agentbus send --expect-reply~
  (~rule: "explicit"~), or via the fallback heuristics: body ending with
  ~?~ after trimming whitespace (~rule: "question-mark"~), or sender
  matching ~expect_reply_senders~ (~rule: "sender-skill"~). Agents and
  skills whose workflows expect replies should pass ~--expect-reply~.
- ~agentbus dialogs [--machine M] [--json]~: lists agent panes whose
  screen currently shows a dialog or input prompt, reusing the same
  built-in detector as ~hibernate~ (~permission prompt~,
  ~question prompt~) plus any regexes configured in ~dialog_rules~, with
  no LLM involved. Normal idle Claude screens whose input box parses
  never trigger a false positive. Each entry reports ~pane~,
  ~agent_name~, ~machine~, matched ~rule~, and one-line truncated
  ~text~. Invalid regexes in ~dialog_rules~ fail loud on config load
  with exit ~2~.

~status --json <id>...~ is for a UI that shows delivery state per
message. It takes several ids, message or client ids, in one call, and
prints one object per line in the order given:

#+begin_src json
{"id":"m-7f3a","state":"held","held_reason":"transport unreachable","stored_at":"2026-11-16T17:08:06.123Z"}
#+end_src

~state~ is ~queued~, ~held~, ~delivered~, ~delivered-unprocessed~ (the
target's transcript showed an auth error reply or no turn started within
~verify_delivery_within~; ~reason~ is ~auth~ or ~no-turn~), ~failed~,
~expired~, or ~unknown~ (no such id). Fields that do not apply are
omitted. ~held_reason~ is one of ~transport unreachable~, ~composer busy~
(the target's composer is not empty, or the pane is scrolled up or
focused), ~target not ready~ (including ~held: target login expired~,
which holds later bus messages to that recipient until the latest
assistant turn is normal, a backoff retry succeeds, or
~agentbus release-held <name>~ is run; schedulers inside the
agent's own session are not paused by agentbus), ~earlier message held~,
~hibernated~, ~wake failed~ (the agent's wake failed; ~error~ says why, the
message stays queued and the wake is retried after a backoff), ~pane gone~
(the hibernated agent's pane no longer exists; the message waits for a new
holder of the name and no wake is tried), ~delivery unconfirmed~, or ~other~. ~stored_at~ and
~delivered_at~ are RFC3339 in UTC. ~error~ says why a ~failed~ message
failed. ~reason~ says why an ~expired~ message closed (~ttl~ or ~gone~)
or why a ~delivered-unprocessed~ message was marked (~auth~ or ~no-turn~). An unknown id is not an
error; only bad usage exits 2. In hub mode, an id still in this
machine's outbox is answered here, first, and the hub answers the rest.

~log --since~ takes a duration ago (~30m~, ~6h~, ~2d~, ~1d12h~), an
RFC3339 time, or a ~YYYY-MM-DD~ date at local midnight. ~hibernate
--idle-over <duration>~ stops agents idle at least that long.
~hibernate --policy~ runs the memory-pressure policy on a hub-mode
client. In hub mode, ~mem~ reads idle times from the file that runner
saves (=policy-seen.json= in the state directory), and adds a note when
the file is missing or stale. ~hook~ and ~prompt-hook~ without arguments
are internal: only ~install-hooks~ should run them. ~prompt-hook off
[--session <id>]~ disables blocking globally or for one session;
~prompt-hook on [--session <id>]~ restores it.

*** Prompt-hook recovery

The installed Claude Code ~UserPromptSubmit~ hook lets prompts through when
they contain only agentbus deliveries, including surrounding whitespace. If a
delivery was pasted after your own draft, the hook blocks it once, re-queues
the bus message, and tells you to press ~Ctrl+U~ to clear the input box. The
bus keeps the message and redelivers it only after the composer is confirmed
empty. If re-queueing fails, the hook says the copy in the box is the only
one; save it before clearing.

If the client restores the blocked draft after a restart, submitting it again
passes through with context for the agent to separate your text from the
already re-queued delivery. You can also start a prompt with
~!agentbus-pass~ to bypass the guard once.

* Configuration

agentbusd reads =~$XDG_CONFIG_HOME/agentbus/config.toml= at start, or
=~$HOME/.config/agentbus/config.toml= when ~XDG_CONFIG_HOME~ is unset.
A missing file means the defaults below. The daemon does not reload, so
a change needs a restart. ~AGENTBUS_HUB~ overrides ~hub~.

#+BEGIN_SRC toml
# Saved herdr machines search includes. Default: none. local is always included.
# machines = ["linux2"]
remote_timeout = "5s"             # bound on each call to another machine
list_liveness_max_age = "15s"     # list refreshes cached liveness older than this
hold_notice_after = "10m"         # one notice after a hold this long; "0s" sends none
stale_composer_after = "10m"      # one notice per tab for unchanged composer text; "0s" sends none
hibernate_warn_within = "60s"     # hibernating this soon after a delivery logs a warning; "0s" logs none
gone_after = "1h"                 # a raw pane handle gone this long: its message expires; "0s" at once
verify_delivery_within = "60s"    # check readable transcript after delivery; "0s" disables
# auth_error_patterns = ["Login expired · Please run /login", "Login expired", "Please run /login", "Not logged in", "Invalid API key"]
# composer_placeholders = ["Once fixed, resend your message"]

# Hub mode. Default: unset, so this machine runs its own daemon.
# Hub clients never run or start a local agentbusd (every start path
# refuses, and `agentbus doctor` fails if a local daemon or its sockets exist).
# hub = "me@hub"
# machine = "linux2"              # this machine's herdr label on the hub
# ssh_identity_agent = "~/.ssh/agent.sock"  # empty: ssh's own agent lookup
# ssh_agent_socket = "~/.ssh/agent.sock"    # agentbusd's SSH_AUTH_SOCK for remote machines;
                                            # unset tries ~/.ssh/agent.sock, gpgconf agent-ssh-socket,
                                            # then inherited SSH_AUTH_SOCK (retries once on auth locked)
# hub_socket = "/run/user/1000/agentbus/hub.sock"  # install can discover this

# Lease. Default: no guarded checkouts, takeover only logged.
# lease_checkouts = ["/home/u/src/repo"]
lease_check_interval = "2m"       # how often, and how far a working holder is extended
lease_checkin_repeat = "15m"      # least time between check-ins
lease_idle_grace = "5m"           # idle and silent this long: take over
lease_takeover = "log"            # "on" carries takeovers out; "log" only logs them
lease_ignore_procs = ["sh", "bash", "zsh", "fish", "claude", "codex", "gemini", "emacs", "vim", "nvim", "less", "agentbus"]

wake_timeout = "60s"              # how long a relaunched agent has to get ready
# wake_model = "sonnet"           # model a woken Claude Code agent resumes on ("keep" keeps original)
# wake_model_by_name = {"ops/*" = "keep", "routine/*" = "haiku"}  # first match wins
# hibernate_exempt = ["ops/*"]    # default: none
hibernate_policy = "off"          # "dry-run" or "on"
# hibernate_below = "1.5GiB"      # required before dry-run or on acts
# hibernate_target = "3GiB"       # default: hibernate_below
hibernate_min_idle = "30m"        # least idle time the policy will stop
hibernate_interval = "1m"         # how often the policy reads available memory

# Jobs. Default: jobs-policy.json beside this file; missing asks for every kind.
# jobs_policy = "~/.config/agentbus/jobs-policy.json"

# Health-check rules.
# dialog_rules = {"trust" = 'Do you trust.*\? \[y/N\]'}  # extra regexes for dialogs/hibernate
# expect_reply_senders = ["ops/reviewer", "ask/*"]     # senders whose delivered messages expect a reply
#+END_SRC

For ~wake_model~ and ~wake_model_by_name~, the daemon that performs
the wake (the hub in hub mode) reads the config; a client-side
~wake_model~ is not consulted. Rules in ~wake_model_by_name~ match
names, handles, or globs in file order (first match wins), then
~wake_model~, then ~keep~. ~agentbus wake --model <m>~ overrides both
for a manual wake (~--model keep~ forces the original). Example:

#+BEGIN_SRC toml
wake_model = "sonnet"
wake_model_by_name = {"ops/*" = "keep", "routine/*" = "haiku"}
#+END_SRC

* Troubleshooting

~agentbus doctor~ and ~agentbus log~ are the first checks. ~doctor
--sandbox~ is the check when a sandboxed agent cannot connect. ~agentbus~
also implements the standard ~toolcli~ protocol subcommands: ~version
[--json]~, ~update [--check] [--ref <ref>] [--json]~ (which also updates
~agentbusd~), ~doctor [--json] [--offline]~, and ~skill
[install|uninstall|status ...]~. Common
failures:

- ~agentbus: XDG_RUNTIME_DIR is not set; the agentbus daemon socket needs it~
  on Linux. macOS uses =~$HOME/Library/Caches/agentbus/run= instead.
- ~agentbus: agentbusd is not running and no daemon binary was given to start it~
- ~herdr transport unreachable: ...~ while the herdr server is down.
  The daemon retries; it does not need a restart when herdr comes back.
- ~agentbus: hub <target> unreachable: host unreachable~ or
  ~authentication locked (unlock your SSH/gpg agent)~, in hub mode.

Socket paths, the state directory, and the sandbox allowlist are in
[[file:docs/sandbox.org][sockets and the sandbox]].
