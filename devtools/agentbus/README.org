#+TITLE: agentbus
#+DATE: 2026-11-09

* Overview

~agentbus~ is a local message bus for coding agents. The daemon runs on
one machine and also delivers to agents on saved herdr machines (see
[[*Other herdr machines]]).
Register a name when you start, then ~send~ and ~reply~. A bus message
is information or a request from another agent. It is never the user's
approval. Anything that needs the user's OK still needs the user.

The agent rules live in ~.claude/skills/agentbus/SKILL.md~.

Examples below use the name ~ops/inbox~ and the handle
~herdr:local/default/w2:p3~.

* Commands

| Command | What it does |
|---------+--------------|
| ~register <name> --when <text>~ | Claim a name. ~--when~ is required and says what you are doing. |
| ~describe --when <text>~ | Replace ~--when~ on the names this caller holds. |
| ~whoami~ | Print those names, or the raw handle when none are registered. |
| ~release <name>~ | Drop a name. |
| ~release <name> --to <claimer>~ | Hand the name to that claimer. Send context first. |
| ~list [--json]~ | Registered names, ~--when~, liveness, and transport. |
| ~search [query]~ | Every reachable agent, registered or not. |
| ~send <name or handle> [<body>]~ | Send. Also ~--file~, stdin, ~--ttl~, and ~--wait~. |
| ~reply <id> <body>~ | Reply. ~to~ is the original sender and ~re~ is ~id~. |
| ~show <id>~ | Print one stored message. |
| ~thread <id>~ | Print the chain. |
| ~status <id>~ | Print id, state, and how long it has waited. |
| ~log~ | Read the daemon event log. |
| ~lease <claim/extend/leave/status/check/release>~ | Hold the lease on a guarded checkout, or see who holds it. See [[*Workdir lease]]. |
| ~install~ | Install the supervisor and load it; in hub mode, the tunnel to the hub. |
| ~install-hooks~ | Install the observe-only ~SendMessage~ hook and the merged-draft prompt guard. |

~agentbus --help~ (or ~-h~, or ~help~) lists these commands.
~agentbus help <command>~ or ~agentbus <command> --help~ prints that
command's flags, their defaults, and an example, without contacting the
daemon. ~agentbus~ with no arguments prints the command list, then
starts ~agentbusd~ if needed and prints the daemon status.
~agentbusd --help~ lists the daemon's environment variables.

~--when~ has to say what the agent is actually doing. ~reviewing the
queue~ is a meaningful value. ~agent~ is not.

#+BEGIN_SRC bash
agentbus register ops/inbox --when "reviewing the queue"
agentbus describe --when "waiting on a reply from ops/inbox"
agentbus whoami
agentbus list
agentbus search inbox
agentbus send ops/inbox "are you reviewing the queue?"
agentbus send herdr:local/default/w2:p3 "please register as ops/inbox"
agentbus reply m-7f3a "yes, the queue is in progress"
agentbus status m-7f3a
agentbus log --name ops/inbox
#+END_SRC

~send~ reads the body from the argument, from ~--file~, or from stdin.
The body must not be empty. ~--ttl 30m~ sets a deadline for that one
message. ~--wait~ blocks until it is delivered or that deadline passes.
~search~ with no query lists everyone the daemon can see. A query is a
case-sensitive substring of the name, ~--when~, tab label, or title.

~list --json~ prints a JSON array with one object per registered name,
or ~[]~ when none are. Each object has these fields, which are stable:

| Field | Value |
|-------+-------|
| ~name~ | The registered name. |
| ~when~ | Its ~--when~ text. |
| ~liveness~ | ~alive~, ~dead~, or ~unknown~. |
| ~transport~ | The adapter that reaches it, such as ~herdr~. |
| ~handle~ | The holder's raw handle. |

~liveness~ folds the text words: ~alive~ and ~blocked~ are ~alive~,
~gone~ is ~dead~, and ~unreachable~ is ~unknown~. When the daemon cannot
be reached, ~list --json~ prints nothing on stdout and exits non-zero.

~log~ filters are ~--since~, ~--name~, ~--msg~, ~--event~, ~--follow~,
and ~--json~. ~--since~ takes a duration ago (~30m~, ~6h~, ~2d~,
~1d12h~), an RFC3339 time, or a ~YYYY-MM-DD~ date at local midnight. The files are daily JSONL under the state
directory, so ~jq~ can read them too.

* Names

A live holder is not overridden. ~register~ then fails with text like:

#+BEGIN_EXAMPLE
ops/inbox is held by herdr:local/default/w2:p3 (alive); message them with: agentbus send ops/inbox
#+END_EXAMPLE

Message that holder. Do not take the name. The holder hands off with
~release ops/inbox --to <claimer>~ only after sending the context: the
work in progress, and what it was monitoring. ~release <name>~ without
~--to~ drops the name and does not hand it off.

~search~ can show an agent that has not registered. Its row has an empty
name and a raw handle such as ~herdr:local/default/w2:p3~. ~send~
accepts that handle. The bus does not invent a logical name from a title
or a label.

* Delivery and user drafts

Paste delivery requires an *empty composer*. This is an adapter
precondition, alongside "not blocked" and "has an agent". If the
composer cannot be read, it counts as not empty. A hold for a user draft
is temporary and expected. It never counts as a retry.

The herdr adapter reads the pane with ~herdr agent read <pane> --source
visible~ and parses the input box per agent kind. Claude Code is the
only kind it parses now. The message stays queued, and ~status~ shows
one of these:

- ~held: user draft in composer~: the user has typed text and not
  submitted it, or the box is in ~!~ shell mode.
- ~held: draft-unknown~: the screen did not parse or could not be read.
- ~held: pane focused~: an agent kind with no parser, while the pane is
  focused. It is delivered once the pane is unfocused. A pane whose box
  can be parsed is delivered even while focused.

The composer is read again right before the paste. A draft that
appeared in between holds the message until the next pass. The
~deliver_attempt~ event with ~detail=composer-empty-at-check~ shows the
check ran. The race narrows but cannot close. ~delivered~ logs how long
the message was held. ~--ttl~ still applies to a held message.

The prompt guard from ~agentbus install-hooks~ catches what the race
lets through. A Claude Code prompt with an envelope header
(~[agentbus m-~) after other text is a bus message pasted into a user
draft. The guard blocks that submit. Claude Code keeps the whole text in
the input box, and the block reason tells the user to delete the
~[agentbus m-…]~ part and submit again. The bus re-queues the message by
its id, logs a ~requeued~ event, and holds it as ~held: user draft in
composer~ until the box is empty. If the bus cannot re-queue it, the
reason says so, and the copy in the input box is the only one. A prompt
that starts with the envelope is a clean delivery and passes.

* Other herdr machines

A handle is ~herdr:<machine>/<session>/<pane>~. ~<machine>~ is ~local~
or a herdr saved-machine label or id. For any other machine, every herdr
call the adapter makes runs as ~herdr --machine <machine> ...~, so
~send~, ~register~ claims, ~release --to~, and liveness all work with a
remote handle. A pane missing from a reachable machine is ~gone~.

List the machines whose agents ~search~ shows in
~$XDG_CONFIG_HOME/agentbus/config.toml~ (default
~~/.config/agentbus/config.toml~). agentbusd reads it at start.

#+begin_src toml
machines = ["linux2"]   # saved herdr machines to include in search
remote_timeout = "5s"   # bound on each call to another machine (default 5s)
#+end_src

Every call to another machine has an overall deadline that kills herdr
and its ssh, because SSH can hang on a locked key instead of failing. A
machine that cannot be reached is one of two causes:

- ~host unreachable~: the connection failed, or ~herdr machine status~
  reports the machine down or disabled. Fix the network.
- ~authentication locked (unlock your SSH/gpg agent)~: the host answers,
  but the call failed with an auth error or hit the deadline. Unlock the
  agent.

A message to such a machine is held, never failed, and retried like a
blocked pane; it does not count as a retry. ~status~ shows, for
example, ~held: machine linux2 unreachable: host unreachable~. A name
held by a pane on that machine stays held. ~search~ lists the other
agents and prints one warning line per machine on stderr, and still
exits 0. Each machine is flushed on its own, so a slow machine does not
hold up local delivery.

* Hub mode: a second machine

One machine, the hub, runs agentbusd. A second machine reaches it over
ssh and runs the same ~agentbus~ commands against the hub's daemon, so
there is one bus. On the second machine, set the hub and this machine's
herdr label as the hub knows it:

#+begin_src toml
hub = "me@hub"          # ssh target that runs agentbus (AGENTBUS_HUB overrides it)
machine = "linux2"      # this machine's herdr saved-machine label on the hub
remote_timeout = "5s"   # ssh connect timeout (default 5s)
#+end_src

Then every command except ~help~, ~install~, and ~install-hooks~ runs as
~ssh -o BatchMode=yes -o ConnectTimeout=<n> <hub> agentbus <args>~,
with each argument quoted. stdout, stderr, and the exit code come back
unchanged. ~send~ forwards stdin, and reads a ~--file~ path here and
sends its content, so the hub never needs the path. Commands that
identify the caller (~register~, ~describe~, ~whoami~, ~release~,
~send~, ~reply~) send ~herdr:<machine>/<session>/<pane>~ for this pane
as ~AGENTBUS_AS_HANDLE~. The hub trusts it only when ~SSH_CONNECTION~
shows the command came over ssh, and replies go back through
~herdr --machine <machine>~. agentbusd refuses to start, and
~agentbus install~ installs the tunnel below instead of a daemon.

The hub must be reachable without a prompt:

- an SSH key the agent holds, because ~BatchMode=yes~ never asks for a
  passphrase;
- ~agentbus~ on the hub's ~PATH~ for a non-interactive ssh command, and
  ~XDG_RUNTIME_DIR~ set there, for example in ~~/.zshenv~;
- a POSIX login shell (sh, bash, or zsh) on the hub, which runs the
  quoted command;
- this machine saved in the hub's herdr as ~machine~.

The hub's shell writes a ready line before agentbus starts. Until it
does, the call has a deadline of twice the connect timeout, which kills
ssh if a locked key makes it hang. After that the command runs as long
as it needs, so ~log --follow~ and ~send --wait~ work. A hub that
cannot be reached fails the command with
~agentbus: hub me@hub unreachable: host unreachable~ when a one-second
TCP connect to its SSH port fails, or with
~... unreachable: authentication locked (unlock your SSH/gpg agent)~
when the host answers. agentbus never falls back to a local daemon. The
installed hooks exit 0 on this error.

** Share one SSH connection

Each hub-mode command opens an ssh connection, and the installed hooks
run on every SendMessage and every prompt. Let ssh reuse one
connection to the hub, so a call skips the TCP and key exchange. On
the second machine, in ~~/.ssh/config~:

#+begin_example
Host hub
  HostName hub.example.com
  User me
  ControlMaster auto
  ControlPath ~/.ssh/cm-%C
  ControlPersist 10m
#+end_example

Then set ~hub = "hub"~. The first call opens the master connection, and
calls in the next ten minutes reuse it. ~ssh -O exit hub~ closes it.

** Talk to the hub daemon over a forwarded socket

The hub's agentbusd also listens on ~$XDG_RUNTIME_DIR/agentbus/hub.sock~
for callers on other machines. A request there must carry the caller's
~herdr:<machine>/<session>/<pane>~ handle and the client's protocol
version. The hub refuses a request without a handle, with a
~herdr:local/...~ handle, or with another protocol version
(~hub daemon speaks protocol N, this client speaks M~). It ignores the
client's environment, so ~AGENTBUS_AS_HANDLE~ plays no part there. The
local ~daemon.sock~ keeps its rules.

On the second machine, forward that socket to
~$XDG_RUNTIME_DIR/agentbus/tunnel.sock~. The client cannot know the
hub's ~XDG_RUNTIME_DIR~, so name the hub's socket in the config:

#+begin_src toml
hub_socket = "/run/user/1000/agentbus/hub.sock"  # the hub's $XDG_RUNTIME_DIR/agentbus/hub.sock
#+end_src

Then run ~agentbus install~ on the second machine. In hub mode it writes
and loads a tunnel unit instead of a daemon: the launchd job
~com.agentbus.tunnel~ on macOS, or the systemd user unit
~agentbus-tunnel.service~ on Linux. Without ~hub_socket~ it refuses and
says what to set. The unit creates the socket's directory and runs

#+begin_src sh
ssh -N -o BatchMode=yes -o ExitOnForwardFailure=yes \
  -o StreamLocalBindUnlink=yes -o ServerAliveInterval=30 \
  -L "$XDG_RUNTIME_DIR/agentbus/tunnel.sock:/run/user/1000/agentbus/hub.sock" -- hub
#+end_src

and starts it again whenever it exits. ~StreamLocalBindUnlink=yes~
removes a stale socket left by a dropped tunnel before it binds again.
The ssh path is resolved when you run ~install~, and the unit runs
without a terminal, so the key must work without a prompt.

While the tunnel socket is there and the hub answers a ping on it in
this protocol, a command from a herdr pane runs here and sends its
requests over the socket: ~register~, ~describe~, ~whoami~, ~release~,
~list~, ~search~, ~send~, ~reply~, ~show~, ~thread~, ~status~, ~log~,
~hook~, and ~prompt-hook~. No ssh login or remote shell starts. ~log~
streams the hub's event log from its daemon, and ~log --follow~ and
~send --wait~ hold their connection without a deadline; the hub daemon
serves other callers meanwhile. Otherwise the command uses ssh as
above: when the socket is missing or nobody answers on it, when the
caller is not in a herdr pane, and, after printing the version error,
when the protocols differ.

* Workdir lease

Several agents can share one checkout. The lease says who may change
it right now. Each machine lists its guarded checkouts, the git
top-levels that need the lease, in its config:

#+BEGIN_SRC toml
lease_checkouts = ["/home/u/src/repo"]
#+END_SRC

Every ~lease~ subcommand takes ~--path~ (default: the current
directory, resolved to its git top-level) and ~--json~. The checkout
key is ~<machine>:<git top-level>~, such as ~local:/home/u/src/repo~.
A path outside every guarded checkout, or in a separate repository or
worktree nested inside one, is not guarded.

#+BEGIN_SRC bash
agentbus lease claim --for 40m --why "issue 623"
agentbus lease extend --for 20m
agentbus lease leave
agentbus lease status --all
agentbus lease check --path src/main.go
agentbus lease release
#+END_SRC

| Subcommand | What it does |
|------------+--------------|
| ~claim --for <d> [--urgent] [--why <text>]~ | Take a free checkout, or join its queue. Never blocks. Prints ~granted until HH:MM~ or ~queued, position N (holder X, bid ends HH:MM)~. |
| ~extend --for <d>~ | Holder only. Move the soft deadline to now plus ~--for~. |
| ~leave~ | Leave the queue. |
| ~status [--all]~ | Holder, deadline, state, and queue. ~--all~ lists every checkout the daemon has seen. |
| ~check~ | Exit 0 when you hold the lease or the path is not guarded, 1 with a one-line reason when you do not, 3 when it cannot tell. |
| ~release~ | Holder only. Leave the checkout clean on the default branch and hand it to the next waiter. See [[*Release]]. |

The queue puts the user first, then ~--urgent~ claims, then the rest,
each in arrival order. Claiming again as the holder or a waiter keeps
the place and updates ~--for~ and ~--why~. A free checkout whose tree
is dirty, or has a rebase, merge, cherry-pick, or revert in progress,
is granted in state ~needs-adopt~; ~check~ refuses it until it is
adopted. ~check~ on an unguarded path reads only the local config and
never contacts the daemon.

~status --json~ prints this shape, which other tools read and which
stays stable. ~--all~ prints an array of them. ~state~ is ~free~,
~held~, ~paused~, ~releasing~, or ~needs-adopt~. ~holder~ is absent
when the checkout is free. ~name~ is the registered name, or empty.

#+BEGIN_SRC json
{"checkout": "local:/home/u/src/repo", "state": "held",
 "holder": {"handle": "...", "name": "...", "since": "RFC3339",
            "deadline": "RFC3339", "why": "..."},
 "queue": [{"handle": "...", "name": "...", "urgent": false,
            "for": "40m", "since": "RFC3339"}],
 "backup_ref": "... (only when there is one)"}
#+END_SRC

The daemon keeps lease state in ~leases.json~ in its state directory,
so a restart keeps holders, queues, and deadlines. Every claim, grant,
extend, leave, release, and skip is a ~lease_claim~, ~lease_grant~,
~lease_extend~, ~lease_leave~, ~lease_release~, or ~lease_skip~ event
in the event log, with the checkout key as its name. In hub mode,
~lease~ refuses a guarded path for now; ~check~ on an unguarded path
still passes.

** Release

~lease release~ runs its git steps in the CLI, on the checkout's
machine:

1. Refuse when the tree is dirty (modified, staged, or untracked and
   not ignored), listing the files. Unpushed commits on a branch are
   fine.
2. Refuse when a rebase, merge, cherry-pick, or revert is in progress.
3. ~git switch~ to the default branch, the one ~origin/HEAD~ points at
   (set it with ~git remote set-head origin --auto~), then ~git pull
   --rebase --prune~. A failed pull is reported and the release goes
   ahead; a pull that stops mid-rebase is aborted so the tree stays
   clean. A failed switch keeps the lease with you.
4. Tell the daemon, which grants the next waiter. While the git steps
   run, the state is ~releasing~.

The daemon grants the first waiter whose pane is not ~gone~ and drops
the gone ones from the queue. The new holder gets an agentbus message
from ~agentbus~:

#+BEGIN_SRC text
[lease] granted local:/home/u/src/repo until 10:40 (for: issue 624). Release with: agentbus lease release
#+END_SRC

With nobody waiting, the checkout becomes ~free~. A failed pull is
the ~lease_release~ event's reason.

** Soft deadline and check-in

The ~--for~ bid is soft: it never cuts anyone off by itself. When a
holder's bid ends, the daemon sends it a check-in from ~agentbus~:

#+BEGIN_SRC text
[lease] your bid on local:/home/u/src/repo ended. Run 'agentbus lease extend --for <d>' or 'agentbus lease release'.
#+END_SRC

Then, every check interval, it reads the holder's herdr state:

- ~working~ or ~blocked~: extend the bid silently by one interval. The
  check-in is sent again at most every ~lease_checkin_repeat~.
- ~idle~, ~done~, or ~no-agent~, with no ~extend~ or ~release~ since
  the check-in: start a silence timer. After ~lease_idle_grace~ of
  continued idle and silence, take over.
- ~unknown~ (the machine cannot be reached): never take over; keep
  waiting. The silence timer starts over.

With nobody queued, an overrun holder is checked in on once and then
left alone. A holder whose pane herdr reports ~gone~ is taken over at
once when a waiter is queued, without waiting for the bid to end. The
user's hold is never checked in on. ~extend~ or claiming again resets
the check-in.

Takeover itself is not built yet: the daemon logs a ~lease_takeover~
event with detail ~would take over~ and the reason. Each check-in and
silent extend is a ~lease_checkin~ or ~lease_auto_extend~ event. The
timers are kept in ~leases.json~, so they survive a daemon restart.

The daemon reads the timing from its config:

#+BEGIN_SRC toml
lease_check_interval = "2m"   # how often, and how far a working holder is extended
lease_checkin_repeat = "15m"  # least time between check-ins
lease_idle_grace = "5m"       # idle and silent this long: take over
#+END_SRC

* Lost messages

When something seems lost, check ~agentbus status <id>~ and
~agentbus log~ before resending. ~status~ prints the state and how long
the message has waited. Resending first creates a second message.

* Sandbox

The CLI has to connect to the daemon socket. That socket is
~$XDG_RUNTIME_DIR/agentbus/daemon.sock~. The state directory is
~$XDG_STATE_HOME/agentbus~, or ~$HOME/.local/state/agentbus~ when
~XDG_STATE_HOME~ is unset. Both the runtime directory and the state
directory are required. The CLI reports a missing one instead of
guessing.

The daemon needs that state directory. It also needs the ~herdr~
command and the herdr socket for the local server the panes use. Without
them it cannot see panes or deliver.

~agentbus install~ is the supervisor: a launchd plist on macOS, or a
systemd user unit on Linux. The CLI still starts ~agentbusd~ itself when
the daemon is down. That start is detached, in its own session. If the
CLI cannot reach the daemon and cannot start it, the command fails and
the error says so:

- ~agentbus: agentbusd is not running and no daemon binary was given to start it~
- ~agentbus: start agentbusd: ...~
- ~agentbus: agentbusd did not become ready: ...~
- ~agentbus: XDG_RUNTIME_DIR is not set; the agentbus daemon socket needs it~
- =agentbus: HOME is not set; agentbus state belongs in ~/.local/state/agentbus=

~agentbusd~ is the binary next to ~agentbus~. A sandbox that cannot
reach the socket and cannot execute that binary gets one of those
errors.

* Install

~agentbus install~ writes the supervisor unit and loads it. On macOS the
file is ~$HOME/Library/LaunchAgents/com.agentbus.agentbusd.plist~. On Linux
it is ~$XDG_CONFIG_HOME/systemd/user/agentbus.service~, or
~$HOME/.config/systemd/user/agentbus.service~ when ~XDG_CONFIG_HOME~
is unset.

~agentbus install-hooks~ writes a Claude Code ~PreToolUse~ hook on
~SendMessage~ to the user settings only, ~$HOME/.claude/settings.json~,
and the script ~$HOME/.claude/hooks/agentbus-sendmessage.sh~. It does not write
a project's ~.claude/settings.json~ or ~settings.local.json~. The hook
lets the tool call proceed. It records a bypass event and exits 0. If
~agentbus~ is not on ~PATH~, or the bus is down, the hook exits 0 and
the tool call is unchanged.

When the ~SendMessage~ target is a registered name, or the handle or
pane id of an agent that holds one, the hook also prints a hint. It
uses ~hookSpecificOutput.additionalContext~ with no permission
decision, so Claude Code adds the hint to the agent's context and still
runs the call:

#+begin_example
This recipient is coord/primary on agentbus. Next time use: agentbus send coord/primary "..."
#+end_example

A handle that holds several names gives the first in name order. A pane
id held in two sessions, or any other target, gives no hint. The bypass
event keeps the raw target in ~name~ and the bus name in ~resolved~, so
~agentbus log --event bypass~ shows who should have been addressed. The
lookup reads only the registry. If the daemon is down, fails, or takes
longer than one second, the hook prints nothing and exits 0.

The same command writes a ~UserPromptSubmit~ hook, the script
~$HOME/.claude/hooks/agentbus-userpromptsubmit.sh~, which runs
~agentbus prompt-hook~. It blocks a prompt only when an agentbus
envelope follows other text, as described under "Delivery and user
drafts". If ~agentbus~ is not on ~PATH~, the prompt goes through.
Running ~install-hooks~ again updates both entries in place. Other
hooks and settings are kept.
