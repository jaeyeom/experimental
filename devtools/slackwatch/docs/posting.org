Read this when a draft is stuck, or you need the approval and retry rules.
Everyday posting is in [[file:../README.org::*Posting through decide][Posting through decide]].

* Posting

~slackwatch post~ routes outbound Slack drafts through the shared
[[file:../../pkg/outbox/README.md][devtools/pkg/outbox]] confirmation
boundary before posting: drafts are hashed (~outbox.Digest~), shown to the
user in [[file:../../decide/README.org][decide]], verified for human UI
provenance (~outbox.EvaluateApproval~), executed via ~outbox.ExecuteSteps~
(direct mode) or ~awaiting-handoff~ (handoff mode, with self-post matching
isolated behind ~slackwatch.OwnPostLinker~ so the inbound thread watcher
stays decoupled), and notified via ~outbox.Transport~ / ~slackwatch.Notifier~.
Posting is off until ~post.mode~ is set; without it, ~post~ refuses.

| Command | Does |
|---------+------|
| ~post --to DEST (--text-file F \vert --canned ID) --owner T --purpose S [--ref R ...] [--supersedes ID] [--owner-unchecked] [--json]~ | Store the draft and file its decide item. Prints the outbox id. ~--canned~ posts a pre-approved text from config without a decide item (thread permalink only). ~--supersedes~ links an older draft that is still open or finished without a post (rejected, cancelled, dropped, mismatch, failed) once this one is stored; an open or failed one is cancelled. |
| ~canned ls [--json]~ | List configured canned responses, their scopes, SHA-256 text hashes, and use counts. |
| ~outbox ls [--state S] [--json]~ | List outbox records. |
| ~outbox show <id> [--json]~ | Show a record, ending with its exact text. |
| ~outbox posted [--manual] <id> <permalink>~ | Report a handoff post, or with ~--manual~ a post made by hand. |
| ~outbox recheck <id>~ | Read a mismatch post back again with the current config. A pass moves it to ~posted~. A failure prints the remaining problems and exits non-zero. A post that was deleted moves the record to ~cancelled~ with the reason ~post deleted~. Either way the result is replied on the decide item, which is then closed. Nothing is posted. |
| ~outbox poke <decide-id>~ | Handle the answer to a decide item now. |
| ~outbox cancel <id> [reason \vert --reason S]~ | Withdraw a draft that is not posted. A ~mismatch~ record, or a ~posted~ record whose message is gone, is closed too, for example ~outbox cancel 12 "post deleted"~. |
| ~outbox retry <id>~ | Post a failed direct record once, or return a failed handoff record to ~awaiting-handoff~. |
| ~outbox repair [--channel <id>=<D…> ...]~ | With no ~--channel~, list records whose channel is still a user id. It does not call Slack. With ~--channel~, rewrite only those records and their watches onto the given ~D…~ channel, merging a duplicate watch. A record whose channel is in ~inbound.ignoreChannels~ is printed as ~skipped (ignored channel)~ and left unchanged, even when a mapping names it. |
| ~pin~ | Check the write token with ~auth.test~ and pin it in the config. |

~DEST~ is a channel id, a ~#name~, an ~@name~, a user id (~U…~), or a
message permalink, which posts into that thread. An ~@name~ posts as
its cached user id. Resolving a name that is not cached needs
~users:read~ (an address needs ~users:read.email~). ~missing_scope~
refuses and asks for the user id. ~im:write~ is not used.

1. *Submit.* ~post~ stores the destination, the exact text, its SHA-256,
   the owner, the purpose, and the refs as a ~pending~ record.
2. *Ask.* It files a decide item. ~relay~ is decide's kind for a choice
   among options. The command is ~decide ask~ with:

   - ~--owner <post.decideOwner>~
   - ~--owner-replies-only~ when this decide accepts that flag, and the
     same command without it when it does not
   - ~--notify-pane <post.decideNotifyPane>~ when that key is set. A
     later ~decide reply~ reuses the item and keeps its pane.
   - ~--kind relay~
   - ~--option yes:"Post as written"~
   - ~--option no:"Don't post"~
   - ~--option edit:"Edit (redraft)"~
   - ~--rec yes~
   - ~--free-text~
   - ~--long-lines~, on this ask and on each ~decide reply~ slackwatch
     writes, so decide's line limit for agents does not refuse text
     slackwatch builds itself. A decide without the flag gets the same
     command again without it.

   The question shows the destination (and the thread permalink), the
   text in a quoted block, the owner, the purpose, and the first 8 hex
   digits of the hash.

   ~HERDR_PANE_ID~ is the [[https://herdr.dev/][herdr]] pane id of this process.
   ~DECIDE_AS_HANDLE~ is the handle ~herdr:<machine>/<session>/<pane>~
   that decide would store for that pane. ~notifyPane~ is the pane
   decide would prompt. ~decide~ runs without those two variables, so
   the item has no agent ~notifyPane~ even when an agent runs
   ~slackwatch post~ from its pane. A reply slackwatch itself posts on
   that item is recorded as the decide owner, so an owner-only item
   accepts it.
3. *Answer.* ~serve~ polls ~decide show --json~ for every pending record
   every 30 seconds.

   - After ask, and on each poll of an open item with no human message,
     slackwatch checks that the item still lists ~yes~ and ~no~ (or legacy
     ~post~ and ~drop~).
   - If they are missing, it re-attaches them once with ~decide reply~
     using ~yes~, ~no~, and ~edit~, ~--rec yes~, ~--free-text~, and the
     same question, logs it, and sends the record's owner
     ~outbox <id>: decide item lost its options; re-attached~.
   - A later loss, after the options are present again, is re-attached
     again.
   - ~decide~'s ~notifyTemplate~ can run ~slackwatch outbox poke <decide-id>~
     for an immediate pickup when the owner is ~post.decideOwner~, so a
     reply lands with slackwatch and not in an agent's pane (see below).
     Polling stays the source of truth.
4. *Accept.* slackwatch reads the user's pick from the item's thread
   messages, not from its state or ~answer~: a later message reopens the
   item, and a later free-text message replaces ~answer~. A human
   message is one with author ~human~ and no ~by~; a message sent with
   ~by~ is an agent's, whatever its ~via~, and does not count. slackwatch
   acts on the latest human message. It posts only when that message
   picks ~yes~ (or legacy ~post~) with ~via~ ~ui~ (a message
   without ~via~ does not count), the stored text still matches its
   hash, and the record is still ~pending~. Agent replies after the pick
   do not cancel it.
   - A free-text message (or ~edit~) is the edit path: the record becomes
     ~needs-redraft~ and the owner gets the text as an ~outbox-redraft~
     notification. The owner submits a new ~post~ with ~--supersedes <id>~.
   - ~no~ (or legacy ~drop~) makes the record ~dropped~ and tells the owner.
   - A human message after a ~yes~ pick, such as ~no~ or free text,
     takes precedence and goes through those paths.
   - Any other ~yes~ pick, such as one given with the decide CLI,
     makes the record ~rejected~ and alerts the owner and
     ~fallbackTarget~.
     The owner can submit the draft again with ~--supersedes <id>~.
   - A decide item closed (~done~ or ~done-unread~) without an
     accepted ~yes~ pick made before ~doneAt~ (or whose latest human
     message is ~no~, free text, or not before ~doneAt~) makes the
     record ~cancelled~; a valid ~yes~ pick made before ~doneAt~ still
     posts as usual.
   - A ~withdrawn~ decide item always makes the record ~cancelled~,
     even after a ~yes~ pick (withdrawal is the owner retracting the
     request).
   - Every outcome closes the decide item with ~decide done~, except
     ~failed~ and ~mismatch~, which leave it open so the user sees them.
5. *Post.*
   - *handoff:* the record becomes ~awaiting-handoff~ and ~post.agent~
     gets ~approved post ready: <id>~. That agent reads the record with
     ~outbox show~, checks its own Slack identity, posts the text
     verbatim, and runs ~outbox posted <id> <permalink>~. slackwatch
     reads the message back with the read token and checks that the
     author is ~post.expectUser~ and the text matches.
   - *direct:* after the identity check below, slackwatch calls
     ~chat.postMessage~ with the text, a blank line, and ~post.footer~.
6. *Watch.* The post is watched with ~--source outbox~ for the owner,
   with the purpose and refs, and the decide item is closed with the
   permalink.
7. *Reply and close.*
   - By default (~post.successReply~ = ~none~), a successful post closes
     the decide item quietly with ~decide done --quiet~ (no success
     reply, marked read so it leaves the inbox, permalink recorded as
     the outcome). Set ~post.successReply~ to ~reply~ to post the
     ~Posted to ...~ reply and close with ~decide done~ instead.
   - When an approved record has not posted within ~post.stuckAfter~
     (default ~10m~), slackwatch replies once with the reason and leaves
     the item open and unread. If it posts later, it closes quietly and
     the stuck notice stays in the thread.
   - When a record ends ~mismatch~, slackwatch replies with the mismatch
     details and leaves the item open and unread.
   - When a record ends ~failed~, slackwatch replies with ~Post failed.~
     and puts ~yes~, ~no~, and ~edit~ back, leaving the item open.
   The same behavior follows ~outbox posted~ (with or without ~--manual~),
   ~outbox recheck~, and ~outbox retry~.

The handoff comparison strips the footer before it compares text.

- ~footerPattern~ finds where the footer starts. Everything from that
  match through the end of the message is dropped, plus one Slack marker
  (asterisk, underscore, or strikeout) immediately before the match and
  the whitespace before that marker.
- An inline footer " *Sent using* <@U1>" is dropped by
  ~Sent using\*? <@U1>~.
- Slack's ~&amp;~, ~&lt;~, and ~&gt;~ escaping is undone. Trailing
  whitespace on each line and at the end is trimmed.
- In handoff mode a connector link ~<url|label>~ is read back as ~url~
  when the label is the URL, the URL without its scheme, or a truncated
  prefix of either ending in ….
- Slack's auto-links are read back as their text: ~<mailto:X|X>~ as
  ~X~, and ~<tel:X|Y>~ as ~Y~ when ~Y~ shows the same digits as ~X~. A
  mail link with a different label stays as it is.
- Runs of blank lines on either side count as one line break.
- Any other difference is a mismatch, including a bold or italic change
  and an unrelated link label.
- On a mismatch the watch is still registered for the owner and flagged,
  the record becomes ~mismatch~, and the owner and ~fallbackTarget~ get
  both texts. slackwatch never edits or deletes the post.

While a record is ~awaiting-handoff~, an own post in its destination
whose text matches is linked to it: it is watched for the owner instead
of becoming an unowned footer watch. ~outbox posted~ then confirms the
link; naming a different message makes the record a ~mismatch~.

When an approved draft is posted by hand, for example because ~serve~
could not reach decide, ~outbox posted --manual <id> <permalink>~
records it.

- It accepts a ~pending~ or ~awaiting-handoff~ record.
- It accepts a ~needs-redraft~ record only when the thread has a
  verified approval of the current draft: an ~optionKey~ ~yes~ (or
  legacy ~post~) answer by ~human~ via ~ui~, after the latest message
  that carries this draft's text hash. Anything else is refused.
- For a ~pending~ record it first reads the decide item and applies the
  same acceptance rule as step 4. When the rule refuses it, the command
  fails with ~no ui approval found for <id>: <reason>~ and changes
  nothing.
- A manual post never bypasses approval. Free text is not an approval.
- The read-back, author, and text checks are the handoff ones. A match
  makes the record ~posted~, watches it for the owner with
  ~--source outbox~, and closes the decide item with the permalink. A
  difference makes it ~mismatch~ and alerts.
- The record notes ~manual: true~.

The decide items slackwatch files belong to slackwatch, and agents do
not reply in their threads (the skill says so). To send an answer on
those items to slackwatch at once, give ~decide~'s ~notifyTemplate~
(in ~$XDG_CONFIG_HOME/decide/config.json~ on the machine that holds the
ledger) a branch for ~post.decideOwner~ that runs ~outbox poke~. It
must run where slackwatch's state lives. Every other owner keeps the
usual pane prompt:

#+begin_src sh
if [ "$DECIDE_OWNER" = slackwatch ]; then
  slackwatch outbox poke "$DECIDE_ID"
else
  herdr ${DECIDE_MACHINE:+--machine "$DECIDE_MACHINE"} agent prompt "$DECIDE_PANE" "$DECIDE_THREAD_HEADER $DECIDE_ANSWER"
fi
#+end_src

As one JSON string:

#+begin_src json
{"notifyTemplate": "if [ \"$DECIDE_OWNER\" = slackwatch ]; then slackwatch outbox poke \"$DECIDE_ID\"; else herdr ${DECIDE_MACHINE:+--machine \"$DECIDE_MACHINE\"} agent prompt \"$DECIDE_PANE\" \"$DECIDE_THREAD_HEADER $DECIDE_ANSWER\"; fi"}
#+end_src

Direct mode checks its identity before it posts:

- ~slackwatch pin~ runs ~auth.test~ with the write token. When the user is
  ~post.expectUser~, it writes ~post.pinSalt~ (generated when unset) and
  ~post.tokenPin~, the hex SHA-256 of the salt followed by the token,
  into the config, and re-enables posting. It rewrites the config with
  sorted keys.
- Before every post, the token's pin must match ~post.tokenPin~. This is
  local, with no API call.
- When ~serve~ starts and whenever the token changes, ~auth.test~ must
  report ~post.expectUser~.
- A failed check disables posting until ~slackwatch pin~ runs again and
  alerts ~fallbackTarget~. Approved records wait in ~approved~ and post
  on the next poll (or ~outbox poke~) after the pin.
- When ~post.footer~ is set, ~footerPattern~ must find the start of that
  footer and remove it, so readers can tell an agent post from a typed
  one. Normalizing ~text~ plus the footer must yield ~text~. Otherwise
  ~post~ refuses and ~serve~ does not start posting.

A ~failed~ record can be resumed with ~outbox retry <id>~. It re-runs
the acceptance checks: the latest human message is a ~post~ pick with
~via ui~, the stored text still matches its hash, and the destination
in the decide question is unchanged. A failed check leaves the record
~failed~ and prints which check failed. Direct mode also checks the
identity pin, then searches the destination for a message from
~post.expectUser~ with this text in the last 15 minutes. A match is
registered as ~posted~ and nothing new is sent. Otherwise it posts
once, reads the message back, and moves the record to ~posted~ or
~mismatch~. Handoff mode does not post: the record returns to
~awaiting-handoff~ and ~post.agent~ gets ~approved post ready: <id>~
again.

A failed record whose decide item is still open is also retried
automatically. When the latest human message there is a new ~post~
pick made after the failure (compared to the second), the next poll or
~outbox poke~ runs the same ~outbox retry~ once: the same checks, and
the same search for a post that already landed. A pick from before the
failure never triggers it. If that retry fails too, the record stays
~failed~ and the thread gets another ~Post failed~ reply; a later
~post~ pick retries once more.

When ~chat.postMessage~ returns ~not_in_channel~, the ~outbox-failed~
notice (the decide reply and the notification) says the posting
account is not a member of the channel and names ~outbox retry~.
~channel_not_found~, ~is_archived~, and ~restricted_action~ name a
short fix and the same command. Any other error is reported as Slack
returned it. The stored reason stays the Slack error.

| State | Meaning |
|-------+---------|
| ~pending~ | Waiting for the decide answer. |
| ~approved~ | Accepted in direct mode, not posted yet (for example while posting is disabled). |
| ~posting~ | A direct post is in flight. Never retried, so never posted twice. |
| ~awaiting-handoff~ | Accepted in handoff mode, waiting for ~outbox posted~. |
| ~posted~ | Posted and watched. |
| ~needs-redraft~ | Answered with free text; the owner has the notes. |
| ~dropped~ | Answered ~drop~. |
| ~rejected~ | Not posted: the user's latest pick was not a ~post~ from the decide UI, or the text changed. |
| ~mismatch~ | The handoff post differs from the approved text, author, or destination. |
| ~cancelled~ | Withdrawn with ~outbox cancel~, its decide item was withdrawn or closed without an accepted pick before ~doneAt~, or its post was deleted (~outbox recheck~). ~status~ does not count it. |
| ~failed~ | ~decide ask~ or ~chat.postMessage~ failed. ~outbox retry~, or a new ~post~ pick in its decide item, resumes it. |

~status~ shows the posting mode and counts the ~pending~,
~awaiting-handoff~, and ~needs-redraft~ records. It exits 1 while direct
posting is disabled.
