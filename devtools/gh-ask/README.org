#+TITLE: gh-ask
#+DATE: 2026-11-15

gh-ask adds an "Ask agent" button to GitHub pull request pages. You
select lines or the whole pull request, type a question, and gh-ask
passes it to a command you choose, usually a coding agent running
locally on your machine. The answer shows in a side panel on the page
and is never posted to GitHub. A small server listens only on
127.0.0.1, and a browser userscript talks to it.

A thread is the conversation id your ~ask_command~ prints. A later
question on the same pull request can reuse that id. ~deep~ is a flag
copied into the message file for your command to interpret; gh-ask
does not. A follow-up is a later question on an open thread. gh-ask
runs ~followup_command~ for it instead of starting another thread.

#+BEGIN_EXAMPLE
Files changed
  pkg/a.go  line 10                         [Ask agent]
                                            Asked in 3f2a · waiting

gh-ask panel
  You    Why is this retried?
  Agent  Because the write can fail.
  Read-only. Nothing here is posted to GitHub.
#+END_EXAMPLE

* Setup

Do these in order. The server will not start until the config and
the token file both exist.

1. [@1] Install the command:

#+BEGIN_SRC bash
go install github.com/jaeyeom/experimental/devtools/gh-ask/cmd/gh-ask@latest
#+END_SRC

2. [@2] Save the five-line program below as an executable. It needs no
agent. gh-ask does not run a shell and does not expand a home
shortcut, so the config names this file by its absolute path.
~chmod +x~ it after you save it.

#+BEGIN_SRC bash
#!/bin/sh
n=$(date +%s)
mkdir -p "$HOME/gh-ask-inbox"
cp "$1" "$HOME/gh-ask-inbox/thread-$n.txt"
printf 'thread-%s\n' "$n"
#+END_SRC

3. [@3] Write the config. The default path is
=~/.config/gh-ask/config.toml=. When ~XDG_CONFIG_HOME~ is set, the
file is =$XDG_CONFIG_HOME/gh-ask/config.toml= instead. ~repos~ lists
the ~owner/name~ repositories the server accepts. ~id_pattern~ is
required; without a capture group, the id is the whole match. Setting
reuse to none means every question runs this program.

#+BEGIN_SRC toml
repos = ["octo/demo"]
ask_command = ["/ABSOLUTE/PATH/gh-ask-inbox", "{file}"]
id_pattern = 'thread-[0-9]+'
reuse = "none"
#+END_SRC

Replace ~octo/demo~ with a repository you review, and replace the
absolute path with the script. ~{file}~ is the message file gh-ask
writes for this question.

4. [@4] Create the token:

#+BEGIN_SRC bash
gh-ask token
#+END_SRC

That writes 32 random bytes, hex encoded, to a ~token~ file next to
the config, mode ~0600~. It prints the existing token when the file
is already there. Both ~gh-ask token~ and ~gh-ask serve~ take
~--config~ when the file is not at the default path.

5. [@5] Start the server:

#+BEGIN_SRC bash
gh-ask serve
#+END_SRC

It prints ~gh-ask: listening on 127.0.0.1:8765~ and stays in the
foreground. It refuses to start without the token file, and it
refuses a token file that group or others can read. The default
listen address is ~127.0.0.1:8765~. Any other address is refused.

6. [@6] Install the userscript in Violentmonkey or Tampermonkey.
   - Open
     =https://github.com/jaeyeom/experimental/raw/main/devtools/gh-ask/userscript/gh-ask.user.js=
     and confirm the install, or paste
     [[file:userscript/gh-ask.user.js][the userscript]] into a new
     script.
   - On a pull request page, open the userscript manager's menu and
     pick "Set gh-ask token / port". Paste the output of ~gh-ask token~,
     then enter the port, 8765 unless you changed ~listen~. An empty
     token answer keeps the stored token.
   - The token and port stay in the userscript manager. They are not
     written into the page or into a URL.

* Try it without an agent

With ~gh-ask serve~ still running, send one whole-PR question. Use a
repository that is listed in ~repos~. ~head_sha~ must be hex, 7 to 64
characters; gh-ask does not check that the commit exists. ~page_url~
must be an ~https://github.com/~ link.

#+BEGIN_SRC bash
curl -s -X POST http://127.0.0.1:8765/ask \
  -H "Content-Type: application/json" \
  -H "X-Gh-Ask-Token: $(gh-ask token)" \
  -d '{"repo":"octo/demo","pr":42,"head_sha":"0123456789abcdef","question":"Is the retry in the right place?","deep":false,"page_url":"https://github.com/octo/demo/pull/42"}'
#+END_SRC

The body is one JSON object and a newline. The digits are the
timestamp the script printed:

#+BEGIN_EXAMPLE
{"id":"thread-1710000000"}
#+END_EXAMPLE

The question is now in =~/gh-ask-inbox/thread-1710000000.txt=. gh-ask
deletes its own temp copy when the script exits, so a command that
hands the file to something asynchronous must copy it first. A
successful ask does not print a server log line.

* Using it on GitHub

The userscript adds "Ask agent" on the pull request Files changed
view, both ~/pull/<n>/files~ and the newer ~/pull/<n>/changes~ page.
Hover a numbered diff line and the button sits on that line.
Selecting text inside one file's diff puts the button at the end of
the selection. A selection that crosses files is refused. A question
about the whole pull request goes in the side panel, with no line.

The button opens a popover with a question box, a ~deep~ checkbox,
and Send. Cmd+Enter or Ctrl+Enter sends. Enter stays a newline. The
popover stays inside the window.

Send stores the question on the thread for that pull request. The
line gets a chip: ~Asked in <id> · waiting~,
then ~answered~ or ~closed~ when the status says so. The chip is
polled every 20 seconds while the tab is visible, for at most 30
minutes. A failed send stays in the popover so you can send it again.
The chip and the popover show the failure: auth failure, forbidden,
too large, rate limit, the command failed, or the server is down.

A ~gh-ask~ button in the sticky pull request header opens a read-only
side panel. On a page without that header it sits next to the title.
It is on every pull request tab, including Conversation and Commits,
and it stays up when GitHub changes tabs without a reload.
The diff buttons are only on the files and changes views.

Opening the panel loads the stored thread. Each message shows You,
Agent, or Note, and the time in local time, oldest first, newest at
the bottom. A closed thread shows ~closed~. When nothing is stored
yet, the panel says "No question yet" and still offers a question
box. A question with no line asks about the whole pull request.
Clicking a status chip opens the same panel. A chip on a line
sends the follow-up as a line question; anything else sends the
whole pull request. Cmd+Enter or Ctrl+Enter sends.

The panel polls every 20 seconds while the tab is visible and the
newest message is from you, and every 60 seconds otherwise. It stops
after 30 minutes with no new message. Refresh starts that window
again. Nothing is polled while the panel is closed, except a chip
that is still waiting.

Message text is plain. URLs stay text, and nothing in the panel is
posted to GitHub. The footer is "Read-only. Nothing here is posted
to GitHub."

* Writing your own commands

The commands are fixed in the config. gh-ask is not a generic exec
service: request text reaches a command only through a file. Each
command runs with no stdin, the server's environment, and
~command_timeout~. ~ask_command~ and ~followup_command~ keep running
if the browser disconnects. ~status_command~ is stopped when the
browser disconnects.

** ask_command

~ask_command~ is an argv, not a shell command. Only ~{file}~, ~{pr}~,
and ~{repo}~ are replaced. Unknown placeholders are errors. The
program must print an id that ~id_pattern~ matches. When the pattern
has a capture group, that group is the id. Otherwise the whole match
is the id. The id is at most 256 bytes and has no control characters.
Stdout with no match is a 502, ~ask_command printed no id~.

** When a command fails

~ask_command~, ~followup_command~, and ~status_command~ failures are a
502 with a short error that says why:

| Error                                    | Meaning                                  |
|------------------------------------------+------------------------------------------|
| ~<name> timed out after <command_timeout>~ | the command was killed at its timeout    |
| ~<name> exited with status N: <detail>~  | non-zero exit; ~<detail>~ is the last non-empty line of stderr |
| ~<name> exited with status N~            | non-zero exit and nothing on stderr      |

~<detail>~ has control characters removed and is cut to 200 bytes. The
last line of stderr therefore reaches the browser, so keep secrets out
of it. Only a caller that holds the token gets the response. Stdout,
the token, and the environment are never in it. The server log keeps
the full stderr.

** The message file

The request is written to a mode-0600 temp file. A line question
looks like this:

#+BEGIN_EXAMPLE
[gh-ask] PR 42 · pkg/a.go:10-12 (RIGHT) · deep=no
Commit: 0123456789abcdef0123456789abcdef01234567
Lines: new lines 10-12 (RIGHT, head side)

Question:
Why is this retried?

Selected:
for i := 0; i < 3; i++ {

Link:
https://github.com/octo/demo/pull/42/files#diff-...
#+END_EXAMPLE

Code is no longer included unless the user selected text in the diff:
a hover ask omits the ~Selected:~ block. A whole-PR question omits
both ~Lines:~ and ~Selected:~:

#+BEGIN_EXAMPLE
[gh-ask] PR 42 · whole PR · deep=no
Commit: 0123456789abcdef0123456789abcdef01234567

Question:
Is this the right place for the retry?

Link:
https://github.com/octo/demo/pull/42/files
#+END_EXAMPLE

** Status

~status_command~ is optional. Only ~{id}~ is replaced. Its stdout is
one JSON object. ~state~, ~answered~, and ~closed~ are required.
~state~ is a string of at most 256 bytes with no control characters.
Other fields are dropped.

#+BEGIN_SRC json
{"state": "answered", "answered": true, "closed": false}
#+END_SRC

It may also print ~messages~, an array of objects:

#+BEGIN_SRC json
{"role": "you", "time": "2026-11-14T10:00:00Z", "text": "hello"}
#+END_SRC

~role~ is ~you~, ~agent~, or ~note~. ~time~ is RFC3339. ~text~ is a
string. The server returns the array oldest first and keeps at most
50 messages, the newest by time. Each ~text~ is cut to 16 KB on a
UTF-8 boundary. Control characters in ~text~ are removed, except
newline and tab. An unknown ~role~ is dropped. Unknown fields are
dropped. The response body is at most 256 KB; older messages are
dropped until it fits.

If ~messages~ is missing or null, the response is the three fields
only. If it is not an array of those objects, or a time is not
RFC3339, the field is left out, the server logs one line, and
~state~, ~answered~, and ~closed~ are still returned. A good result
is cached for 10 seconds per id. A failure of the three required
fields is not cached. Status requests do not use the ask rate limit.

** Thread reuse

~reuse = "per-pr"~ is the default. The server stores the id that
~ask_command~ printed for each repository and pull request in
=$XDG_STATE_HOME/gh-ask/threads.json=, or
=~/.local/state/gh-ask/threads.json= when ~XDG_STATE_HOME~ is unset.
It writes the file with mode ~0600~ to a temp file and renames it
into place. This mode requires ~followup_command~.

A later ask on the same pull request checks the stored id before
reusing it. When ~status_command~ is set, the ask uses a cached
status younger than about 10 seconds; otherwise it runs
~status_command~. ~closed~ true runs ~ask_command~, and the new id
replaces the stored one. If ~status_command~ fails, with a non-zero
exit, a timeout, or invalid JSON, the ask logs the reason and starts
a new thread too. When the status is still open, the ask runs
~followup_command~ with ~{id}~ and the new ~{file}~, ignores that
command's stdout, and returns the stored id. ~followup_command~
replaces ~{id}~, ~{file}~, ~{pr}~, and ~{repo}~. Without
~status_command~, a stored thread is reused until you remove it from
the state file.

Two asks on the same pull request at the same moment can both start
a thread; the one that finishes last is stored.

With ~reuse = "none"~, every ask runs ~ask_command~ and nothing is
stored. ~followup_command~ is then optional.

* Configuration

The block in Setup is enough to run the inbox script. This is the
full file. ~ask-agent~ is a placeholder. Replace it with your own
program. Unknown keys are errors.

#+BEGIN_SRC toml
# Only 127.0.0.1:<port> is accepted. Default 127.0.0.1:8765.
listen = "127.0.0.1:8765"
# owner/name repos the server accepts.
repos = ["octo/demo"]
# argv, run without a shell. Only {file}, {pr} and {repo} are replaced.
ask_command = ["ask-agent", "--message-file", "{file}", "--pr", "{pr}", "--repo", "{repo}"]
# Finds the id in stdout: group 1 if the pattern has a group, else the match.
id_pattern = 'thread-([0-9a-f]+)'
# Runs instead of ask_command for a later ask on a PR whose thread is
# open. Only {id}, {file}, {pr} and {repo} are replaced. Required unless
# reuse = "none".
followup_command = ["ask-agent", "--thread", "{id}", "--message-file", "{file}"]
# Optional. The default is per-pr. "none": every ask runs ask_command.
reuse = "per-pr"
status_command = ["ask-agent", "--status", "{id}"]  # only {id}; enables GET /status/<id>
rate_limit = 10            # asks per hour
command_timeout = "2m"     # applies to every command
token_file = "token"       # relative to the config file's directory
#+END_SRC

~rate_limit~ defaults to 10 asks per hour. ~command_timeout~ defaults
to ~2m~. ~token_file~ defaults to ~token~ next to the config. A
relative ~token_file~ is joined to the config's directory.

* HTTP API

The server has three endpoints. Errors are ~{"error": "..."}~ with a
short message; details go to the server log. On success, ~POST /ask~
returns ~{"id": "..."}~.

A whole-PR body, the same shape as the curl above:

#+BEGIN_SRC json
{"repo":"octo/demo","pr":42,"head_sha":"0123456789abcdef","question":"Is the retry in the right place?","deep":false,"page_url":"https://github.com/octo/demo/pull/42"}
#+END_SRC

** POST /ask

| Field        | Notes                                        |
|--------------+----------------------------------------------|
| ~repo~       | ~owner/name~, must be in ~repos~             |
| ~pr~         | positive integer                             |
| ~head_sha~   | hex commit id                                |
| ~path~       | file path, at most 1 KB, no control chars    |
| ~side~       | ~LEFT~ or ~RIGHT~                            |
| ~start_line~ | first line, 1 or later                       |
| ~end_line~   | last line, not before ~start_line~           |
| ~selection~  | code, at most 4 KB                           |
| ~question~   | non-empty, at most 2 KB                      |
| ~deep~       | boolean                                      |
| ~page_url~   | an ~https://github.com/~ link, at most 2 KB  |

~path~, ~side~, ~start_line~, ~end_line~, and ~selection~ are
optional, and all-or-none. A request with none of them is a question
about the whole pull request. A request with any of them must include
a valid path, side, and line range. A partial location is a 400.
~selection~ may still be empty on a line question.

| Status | Meaning                                                |
|--------+--------------------------------------------------------|
| 400    | bad JSON or a bad field                                |
| 401    | missing or wrong ~X-Gh-Ask-Token~                      |
| 403    | bad ~Host~, bad ~Origin~, or repo not in ~repos~       |
| 404    | not ~/ask~, ~/status/<id>~ or ~/thread~                |
| 405    | any method other than ~POST~, including ~OPTIONS~      |
| 413    | a field over its cap, or a body over 16 KB             |
| 429    | over the rate limit                                    |
| 502    | the command failed, timed out, or printed no id        |

** GET /status/<id>

#+BEGIN_SRC bash
curl -H "X-Gh-Ask-Token: $(gh-ask token)" http://127.0.0.1:8765/status/abc123
#+END_SRC

The server runs ~status_command~ with ~{id}~ and returns the cleaned
JSON from the Status section. Only ids that ~ask_command~ printed
answer: ids from this process, and with ~reuse = "per-pr"~, ids in
the state file.

| Status | Meaning                                                    |
|--------+------------------------------------------------------------|
| 401    | missing or wrong ~X-Gh-Ask-Token~                          |
| 403    | bad ~Host~ or bad ~Origin~                                 |
| 404    | an id this server did not create, or no ~status_command~   |
| 405    | any method other than ~GET~, including ~OPTIONS~           |
| 502    | the command failed, timed out, or printed bad JSON         |

** GET /thread

#+BEGIN_SRC bash
curl -G -H "X-Gh-Ask-Token: $(gh-ask token)" \
  --data-urlencode repo=octo/demo --data-urlencode pr=42 \
  http://127.0.0.1:8765/thread
#+END_SRC

Returns the id stored for that pull request, ~{"id": "..."}~,
including when the stored thread is closed. No command runs. With
~reuse = "none"~, or when nothing is stored for that pull request,
the response is 404.

| Status | Meaning                                              |
|--------+------------------------------------------------------|
| 400    | ~pr~ is not a positive integer                       |
| 401    | missing or wrong ~X-Gh-Ask-Token~                    |
| 403    | bad ~Host~, bad ~Origin~, or repo not in ~repos~     |
| 404    | nothing stored, or ~reuse = "none"~                  |
| 405    | any method other than ~GET~, including ~OPTIONS~     |
| 502    | the state file could not be read                     |

* Security

- The server binds only ~127.0.0.1~. Any other ~listen~ address is
  refused.
- All three endpoints get the same token, ~Host~, and ~Origin~ checks.
- ~X-Gh-Ask-Token~ must match the token file. The compare runs in
  constant time.
- No CORS headers are ever sent, and ~OPTIONS~ gets ~405~. A web page
  cannot send the token header cross-origin, so only a userscript or
  extension can call the server.
- ~Host~ must be ~127.0.0.1:<port>~ or ~localhost:<port>~. This blocks
  DNS rebinding.
- ~Origin~, when present, must be ~https://github.com~ or a
  ~chrome-extension://~, ~moz-extension://~, or
  ~safari-web-extension://~ origin.
- Requests rejected before the rate limit check do not use up the
  limit.

* Limitations

- GitHub's diff markup is not an API and changes without notice. When
  the button stops appearing or the payload is wrong, the update
  steps are under Development.
- The script loads on every github.com page. A match limited to the
  files URL never runs when you open Files changed from the pull
  request list or the Conversation tab, because GitHub changes pages
  without a full reload. Until the path is a pull request, the script
  only checks the URL. The panel button is on every tab of that pull
  request. The diff buttons appear only on the files and changes
  views; leaving that view removes them and stops their polling.
- The changes view re-renders rows, which can drop a chip.
- A range covers one side of one file.
- The panel shows the thread as plain text. URLs in a message are not
  links. Nothing in the panel is posted to GitHub.

* Development

** Tests

#+BEGIN_SRC bash
node --test devtools/gh-ask/userscript/
bazel test //devtools/gh-ask/userscript:userscript_test
#+END_SRC

The test runs the payload builder, URL and head-commit parsing, error
text, the poller, and the answer panel against sample diff markup in
=userscript/testdata/=, one file per view. A panel question with no
line is checked as a whole-PR payload. The panel tests check that
message text stays literal, the poll cadence, ~GET /thread~, and
which ask form a follow-up uses. Popover placement is checked against
fixed viewports, not a layout engine. It uses the host's ~node~ and
fails when ~node~ is missing. The browser glue (button, popover,
chip, panel) has no automated test.

** Manual check

After changing the browser glue, check by hand on a real pull
request: the button on hover and on a selection, a send that reaches
the server, the chip moving to ~answered~, the panel on the
Conversation tab, and "auth failed" in the chip after setting a wrong
token.

** Lint

When ~biome~ or ~oxlint~ is installed:

#+BEGIN_SRC bash
biome lint devtools/gh-ask/userscript/
oxlint devtools/gh-ask/userscript/
#+END_SRC

** Updating a fixture

Each fixture in =userscript/testdata/= says which markup it copies.
When the button stops appearing or the payload is wrong, save the
real page, update the fixture, and fix the script against the test.

=changes-view-captured.html= is the one fixture captured from GitHub
rather than written by hand: the markup of a newly added file on a
pull request's =/changes= page, as served on 2026-11-22. A logged-out
request is redirected to the classic view, so capture it in a signed-in
browser. To refresh it, open =/changes= on a pull request that adds a
file, copy the outerHTML of that file's =div[id^="diff-"]= element, and
keep the file header, the hunk row and the first few line rows. Keep
tags, attributes and class names as served. Replace any private content
(paths, code, CODEOWNERS text) and recompute the =diff-= anchor as the
SHA-256 of the new path. Then update the expected text in the
"captured changes view" tests.

** Userscript internals

- ~repo~ and ~pr~ come from the URL.
- ~head_sha~ comes from a commit range in the URL, else
  ~pullRequestsLayoutRoute.pullRequest.headSha~ in the
  ~react-app.embeddedData~ JSON, else the hidden ~head_sha~ or
  ~comparison_end_oid~ input, else ~headOid~ in the page's embedded
  JSON. A page with none of those fetches ~/OWNER/REPO/pull/N/files~
  on this origin and reads the commit there. That result is cached
  for the pull request until the URL changes or the page loads again.
  The panel and the line popover say "finding the head commit…"
  while the fetch runs. If it fails, they say "couldn't find the
  head commit; open Files changed and ask there", do not call the
  local server, and the line popover keeps the question text.
- ~path~, ~side~, and the line range come from the diff rows. A range
  takes the side of the line where the selection ends.
- ~selection~ is the selected text when the user selected text in the
  diff, cut to 4 KB, or empty on a hover ask.
- ~page_url~ is the page link with the line anchor, such as
  ~#diff-<hash>R10-R12~. A whole-PR question from the panel uses the
  page without a line anchor.
- The popover and the button stay inside the window: a box that would
  pass the right edge shifts left, one that would pass the bottom
  opens above, and a narrow window shrinks the popover. Resizing the
  window moves an open popover.
- The script sends agent requests only with ~GM_xmlhttpRequest~, only
  to ~http://127.0.0.1:<port>~, and with ~anonymous~ set so no cookies
  go along. ~@connect~ lists only ~127.0.0.1~ and ~localhost~. The
  head-commit lookup is a same-origin ~fetch~ of the files page, not
  ~GM_xmlhttpRequest~, and it sends no token. Text from the server is
  shown with ~textContent~. The panel uses ~white-space: pre-wrap~
  and does not render markdown. Its CSS is added with ~GM_addStyle~.
- The token and port are stored with ~GM_setValue~.
- ~@match~ is ~https://github.com/*~.

* Standard CLI protocol

~gh-ask~ implements ~version [--json]~, ~update [--check] [--ref <ref>] [--json]~, ~doctor [--json] [--offline]~, and ~skill [install|uninstall|status ...]~.
