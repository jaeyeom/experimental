#+TITLE: gh-ask
#+DATE: 2026-11-14

* Overview

~gh-ask~ lets a reviewer ask a question about a line range in a pull
request diff from the browser. A local server on ~127.0.0.1~ takes the
question and hands it to a command you configure, for example one that
files the question for an agent and prints a thread id.

The server has two endpoints, ~POST /ask~ and ~GET /status/<id>~. It
is not a generic exec service: the commands are fixed in config, and
the request text reaches them only through a file.

* Install

#+BEGIN_SRC bash
go install github.com/jaeyeom/experimental/devtools/gh-ask/cmd/gh-ask@latest
#+END_SRC

* Usage

#+BEGIN_SRC bash
gh-ask token                                     # create the secret if missing and print it
gh-ask serve --config ~/.config/gh-ask/config.toml
#+END_SRC

Both commands take ~--config~. The default is
=$XDG_CONFIG_HOME/gh-ask/config.toml=, or
=$HOME/.config/gh-ask/config.toml=.

~gh-ask token~ writes 32 random bytes, hex encoded, to the token file
with mode ~0600~. It prints the existing token when the file already
exists. ~gh-ask serve~ refuses to start without the token file, and
refuses a token file that group or others can read.

* Config

#+BEGIN_SRC toml
# Only 127.0.0.1:<port> is accepted. Default 127.0.0.1:8765.
listen = "127.0.0.1:8765"
# owner/name repos the server accepts.
repos = ["octo/demo"]
# argv, run without a shell. Only {file}, {pr} and {repo} are replaced.
ask_command = ["ask-agent", "--message-file", "{file}", "--pr", "{pr}", "--repo", "{repo}"]
# Finds the id in stdout: group 1 if the pattern has a group, else the match.
id_pattern = 'thread-([0-9a-f]+)'
# Runs instead of ask_command for a later ask on a PR whose thread is
# open. Only {id}, {file}, {pr} and {repo} are replaced. Required unless
# reuse = "none".
followup_command = ["ask-agent", "--thread", "{id}", "--message-file", "{file}"]
# Optional.
reuse = "per-pr"           # or "none": every ask runs ask_command
status_command = ["ask-agent", "--status", "{id}"]  # only {id}; enables GET /status/<id>
rate_limit = 10            # asks per hour
command_timeout = "2m"     # applies to every command
token_file = "token"       # relative to the config file's directory
#+END_SRC

Unknown keys and unknown placeholders are errors.

* Thread reuse

With ~reuse = "per-pr"~, the default, the server stores the id that
~ask_command~ printed for each ~(repo, pr)~ in
=$XDG_STATE_HOME/gh-ask/threads.json=, or
=$HOME/.local/state/gh-ask/threads.json=. It writes the file with mode
~0600~ to a temp file and renames it into place.

A later ask on the same PR checks the stored id before reusing it.
When ~status_command~ is set, the ask uses a cached status younger
than about 10 seconds; otherwise it runs ~status_command~. ~closed~
true runs ~ask_command~, and the new id replaces the stored one. If
~status_command~ fails, with a non-zero exit, a timeout, or invalid
JSON, the ask logs the reason and starts a new thread too. A visible
new thread is better than a question lost in a thread that might
already be closed. When the status is still open, the ask runs
~followup_command~ with the stored ~{id}~ and the new message ~{file}~,
ignores that command's stdout, and returns the stored id. Without
~status_command~, a stored thread is reused until you remove it from
the state file.

Two asks on the same PR at the same moment can both start a thread; the
one that finishes last is stored.

With ~reuse = "none"~, every ask runs ~ask_command~ and nothing is
stored.

* POST /ask

The body is JSON:

| Field        | Notes                                        |
|--------------+----------------------------------------------|
| ~repo~       | ~owner/name~, must be in ~repos~             |
| ~pr~         | positive integer                             |
| ~head_sha~   | hex commit id                                |
| ~path~       | file path, at most 1 KB, no control chars    |
| ~side~       | ~LEFT~ or ~RIGHT~                            |
| ~start_line~ | first line, 1 or later                       |
| ~end_line~   | last line, not before ~start_line~           |
| ~selection~  | code, at most 4 KB                           |
| ~question~   | non-empty, at most 2 KB                      |
| ~deep~       | boolean                                      |
| ~page_url~   | an ~https://github.com/~ link, at most 2 KB  |

On success the response is ~{"id": "..."}~. Errors are
~{"error": "..."}~ with a short message; details go to the server log.

| Status | Meaning                                                |
|--------+--------------------------------------------------------|
| 400    | bad JSON or a bad field                                |
| 401    | missing or wrong ~X-Gh-Ask-Token~                      |
| 403    | bad ~Host~, bad ~Origin~, or repo not in ~repos~       |
| 404    | any path other than ~/ask~ or ~/status/<id>~           |
| 405    | any method other than ~POST~, including ~OPTIONS~      |
| 413    | a field over its cap, or a body over 16 KB             |
| 429    | over the rate limit                                    |
| 502    | the command failed, timed out, or printed no id        |

* GET /status/<id>

#+BEGIN_SRC bash
curl -H "X-Gh-Ask-Token: $(gh-ask token)" http://127.0.0.1:8765/status/abc123
#+END_SRC

The server runs ~status_command~ with ~{id}~. The command must print
one JSON object:

#+BEGIN_SRC json
{"state": "answered", "answered": true, "closed": false}
#+END_SRC

All three fields are required. ~state~ is a string of at most 256
bytes with no control characters. Other fields are dropped, and the
three are returned as the response body. A good result is cached for
10 seconds per id; a failure is not cached. Status requests do not use
up the ask rate limit.

| Status | Meaning                                                    |
|--------+------------------------------------------------------------|
| 401    | missing or wrong ~X-Gh-Ask-Token~                          |
| 403    | bad ~Host~ or bad ~Origin~                                 |
| 404    | an id this server did not create, or no ~status_command~   |
| 405    | any method other than ~GET~, including ~OPTIONS~           |
| 502    | the command failed, timed out, or printed bad JSON         |

Only ids that ~ask_command~ printed answer: ids from this process, and
with ~reuse = "per-pr"~, ids in the state file.

* Security

- The server binds only ~127.0.0.1~. Any other ~listen~ address is
  refused.
- Both endpoints get the same token, ~Host~ and ~Origin~ checks.
- ~X-Gh-Ask-Token~ must match the token file. The compare runs in
  constant time.
- No CORS headers are ever sent, and ~OPTIONS~ gets ~405~. A web page
  cannot send the token header cross-origin, so only a userscript or
  extension can call the server.
- ~Host~ must be ~127.0.0.1:<port>~ or ~localhost:<port>~. This blocks
  DNS rebinding.
- ~Origin~, when present, must be ~https://github.com~ or a
  ~chrome-extension://~, ~moz-extension://~ or
  ~safari-web-extension://~ origin.
- Requests rejected before the rate limit check do not use up the
  limit.

* The message file

The request is rendered to a mode-0600 temp file:

#+BEGIN_EXAMPLE
[gh-ask] PR 42 · pkg/a.go:10-12 (RIGHT) · deep=no

Question:
Why is this retried?

Code:
for i := 0; i < 3; i++ {

Link:
https://github.com/octo/demo/pull/42/files#diff-...
#+END_EXAMPLE

The file is deleted when the command exits. A command that hands the
file to something asynchronous must copy it first.

~ask_command~ and ~followup_command~ run with no stdin, the server's
environment, and ~command_timeout~. They keep running if the browser
disconnects. ~status_command~ runs the same way but is stopped when the
browser disconnects.

* Userscript

[[file:userscript/gh-ask.user.js][userscript/gh-ask.user.js]] adds an "Ask agent" button to the pull
request "Files changed" view, both the classic ~/pull/<n>/files~ page
and the newer ~/pull/<n>/changes~ page. It runs in Violentmonkey or
Tampermonkey.

** Install

1. Install Violentmonkey or Tampermonkey in the browser.
2. Open the raw file, for example
   =https://github.com/jaeyeom/experimental/raw/main/devtools/gh-ask/userscript/gh-ask.user.js=,
   and confirm the install. Or create a new script and paste the file.
3. Start the server with ~gh-ask serve~, with the repos you review in
   ~repos~.
4. On a pull request page, open the userscript manager's menu and pick
   "Set gh-ask token / port". Paste the output of ~gh-ask token~, then
   enter the port from ~listen~, 8765 by default. An empty token answer
   keeps the stored token.

The token and port are stored with ~GM_setValue~, in the userscript
manager's storage. They never go into the page DOM or a URL.

** How it works

- Hovering a numbered diff line shows the button on that line.
  Selecting text inside one file's diff shows it at the end of the
  selection.
- The button opens a popover with a question box, a "deep" checkbox and
  Send. The popover and the button stay inside the window: a box that
  would pass the right edge shifts left, one that would pass the bottom
  opens above, and a narrow window shrinks the popover. Resizing the
  window moves an open popover.
- Send builds the ~POST /ask~ body from the page:
  - ~repo~ and ~pr~ from the URL.
  - ~head_sha~ from a commit range in the URL, else the hidden
    ~comparison_end_oid~ input (classic view), else ~headOid~ in the
    page's embedded JSON (changes view).
  - ~path~, ~side~ and the line range from the diff rows. A range takes
    the side of the line where the selection ends.
  - ~selection~ from the selected text, or the hunk around the line when
    nothing is selected, cut to 4 KB.
  - ~page_url~, the page link with the line anchor, such as
    ~#diff-<hash>R10-R12~.
- After the server answers, the line gets a chip, ~Asked in <id> ·
  waiting~. The script polls ~GET /status/<id>~ every 20 seconds while
  the tab is visible, for at most 30 minutes, and shows ~answered~ or
  ~closed~ when the status says so.
- Errors show in the chip and the popover: auth failure (401), forbidden
  (403), too large (413), rate limit (429), command failed (502), and
  server down when there is no response. The popover stays open after a
  failed send so the question can be sent again.

The script sends requests only with ~GM_xmlhttpRequest~, only to
~http://127.0.0.1:<port>~, and with ~anonymous~ set so no cookies go
along. ~@connect~ lists only ~127.0.0.1~ and ~localhost~. Text from the
server is shown with ~textContent~.

** Tests

#+BEGIN_SRC bash
node --test devtools/gh-ask/userscript/
bazel test //devtools/gh-ask/userscript:userscript_test
#+END_SRC

The test runs the payload builder, URL and head commit parsing, error
text, and the poller against sample diff markup in
=userscript/testdata/=, one file per view. Popover placement is checked
against fixed viewports, not a layout engine. It uses the host's ~node~
and fails when ~node~ is missing. The browser glue (button, popover,
chip) has no automated test. After changing it, check by hand on a real pull
request: the button on hover and on a selection, a send that reaches
the server, the chip moving to ~answered~, and "auth failed" in the
chip after setting a wrong token.

Lint, when ~biome~ or ~oxlint~ is installed:

#+BEGIN_SRC bash
biome lint devtools/gh-ask/userscript/
oxlint devtools/gh-ask/userscript/
#+END_SRC

** Limitations

- GitHub's diff markup is not an API and changes without notice. Each
  fixture in =userscript/testdata/= says which markup it copies. When the
  button stops appearing or the payload is wrong, save the real page,
  update the fixture, and fix the script against the test.
- The script loads only on URLs that match ~@match~. GitHub moves
  between pull request tabs without a page load, so after clicking into
  "Files changed" from another tab, reload the page once.
- The changes view re-renders rows, which can drop a chip.
- A range covers one side of one file. A selection across files is
  refused.
- The answer text is not shown; read it where the agent posts it.
