#+TITLE: Experimental Mono Repo

This repository contains everything. It started as an experimental repository
where I could put random pieces of code. Later, I wanted to have a monorepo for
my code, and I realized that this repository could be the best option if I
cleaned it up a bit.

New work usually starts here. A project lives in this monorepo while it is
still experimental and not yet stable. Once it stabilizes it often stays; when
it needs its own release cycle or module path, it sometimes splits out into an
independent repository (for example
[[https://github.com/jaeyeom/bazel-affected-tests][bazel-affected-tests]]).

The result is a polyglot monorepo (Go, Python, TypeScript, Protobuf, Elisp,
Ansible) that holds reusable libraries, command-line tools, language
experiments, and my development environment configuration, all built and tested
through a single Make + Bazel workflow.

* Getting Started
The Go module path is =github.com/jaeyeom/experimental=. You will need:

- [[https://bazel.build/install/bazelisk][Bazelisk]] (pinned via =.bazeliskrc=) — primary build, format, lint, and test driver. All Go/Python/shell linters (=nogo=, =ruff=, =mypy=, =shellcheck=, =semgrep=), secret scanning (=gitleaks=), =uv.lock= verification, and formatting checks run hermetically through Bazel.
- =emacs= (optional) — only needed locally for =make check-spacemacs=.

Clone the repo and run the test suite to verify your setup:

#+begin_src sh
git clone https://github.com/jaeyeom/experimental
cd experimental
make test
#+end_src

* Build System
This repository is driven by GNU Make as the orchestration layer, with Bazel
underneath for hermetic, reproducible builds.

** GNU Make
=Makefile= exposes the common entry points:

| Command              | Purpose                                                                                  |
|----------------------+------------------------------------------------------------------------------------------|
| =make check=         | Run all pre-commit checks: Bazel tests/linters/scans (=make test=) and Spacemacs checks. |
| =make test=          | Run all Bazel tests, linters, format checks, and security scans (=bazel test //...=).    |
| =make test-rbe=      | Run remote-eligible Bazel tests on BuildBuddy RBE and =local=/=no-remote= tests locally. |
| =make format=        | Format code via Bazel (=goimports=, =buildifier=, whitespace, etc.).                     |
| =make lint=          | Run local Spacemacs checks (all other linters run via Bazel in =make test=).             |
| =make fix=           | Best-effort autofix for lint issues.                                                     |
| =make all=           | Regenerate, format, fix, then test.                                                      |
| =make install=       | Install this checkout's Go CLIs. See =devtools/README.org=.                              |
| =make coverage-html= | Generate an HTML coverage report under =coverage/html/=.                                 |

** Bazel
This repository is experimenting with Bazel and the goal is to make it fully
hermetic, working both on Linux and Termux. =MODULE.bazel= wires up the Go SDK
(with =nogo= static analysis via custom linters in =//tools/lint=), Gazelle for
BUILD file generation, rules_python, the Buf protobuf toolchain, and Pkl for
configuration code generation.

In CI, =.github/workflows/bazel-test.yml= is the sole general check workflow:
it checks out full Git history (=fetch-depth: 0=) and runs =bazel coverage //...=,
which executes all unit tests, linters (=nogo=, =ruff=, =mypy=, =shellcheck=),
format/freshness checks, =semgrep=, and full-history =gitleaks=. Emacs and
Spacemacs checks run separately in the path-filtered =.github/workflows/emacs.yml=
workflow.

*** BuildBuddy Remote Cache and RBE
Opt-in BuildBuddy Build Event Service (BES), remote caching
(=--config=buildbuddy=), and Linux =x86_64= Remote Build Execution
(=--config=rbe=) are configured in =.bazelrc=. Default =make test= and
=make check= run locally and do not require BuildBuddy credentials.

To enable BuildBuddy locally, add your API key to the gitignored
=.bazelrc.user= file (with restrictive permissions, e.g., =chmod 600=):

#+begin_src conf
build:buildbuddy --remote_header=x-buildbuddy-api-key=<YOUR_API_KEY>
build:buildbuddy --bes_header=x-buildbuddy-api-key=<YOUR_API_KEY>
#+end_src

Then run with BES + remote cache or full RBE:

#+begin_src sh
# BES + remote cache only (executes locally)
bazel test --config=buildbuddy //...

# Full RBE: remote-eligible targets on BuildBuddy Linux workers,
# local/no-remote targets locally with host PATH
make test-rbe

# Direct Bazel RBE invocation for remote-eligible targets
bazel test --config=rbe --build_tag_filters=-local,-no-remote --test_tag_filters=-local,-no-remote //...
#+end_src

On macOS (=darwin_arm64=), =--config=rbe= targets =linux_x86_64= workers, so
=local= and =no-remote= targets cannot execute Linux binaries locally;
=make test-rbe= splits remote-eligible tests (without macOS host
=BAZEL_TEST_PATH=) from =local=/=no-remote= tests (run natively on the host).
Machine-local overrides such as =build --spawn_strategy=local= in gitignored
=.bazelrc.local= are imported before =.bazelrc.user= and overridden by
=--config=rbe=.

* Development Workflow
- Run =make check= before requesting a commit. If it changes files (formatters
  or generators), include those changes in the commit.
- Keep the =main= branch history flat — integrate upstream with =git pull
  --rebase= and merge with =git merge --ff-only=.
- With [[https://github.com/gabyx/Githooks][Githooks]] installed (=git hooks install=), the
  =.githooks/pre-commit/gitleaks.sh= hook scans staged changes for secrets and
  blocks the commit on a finding. Resolve a false positive by updating
  =.gitleaks.toml= or =.gitleaksignore=, not by skipping hooks.

See [[file:CLAUDE.md][CLAUDE.md]] and [[file:AGENTS.md][AGENTS.md]] for the conventions followed by AI assistants and
automated workflows in this repository.
